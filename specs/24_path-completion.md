# Spec: 入力欄のパス補完 — `@` でファイルを指す

**ID**: 24
**Date**: 2026-08-06
**Status**: **rev1（起票。査読待ち）**
**Branch**: なし（main へ Phase 単位で直接コミット）

## Goal

会話の入力欄で `@` を打つと、作業フォルダのファイルが候補として出て、
選ぶと**そのパスが本文へ入る**。

起点は利用者（2026-08-06）—「Claude Code や Copilot は `@` でファイル名を
補完できる。ああいう機能を Concordia にも」。

**効き目は 2 つあり、大きいのは 2 つ目**:

1. **利用者がパスを手で打たなくて済む**（入力補助）。綴りと区切り文字の
   取り違えが構造的に消える — 「参照…」ボタンを足したときと同じ動機
2. **サーヴァントが探す周回が消える**（トークン）。今日の実機ログでも、
   ソネットは 1 ターンで `fd` → `file` → `file` → `file` と**探索に 2 周**
   使っている。**周が増えるたびにプロンプト全体が再送される**ので、
   効き目は呼び出しの本数ではなく再送の回数で数える（Spec 17 の起票理由と同型）

## 現況（実測 2026-08-06）

- **`@` は UI でまだ使われていない**（`grep '"@"'` が 0 件）。名前空間は空いている
- **`collect_files` が既にある**（`tools/fs.rs`）— work_dir 境界・`SKIP_DIRS` 除外・
  **上限 `MAX_FILES` = 20,000 件**・打ち切りフラグ付き。`pub(crate)` なので
  公開の薄いラッパが要る
- **同梱ツールの引数はすべて work_dir 相対パス**（`sd` / `file` / `grep` の `path`）
- **絶対パスをモデルの読む本文へ出さない規律がある**（`failures.md` #60 —
  `canonicalize()` の `\\?\` 前置が漏れて `display_path` で塞いだ）

### Claude Code の `@` を実測した（2026-08-06。この Spec の設計判断に直接効く）

利用者が `@01_sd-yq-write-tools.md` まで打って補完した結果、**3 層**に分かれた:

| 層 | 中身 | どこに残るか |
|---|---|---|
| 打った断片 | `01_sd-yq-write-tools.md` | 残らない |
| 本文 | `specs/01_sd-yq-write-tools.md` | チャットにも、モデルが読む本文にも |
| 転送 | `D:\…\specs\01_sd-yq-write-tools.md` | ツール引数だけ |

そして**中身が 279 行まるごと展開されて届いた**。しかも `Read` ツール呼び出しの
形で来ている — **ハーネスがターンの前に代わりに実行している。**

**読み取れたこと 3 点**:

1. **解決は「選んだ瞬間」に起きる**（送信時ではない）。だから打ち間違いは
   選ぶ前に分かり、本文に残るのは正規化された相対パスになる
2. **絶対パスは転送層だけ**。人の読む面にもモデルの読む本文にも出ない
3. **`use_tool` の回数は減っていない**（1 回消費している）。減っているのは**周回**

## 設計の核

**挿すのは work_dir 相対パスの文字列だけ。中身は展開しない**（D1）。
**コア側の機構はゼロ**で、増えるのは読み取り専用の IPC 1 本と入力欄の部品だけ。

```text
入力欄で「@」→ 候補一覧（IPC で 1 回取って以後はクライアント側で絞る）
  → 選ぶ → 本文へ「specs/01_….md」という文字列が入る
  → サーヴァントは必要なら既存の `file read` で読む（読まなければ払わない）
```

## 決めること

- **D1（最重要）中身は展開しない。パスだけを挿す。**
  Claude Code は展開するが、**この村は履歴の寿命が違う**:

  | | ツール結果（`file read`） | 利用者の発話 |
  |---|---|---|
  | どこに載るか | そのターンの `messages` だけ | `sent_user_turn` → **履歴** |
  | 寿命 | **1 ターン** | **滑る窓 8 往復** |

  根拠は実装コメント（`orchestrator.rs`）—「中間のツール結果はこのターンの
  `messages` にしか存在せず、履歴には積まれない」。**発話へ埋め込むと
  #45 の規律でそのまま履歴へ載る**ので、1 万トークンのファイルが
  **最大 8 回再送**される。

  **これは Spec 23 の D1 と同じ構造**（画像を履歴に残すと 8 ターンぶん払う）。
  あちらは「1 ターン限り」の機構を作って解いたが、**pull なら
  既存の `file read` の寿命が最初からそれを満たしている** — 作らずに済む。

  **代償を正直に書く**: 中身が要るときは `file read` の 1 周が残る。
  消えるのは*探す*周であって*読む*周ではない。
- **D2 `@` の名前空間は将来のために種別を持てる形にする。v1 はファイルのみ。**
  Slack / Discord では `@` は**人**で、この村にはサーヴァントという概念がある。
  README の「意図的に未実装」に**利用者からの同報**が保留として載っており、
  実装するなら `@ザリ @ジェミー` が最も自然な入口になる。
  **ファイル専用として作ると、その道が塞がる。**
  処方は候補に種別（`kind: "file"`）を持たせておくことだけで、v1 では
  ファイルしか載せない。**機構は増えず、後から足せる形だけ残る。**
- **D3 候補源は選択中サーヴァントの work_dir。無い個体では候補を出さない。**
  作業フォルダが無ければ `file` / `grep` も提示されていないので、
  パスを挿しても読む手段が無い。理由を出す形は
  `AgentSettingsDialog` の `noWorkDirWarn` に倣う。
  **宛先を切り替えたら候補も切り替わる**（同じ `@` が別の村を指す）。
- **D4 打ち切りを必ず画面に出す。** `collect_files` は 20,000 件で打ち切る。
  候補に出ないファイルが存在するのに画面がそれを言わないと、
  **「打っても出ないから無い」と読まれる**。この村は同じ扱いを
  `grep` / 広場ログ / `sd` で 3 回間違えて直している（`failures.md` #55 / #58）。
- **D5 照合はファイル名（basename）優先、挿すのは相対パス。**
  実測で利用者はファイル名だけを打って正しい 1 本に当てている。
  ディレクトリ部分は**同点破りにだけ**使う。純関数にして vitest で留める。
- **D6 一覧は開いたときに取り、ターンをまたいで持ち越さない。**
  20,000 件でも JSON は数百 KB、JS 側の絞り込みは体感ゼロなので、
  **性能ではなく鮮度が論点**。黒板ペインの「表示中 10 秒の再読 + 手動更新」に
  倣うか、`@` を打った瞬間に 1 回取るかを実装時に決める（後者を推す —
  補完は開いている時間が短く、閉じていれば取る理由が無い）。

## Stories

- S1 利用者が `@` を打ち、ファイル名の一部で絞り込んで選ぶと、
  **work_dir 相対パスが本文へ入る**
- S2 選んだパスを見たサーヴァントが、探索なしで `file read` に入る
- S3 作業フォルダを持たないサーヴァントが宛先のとき、候補が出ない理由が読める
- S4 候補が上限で打ち切られていることが画面から分かる
- S5 `@` を打ったが補完を使わずに書き続けても、**普通のテキストとして通る**
  （`@` そのものは何も壊さない）

## Tasks

- **P0 IPC + 契約**: `list_work_dir_files(agent_id) -> { paths: Vec<String>,
  truncated: bool }`。`collect_files` の公開ラッパをコアへ 1 本。
  **`data_contract` へ短い節**: 挿すのはパスだけで push 注入をしない（D1）/
  打ち切りを画面に出す（D4）。**新しいドメイン型は増えない**ので
  `ipc_contract.rs` は触らない
- **P1 照合の純関数**: `lib/pathComplete.ts`（basename 優先・同点破り・
  順位付け・上限件数）+ vitest
- **P2 補完 UI**: `ChatInput.vue` へポップアップ。**Enter は補完が開いている
  間は「確定」であって送信ではない**（`isComposing` の扱いも既存と同じ配慮が要る）。
  ↑↓ で選択・Esc で閉じる。置き場は添付チップと同じ入力欄の直上を推す
  （textarea のカーソル座標を取るにはミラー要素が要り、割に合わない）
- **P3 台帳**: README 日英 + CLAUDE.md
- **P4 実機確認**（画面・ログで観測できる項目だけ — #68）:
  1. ファイル名の一部で絞って選ぶと相対パスが入る
  2. 選んだパスをサーヴァントが `file read` に渡し、**`fd` / `grep` を呼ばない**
     （`tool:` 行で読める）
  3. work_dir の無い個体では候補が出ず、理由が読める
  4. `@` を打って補完を使わずに送っても壊れない

## Notes

1. **この機能は「文脈を渡す機構」ではなく「パスを手で打たなくて済む機能」。**
   そう捉えると規模がステータスバー・右クリック抑止と同じ階層まで落ちる。
   **Spec を切ったのは規模ではなく、D1 と D2 が取り消しにくいから。**
2. **D2 を先に決めないと後で動かせない。** `@` をファイル専用にしてから
   同報を実装すると、そのとき `@` は既に埋まっている。
   **空いている名前空間の使い道は、埋める前にしか決められない。**
3. **絶対パスを本文へ入れない理由は 3 つあり、独立している** —
   (a) 既存ツールの引数が相対パス (b) `failures.md` #60 の規律
   (c) **会話ログは村ごと配れる**ので、絶対パスが焼き付くと別の端末で
   意味を失う（Spec 14 の `work_dir` / Spec 18 の `rag_sources` で
   **既に 2 回踏んでいる形**）。**同じ結論に別々の根拠があるときは全部書く**
4. **`fd` ツールとは別物。** `fd` はモデルが呼ぶ道具、これは人が使う入力補助で、
   **同じ `collect_files` を共有するが提示面には現れない**。
   ツールを 1 本も増やさないので、モデルが読む面は 1 字も伸びない
   （Spec 23 の「使わない人は払わない」と同じ形）
