# Spec: 思考の要約を受け取って表示する（xAI と Anthropic）

**ID**: 33
**Date**: 2026-08-10
**Status**: **rev2 承認 → P0 完了**（2026-08-10。契約は `data_contract.yaml` の
`llm_wire.reasoning_summary`。凍結したのは **`reasoning_summary` だけ**で、
**D2-b（ワイヤ上の産物の往復）は未凍結**のまま残してある。
査読 8 点 → 採用 5 / 訂正して採用 3 / 反証 0。
rev1 からの最大の変更は **D2 の分割** — `reasoning_summary`（表示物）と
Anthropic の `thinking + signature`（ワイヤの往復物）を**同じ決定に混ぜていた**。
分けないと P0 で凍結した契約を P2 の測定が壊す）
**Branch**: なし（main へ直接コミット。Phase ごと）

## Goal

**モデルが返す「思考の要約」を受け取り、来歴として画面に出す。**

[Spec 32](specs/32_thinking-reception.md) が**量**を数えられるようにした。
本 Spec は**中身**を扱う。実測では Anthropic の 1 ターンで
**出力 4,096 トークンのうち 4,090 が思考で本文は 6 字**。埋めるのは、
その 4,090 の中身が読めないこと。

**範囲は xAI と Anthropic**（利用者裁定の順序の 1・2 番目）。

**OpenAI 互換を外す理由は 2 段で、混ぜると Spec 32 と矛盾して見える**（査読 7）:

- **技術**: **数は `/v1/chat/completions` で取れるが、本文は来ない。**
  Spec 32 が数えたのは `usage.completion_tokens_details.reasoning_tokens` で、
  これは**使用量の欄**。思考の**本文**を運ぶブロックはこの口に存在しない。
  **「受け取れない」と「数えられない」は独立**（Spec 32 P1 の実測）
- **規模**: 本文を取るには `/v1/responses` が要り、実質
  `Provider::OpenAiResponses` の新設 = Spec 31 P1 と同規模

**ゆえに Spec 34。** 「4 社すべてで `reasoning=` が出る」（Spec 32）と
「本 Spec は 2 社」は矛盾しない — **数と本文は別の口**。

## 接地（2026-08-10 の probe。使い捨ての example・実鍵・削除済み）

### xAI（`grok-4.5`。8 発）

- `reasoning` item は `summary: [{ type: "summary_text", text }]` を持つ
- **欄は 4 つで固定**（`id` / `summary` / `type` / `status`）。
  `encrypted_content` も `signature` も無い
- 要約は **2 形** — **短形（129 字 = 問題文の再掲だけ）** / 長形（919〜1,367 字）
- **`reasoning: {"summary":"auto"} は効かない**。短形/長形の分布が
  既定 2:2 / auto 2:2 で**一致**した

**往復の要求については、xAI では試験していない**（査読 8）。
**欄の不在から挙動を推論しただけ**で、Anthropic では実際に落として送る対を
打っている。**判定の方法が非対称**なので、P1 冒頭で同じ試験を打つ（D2-b）。

### Anthropic（`claude-sonnet-5`。7 発）

- **既定は `display: "omitted"`**（5 世代）。`signature` は 368〜16,328 字あるのに
  **`thinking` テキストは 0 字**
- **`thinking: {"type":"adaptive","display":"summarized"}` で本文が返る**
  （実測 **3,475 字**）
- **`budget_tokens` は 400**。サーバー自身が `thinking.type.adaptive` と
  `output_config.effort` を名指しする
- **課金は `display` に依存しない**（実測 **1 対**で `thinking_tokens` 4,090 対 4,096
  = 差 6。**1 対なので「同程度」までしか言わない**）
- **ツール併用の回は `summarized` を送っても要約が 0 字**（`thinking_tokens=34`）
- **`thinking` ブロックを落として `tool_result` を返しても 200**（戻す対照も 200）。
  **各 1 サンプル、かつ `display` を送っていない条件**での観測

### 両社に共通

- **要約は英語で返る**（問いが日本語でも）
- **要約は生の思考ではない** — xAI は `reasoning_tokens` 1,118〜3,685 に対し
  最大 1,367 字、Anthropic は 4,096 トークンに対し 3,475 字

## 決定（D）

### D1: 範囲は xAI と Anthropic

Goal の 2 段（技術と規模）が根拠。OpenAI 互換は Spec 34。

### D2-a: `reasoning_summary` は**両社とも常に履歴へ積まない**（不変）

置き場と経路は **`Grounding` を写す** — `ChatResponse.reasoning_summary` →
周ごとに畳んでターンぶんで持ち、`AgentMessage` へ載せる。

**`ChatMessage`（履歴）には席を作らない。** 積むと滑る窓 8 往復で最大 8 回
再送され、**3,475 字が固定費になる**。Spec 23 D1 と同じ判断で、根拠も同じ
（履歴は `String`・#45 の規律）。

**これは測定で覆らない。** 表示物をプロンプトへ戻す要求はどのプロバイダにも
無く、あるとすればそれは次の D2-b の話（**別の物**）。

**証明は型で取る** — 席を作らなければ積めないので、**単体テスト 1 本**で足りる
（Spec 23 P3 が同じ問いを型で閉じた前例）。**runtime の byte 計測は要らない。**

### D2-b: **ワイヤ上の産物**の往復要否は**測ってから決める**（未凍結）

**産物の名前は社ごとに違う** — xAI は `reasoning` item、Anthropic は
`thinking + signature`。**同じ問い（次のターンへ戻す要求があるか）に対する、
社ごとの対象。**

**これは D2-a とは別の物**（査読 1）— 表示のための要約ではなく、
**プロバイダが次のターンで要求するかもしれないワイヤ上の産物**。

現状の観測は「落としても 200」だが、**各 1 サンプル**かつ
**`display` を送っていない条件**だった。**`summarized` を送った応答で対を測る**
（P2 の冒頭 / xAI は P1 の冒頭）。

**真だった場合に増えるのは `ChatMessage` の席 1 つ**（`thinking` + `signature` を
そのプロバイダのぶんだけ運ぶ）で、**D2-a は影響を受けない**。

**この決定は P0 で凍結しない**（査読 2）。P0 が凍結するのは D2-a まで。

### D3: 送信側が変わるのは Anthropic だけ。既定は常送、ただし P2 でガードの要否を測る

| | 送るもの | 理由 |
|---|---|---|
| **xAI** | **何も足さない** | `summary:"auto"` は効果ゼロを 4 対 4 で実測 |
| **Anthropic** | `thinking: {"type":"adaptive","display":"summarized"}` | 送らないと `thinking` が空 |

**トグルにしない。** 思考ぶんは `display` に関わらず払っており、`summarized` は
**既に払ったものを返してもらうだけ**。トグルを置くと
**「払っているのに見えない」設定を利用者が作れてしまう**。

**ただし「常に」は 5 世代以外への送信を確かめてから**（査読 4）。
実害が無いという読みは**この村の登録が全部 5 世代だという運用前提**であって、
仕様の根拠にならない。**P2 で 5 世代以外へ送って挙動を数え、拒否されるなら
モデル名でのガードを入れる** — これは `reasoning_effort` のモデル名送り分けと
同じ**「同じワイヤ内の方言の吸収」**で、Spec 31 D2 が禁じた
「ワイヤの選択に名前を使う」には当たらない。

**課金の 1 対も P2 で 3 対に増やす**（#92 — probe の数字を設計の根拠にするなら、
それが測定条件の産物でないかを確かめる）。

### D4: 「空」は **0 字**。短形は空ではないので出す（長さで判定しない）

**rev1 は「空」を二重に定義していた**（査読 5）— Anthropic のツール併用回は
**事実 0 字**、xAI の短形は **129 字**で 0 字ではない。

**閾値で切らない。** 129 と 919 の間に線を引くと、**probe の産物である数字が
表示規則になる**（#92 と同じ罠）。しかも「再掲だけかどうか」は内容の判断で、
ハーネスには決められない。

- **0 字** → 出さない（枠ごと描かない）。**エラーにも警告にもしない** —
  実運用の大半（ツールループの回）がここに落ちるので、警告にすると
  正常なターンのほとんどで鳴る
- **1 字以上** → そのまま出す。短形が薄いことは**利用者が読めば分かる**

**D5 の語（「思考の要約」）が、内容の質を保証しないことを既に担っている。**

### D5: 画面の語は「思考の要約」。生の思考とは言わない

返るのは summary であって思考そのものではない（トークン数と字数が 2 桁違う）。
**「思考を表示します」と書くと、返っていないものを返っていると言うことになる** —
Spec 05 が `sources` の空を受けて縮小したのと同じ規律。

### D6: 接地（出典）と同じ枠に並べない

**出典は検証できる外部の指し先、要約は検証できない内部の申告。**
同じ枠に並べると**後者に前者の信用が乗る**。枠と見出しを分ける。

### D7: 英語で返ることへの注記 — **P3 の入口条件として先に決める**（査読 6）

要約は問いの言語に関わらず英語で返る（実測。両社）。

- (a) そのまま出す
- **(b) 「モデルが出した要約（原文）」と注記する ← 推し**
- (c) 訳す（**採らない** — LLM をもう 1 回呼ぶのは「見えないコスト」を作る）

(b) の根拠: (a) だと**日本語の村で突然英語が出る理由が読めない**。注記は
**訳語ではなく事実の記述**なので D5 と衝突しない。

**P3 は D7 が確定するまで着手しない。** 未決のまま実装へ入ると、
注記の有無で画面の構造が変わる（枠の中か外か）。

## Phases

- **P0**: 契約凍結 — **`reasoning_summary` に限定**（欄・履歴に積まない・
  空は 0 字・送信側は Anthropic だけ）。**`thinking` の往復に関する契約は
  凍結しない**（D2-b。P1 / P2 の測定後に別途）
- **P1**: **xAI** — **冒頭で D2-b の対を測る**（`reasoning` item を落として
  次のターンを投げる / 戻す）。その後 `XaiOutputItem` に `summary` +
  canonical の席 + `absorb` の配線。**表示なし**
- **P2**: **Anthropic** — **冒頭で 3 つ測る**（(1) `summarized` を送った応答で
  D2-b の対 (2) 課金の 3 対 (3) 5 世代以外への `display` 送信）→ 送信側の実装 +
  受け取り。**測定結果を Spec へ書いてから実装へ入る**
- **P3**: **表示** — **D7 の確定が入口条件**。`AgentMessage` → 画面。
  語は D5、0 字は描かない（D4）、枠は接地と分ける（D6）、辞書 ja/en
- **P4**: 台帳 — README / DETAIL 日英 + `data_contract` の回収
  （**数えるのはファイル単位** — #51 (b)）
- **P5**: 実機

## 検収（#68 / #80 / #92 / #93 の規律。**数字を条件にしない**）

Spec 32 の検収 1 は probe の産物（差 3〜5）を合格条件にして外した（#92）。
ここでは**性質**だけを条件にする。

1. **xAI のターンで要約が画面に出る。** 同じターンの `turn:` 行の `reasoning=` が
   非ゼロであることと**対で読む**（量と中身が同じターンに揃う）
2. **Anthropic のターンで要約が出る。** `display` を送る前後で**同じ問いを
   1 回ずつ**投げ、**前は出ず後は出る**ことを対で見る
   （片方だけでは「元から出ていた」と区別が付かない）
3. **要約が 0 字のターンで枠ごと出ない**（D4）。**ツールを使うターンで踏める** —
   実測でそこが `thinking_tokens=34` / 要約 0 字だった
4. **短形（1 字以上だが薄い）のターンでも壊れずに出る**（D4 の後半。
   3 とは別のケースで、**同じ検収に畳むと長さの扱いが検証されない**）
5. **要約の枠と接地の枠が画面で別**（D6）。両方が出るターンで見る
   （xAI の Live Search + thinking が同時に出る回が最も濃い）
6. **D2-b が真だった場合のみ**: 履歴が `thinking` を運ぶようになった後で、
   `cached` が前ターンの `prompt` 付近まで伸びる（前方一致が保たれている）。
   **D2-a の検査ではない** — あちらは型で閉じており実機で見るものが無い（査読 3）

## Notes

1. **v0.2.0 の残りは本 Spec と Spec 34 と多モーダル。** 公表が最後のマイルストーン
2. **`output_config.effort` は対象外。** `canonical.rs` の doc に名前だけがあり
   実装は無い。**思考の深さの制御**は受け取りとは別の問いで、足すなら
   `Effort` の写像（既存の `reasoning_effort` と同じ棚）
3. **Spec 32 で 4 回外した機序を持ち込まないための確認を Phase に埋めてある** —
   D2-b の対（1 サンプルで決めない）/ D3 の 3 対（probe の数字を設計根拠にしない）/
   検収から数字を外す（測定条件の産物を合格条件にしない）/
   **判定の方法を社ごとに揃える**（査読 8 — xAI だけ試験せず推論で断定していた）
4. **rev2 で直した自己矛盾は 3 つ**（査読 1・3・5）。どれも
   **「同じ語で 2 つの物を指していた」**形 — `履歴に積まない`（表示物 / ワイヤの
   往復物）/ `runtime 計測は要らない`（D2-a の証明 / D2-b の傍証）/
   `空`（0 字 / 内容が薄い）。**語を分けると決定も分かれた。**
