# Spec: 思考の要約を受け取って表示する（xAI と Anthropic）

**ID**: 33
**Date**: 2026-08-10
**Status**: **Draft rev1**（査読待ち）
**Branch**: なし（main へ直接コミット。Phase ごと）

## Goal

**モデルが返す「思考の要約」を受け取り、来歴として画面に出す。**

[Spec 32](specs/32_thinking-reception.md) が**量**を数えられるようにした
（4 社すべてで `reasoning=` が出る）。本 Spec は**中身**を扱う。

**範囲は xAI と Anthropic**（利用者裁定の順序 xAI → Anthropic → OpenAI 互換の
1・2 番目）。**OpenAI 互換は本文が `/v1/chat/completions` に来ない**ので
Spec 34（`Provider::OpenAiResponses` の新設）へ送る。

**Spec 32 で「払ったものの大半が画面に出ていない」ことは数字で出た。**
実測では Anthropic の 1 ターンで**出力 4,096 トークンのうち 4,090 が思考で
本文は 6 字**。本 Spec が埋めるのは、その 4,090 の中身が読めないこと。

## 接地（2026-08-10 の probe。使い捨ての example・実鍵・削除済み）

### xAI（`grok-4.5`。8 発）

- `reasoning` item は `summary: [{ type: "summary_text", text }]` を持つ
- **欄は 4 つで固定**（`id` / `summary` / `type` / `status`）。
  **`encrypted_content` も `signature` も無い = 往復の要求が無い**
- 要約は **2 形** — 短形（129 字 = 問題文の再掲だけ）/ 長形（919〜1,367 字）
- **`reasoning: {"summary":"auto"} は効かない**。短形/長形の分布が
  既定 2:2 / auto 2:2 で**一致**した。**送信側の変更は要らない**

### Anthropic（`claude-sonnet-5`。7 発）

- **既定は `display: "omitted"`**（5 世代のモデル）。`signature` は
  368〜16,328 字あるのに **`thinking` テキストは 0 字**
- **`thinking: {"type":"adaptive","display":"summarized"}` で本文が返る**
  （実測 **3,475 字**）。**送信側の変更が要る** — ここが xAI と決定的に違う
- **`budget_tokens` は 400**。サーバー自身が
  `thinking.type.adaptive` と `output_config.effort` を名指しする
- **課金は `display` に依存しない**（実測 1 対で `thinking_tokens` 4,090 対 4,096。
  **差 6 トークン**。1 対なので「無料」と言い切らず、**同程度**と書く）
- **ツール併用の回は `summarized` を送っても要約が 0 字**だった
  （`thinking_tokens=34`）。**思考が短い回には要約が付かない**
- **往復の要求は再現しなかった** — `thinking` ブロックを落として `tool_result` を
  返しても 200（戻す対照も 200）。**ただし各 1 サンプル**

### 両社に共通

- **要約は英語で返る。** 問いが日本語でも
  （xAI の長形 / Anthropic の 3,475 字とも英語）
- **要約は生の思考ではない。** xAI は `reasoning_tokens` 1,118〜3,685 に対し
  最大 1,367 字、Anthropic は 4,096 トークンに対し 3,475 字。
  **構造的に欠落する**

## 決定（D）

### D1: 範囲は xAI と Anthropic。OpenAI 互換は Spec 34

**「受け取りと表示」の名前で OpenAI 互換を含めると見積もりが外れる** —
あちらは実質 `Provider::OpenAiResponses` の新設で Spec 31 P1 と同規模
（Spec 32 の引き継ぎで確定済み）。

### D2: 要約は履歴に積まない

置き場と経路は **`Grounding` を写す** — `ChatResponse.reasoning_summary` →
周ごとに畳んで（`absorb` と同型）ターンぶんで持ち、`AgentMessage` へ載せる。

**`ChatMessage`（履歴）には席を作らない。** 積むと滑る窓 8 往復で最大 8 回
再送され、**3,475 字が固定費になる**。Spec 23 D1（画像は 1 ターン限り）と
同じ判断で、根拠も同じ（履歴は `String`・#45 の規律）。

**検収は型で取る**（Spec 32 の引き継ぎで確定）— 席を作らなければ積めないので、
**単体テスト 1 本で「積めない」ことが証明できる**。runtime の byte 計測は要らない
（Spec 23 P3 が同じ問いを型で閉じた前例）。

**Anthropic の往復要求は「無い」と決め打たない。** P4 の probe で再現しなかったが
**各 1 サンプル**で、しかも**`display` を送っていない条件**での観測だった。
**P2 の冒頭で、`summarized` を送った応答の thinking ブロックを落として
tool_result を返す対を測る**（測るまで実装しない）。真なら D2 は
**xAI 限定**へ縮小し、Anthropic は例外を持つ。

### D3: 送信側が変わるのは Anthropic だけ

| | 送るもの | 理由 |
|---|---|---|
| **xAI** | **何も足さない** | `summary:"auto"` は効果ゼロを 4 対 4 で実測 |
| **Anthropic** | `thinking: {"type":"adaptive","display":"summarized"}` | 送らないと `thinking` が空 |

**Anthropic は常に送る（トグルにしない）。** 根拠は**課金が同程度**であること
（実測 1 対で差 6 トークン）— **思考ぶんは `display` に関わらず払っており、
`summarized` は「既に払ったものを返してもらう」だけ**。
**トグルを置くと「払っているのに見えない」設定を利用者が作れてしまう。**

**ただし 1 対の観測なので、P2 で 3 対に増やして分布を見る**（#92 —
probe の数字を設計の根拠にするなら、その数字が測定条件の産物でないかを確かめる）。

### D4: 空の要約は正常系。エラーにも警告にもしない

**両社で「要求しても返らない回」が実在する** — xAI の短形、Anthropic の
ツール併用回（`thinking_tokens=34` で要約 0 字）。
**しかも実運用の大半は後者**（この村のターンはツールループの中で回る）。

**「要約が無い」を失敗として扱うと、正常なターンの大半に警告が出る。**
表示は**あるときだけ出す**。

### D5: 画面の語は「思考の要約」。生の思考とは言わない

返るのは summary であって思考そのものではない（トークン数と字数が
2 桁違う）。**「思考を表示します」と書くと、返っていないものを返っていると
言うことになる** — Spec 05 が `sources` の空を受けて「検索語と発表元だけを
言う告知」へ縮小したのと同じ規律。

### D6: 接地（出典）と同じ枠に並べない

**出典は検証できる外部の指し先、要約は検証できない内部の申告。**
同じ枠に並べると**後者に前者の信用が乗る**。`GroundingNote` の隣に置くとしても、
**枠と見出しは分ける**。

### D7: 英語で返ることは画面で断らない（未決 — 査読で確認したい）

要約は問いの言語に関わらず英語で返る（実測。両社）。案は 3 つ:

- **(a) そのまま出す**（訳さない。翻訳はプロンプトの変更であり、
  `data_contract` の「システムプロンプト・ツール説明は訳さない」と同じ棚）
- (b) 「モデルが出した要約（原文）」と注記する
- (c) 訳す（**採らない** — 訳すために LLM をもう 1 回呼ぶのは
  「見えないコスト」を作る）

**推しは (b)** — (a) だと日本語の村で突然英語が出る理由が読めない。
注記 1 行なら**訳語ではなく事実の記述**なので D5 と衝突しない。

## Phases

- **P0**: 契約凍結 — `data_contract.yaml` へ `reasoning_summary` の欄と
  「履歴に積まない」「空は正常」「送信側は Anthropic だけ」
- **P1**: **xAI の受け取り**（送信側の変更なし）— `XaiOutputItem` に `summary` +
  canonical の席 + `absorb` の配線。**表示なし**。単体は probe の実応答を golden に
- **P2**: **Anthropic** — **冒頭で D2 の対を測る**（`summarized` を送った応答の
  thinking を落として tool_result → 拒否されるか）+ 課金の 3 対 → 送信側の実装
  （`thinking.display`）+ 受け取り
- **P3**: **表示** — `AgentMessage` → 画面。語は D5 準拠、空は出さない（D4）、
  枠は接地と分ける（D6）、辞書 ja/en
- **P4**: 台帳 — README / DETAIL 日英 + `data_contract` の回収
  （**数えるのはファイル単位** — #51 (b)）
- **P5**: 実機

## 検収（書く前に読み口の実在を数える — #68 / #80 / #92 / #93 の規律）

**数字を条件にしない。** Spec 32 の検収 1 は probe の産物（差 3〜5）を
合格条件にして外した（#92）。ここでは**性質**だけを条件にする。

1. **xAI のターンで要約が画面に出る。** 同じターンの `turn:` 行の `reasoning=` が
   非ゼロであることと**対で読む**（量と中身が同じターンに揃う）
2. **Anthropic のターンで要約が出る。** `display` を送る前後で**同じ問いを
   1 回ずつ**投げ、**前は出ず後は出る**ことを対で見る
   （片方だけでは「元から出ていた」と区別が付かない）
3. **要約が付かないターンで画面が壊れない**（D4）。**ツールを使うターンで踏める** —
   実測でそこが `thinking_tokens=34` / 要約 0 字だった
4. **2 ターン目のプロンプトに要約が入っていない**（D2）。
   **型で証明済みなので、実機では「入っていたら起きること」を見る** —
   `cached` が前ターンの `prompt` 付近まで伸びる（履歴が前方一致する）ことを確認
5. **要約の枠と接地の枠が画面で別**（D6）。両方が出るターンで見る
   （xAI の Live Search + thinking が同時に出る回が最も濃い）

## Notes

1. **v0.2.0 の残りは本 Spec と Spec 34 と多モーダル。** 公表が最後のマイルストーン
2. **未確認が 1 点** — `display` を 5 世代以外の Anthropic モデルへ送って
   拒否されないか。この村の登録は全部 5 世代なので実害は無いはずだが、
   **確かめていない**（P2 で送る条件を決めるときに数える）
3. **`output_config.effort` は本 Spec の対象外。** `canonical.rs` の doc に
   名前だけがあり実装は無い。**思考の深さの制御**は受け取りとは別の問いで、
   足すなら `Effort` の写像（既存の `reasoning_effort` と同じ棚）
4. **Spec 32 で 4 回外した機序を持ち込まない**ための確認を Phase に埋めてある —
   D2 の対（1 サンプルで決めない）/ D3 の 3 対（probe の数字を設計根拠にしない）/
   検収から数字を外す（測定条件の産物を合格条件にしない）
