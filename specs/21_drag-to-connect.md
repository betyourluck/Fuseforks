# Spec: カードから絆を引く — サーヴァントリストから地図のノードへのドラッグで接続

**ID**: 21
**Date**: 2026-08-06
**Status**: Draft rev1（査読待ち）
**Branch**: なし（main へ Phase 単位で直接コミット）

## Goal

サーヴァントリストのカードを「サーヴァントの絆」のノードへドラッグして落とすと、
カードのサーヴァントからそのノードのサーヴァントへの絆が張られる。

起点は利用者の言葉（2026-08-06）—「サーヴァントの編集ダイアログを開いて
絆をつなげるのは面倒」。

**「線は人が引く」は動かない** — 引く操作の入口が 1 つ増えるだけで、
機械が線を引く経路は 1 本も増えない。

## 現況（実測 2026-08-06）

絆の追加経路は既に 2 つある:

| 経路 | 実装 | 反映 |
|---|---|---|
| 編集ダイアログのチェックボックス | `AgentSettingsDialog.vue` の `toggleConnection` | 保存ボタンでまとめて |
| 地図のハンドル同士のドラッグ | `TopologyMap.vue` の `onConnect`（Vue Flow の `@connect`） | 即時・一方向・重複は `includes` で弾く |

保存はどちらも source の `connectedAgents` へ target を足す**一方向**
（`orchestrator.setConnections`）。双方向は逆向きがもう 1 本ある状態を
1 本の線で描く（既存の描画規則。削除はその 1 本で両方向とも切れる）。

**リストのカードは既にドラッグできる** — `AgentList.vue` の `VueDraggable`
（並び替え）。`:force-fallback="true"` 付き。

**ネイティブ HTML5 DnD はこのアプリでは使えない**（Phase 0 で 1 回だけ実測して
確定させる）。`tauri.conf.json` は `dragDropEnabled` を書いていない = Tauri v2 の
既定 `true` で、Windows WebView2 では Tauri がドロップイベントを横取りするため、
ページ内の `dragstart` / `dragover` / `drop` が発火しない。`force-fallback: true` が
付いている理由がこれ。**本 Spec の機構はネイティブ DnD を前提にできない。**

## 設計の核

**機構は「fallback ドラッグの終端座標でヒットテスト」**。VueDraggable
（SortableJS）の fallback はドラッグ中の分身をリストの外まで追従させ、
`@end` の `originalEvent` に終端座標（clientX/Y）が残る。終端で
`document.elementFromPoint` を引き、Vue Flow のノード要素
（`.vue-flow__node` の `data-id`）に当たれば絆を張る。

- **方向はカード = source、ノード = target の一方向**（D1）
- **追加の規則は 1 実装へ寄せる** — `onConnect` の「`includes` で弾いて
  `setConnections`」を共有関数へ切り出し、drop 経路から同じものを呼ぶ
  （同じ規則を 2 箇所に書かない）
- **自分自身への drop・既存の絆は no-op**
- **リスト内で終わった drop は今までどおり並び替え。地図で終わった drop は
  並び替えを確定しない**
- 削除は射程外（既存の `@edge-click` + 確認のまま）

## 決めること

- **D1 方向** — 一方向（`onConnect` と同じ規則）を推す。ドラッグには始点と
  終点がある以上、これを双方向にすると既存のハンドルドラッグと規則が割れ、
  「どちらの操作で引いたか」で線の意味が変わる。双方向にしたければ逆も引く
  （今までと同じ）
- **D2 ドラッグ中の視覚フィードバック** — ノードの上へ来たら対象をハイライト
  する。無いと「落とせる場所」が画面から読めない。ただし fallback の分身が
  `elementFromPoint` を遮る問題と同根なので、成立するかは Phase 0 の PoC で
  確かめてから約束する
- **D3 成功の告知** — 地図に線が現れることが応答そのもの。トーストは出さない
  （操作のたびに 1 枚積まれる）

## Stories

- S1 カードを地図のノードへ落とすと絆が張られ、線が即時現れる
- S2 接続済みの相手・自分自身へ落としても何も起きず、何も壊れない
- S3 リスト内の並び替えは今までどおり動く（本 Spec で挙動を変えない）
- S4 落とせる場所がドラッグ中に分かる（D2 が PoC で成立したら）

## Tasks

- fallback ドラッグの終端で `elementFromPoint` が Vue Flow ノードを返すことを
  実測する。**SortableJS の分身が座標上に残っていれば分身自身が返る** —
  `@end` 時点で分身が除去済みかを確かめ、駄目なら分身へ
  `pointer-events: none` を打つか、除去後の次フレームで判定する
- ドラッグ中の hover 判定（D2）が同じ機構で取れるかを実測する
- ネイティブ DnD が発火しないことを 1 回実測し、現況の記述を確定させる
- **PoC の結論しだいで機構を差し替える判断はここで下す**（pointer イベントの
  自前実装が代替。VueDraggable を触らずに済むかが分かれ目）

## Notes

1. **契約面はゼロの見込み。** `setConnections` / `TopologyEdge` /
   `topologyPositions` / `list_topology` は据え置きで、変わるのはフロントの
   操作経路だけ。ライトテーマ・StatusBar と同じ「フロントで閉じる」形だが、
   決めること（D1〜D3）と機構の選択（Phase 0）があるので Spec を切った
2. **3 つ目の入口であって、新しい規則ではない。** 追加の規則が 1 実装に
   寄っていることを Phase 1 のテストで留める
3. **`force-fallback: true` の理由を初めて台帳に書いた。** 今までコメントが
   無く、次に誰かが「ネイティブに戻せば軽くなる」と親切心で外すと、
   Windows WebView2 では並び替えごと動かなくなる
