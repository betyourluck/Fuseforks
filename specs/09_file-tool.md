**ID**: 09

**Status**: Draft rev1（査読待ち）
**Branch**: なし（main へ Phase 単位で直接コミット。契約凍結 Phase は本 Spec の

## Goal

同梱ツールへ `file` を 1 本追加し、作業フォルダ内のファイル・フォルダ操作
（読む・作る・動かす・消す）をエージェントに渡す。

起点は実機の空転（2026-07-31）: README の英訳を頼んだが、道具立てに
**ファイルの新規作成が無く**、エージェントは `sd` で延々と試み続けた。
`sd` のファイル不在エラーは OS エラーの素通し（「読めません: os error 2」）で、
「新規作成はできない」とどこにも書いていない — モデルはパスの書き方の問題と
解釈して再試行する。**判断材料の欠落**型の空転で、能力を足すと同時に、
できないことをできないと言う文言も直す。

### 立場の宣言

- **1 ツール + op 列挙**（利用者判断 2026-07-31）。`yq` が確立した形
  （`op: get / set / remove`）をそのまま踏襲する。操作ごとに 6 本のツールを
  並べると毎ターンのスキーマ固定費が 6 倍になり、モデルの選択肢も散る
- **crate は増やさない。本体は `std::fs`。** ファイル操作は crate の穴ではなく
  契約設計が本体。唯一の例外は削除の安全化で `trash`（下記）
- **削除はごみ箱へ。完全削除の経路は作らない。** エージェントの操作は
  取り消せる側に倒す（拒否文言で嘘をつかない — できないことは仕様として明記）

## Stories

### P1: `file` ツール

> エージェントとして、作業フォルダの中でファイルを作り・読み・動かし・消したい。
> なぜなら翻訳や成果物の書き出しは「新しいファイルを作る」が本体で、
> 既存ファイルの書き換え（`sd` / `yq`）だけでは完結しないから。

**ツール定義**

- name: `file`
- 提示条件: 既存のファイル系ツールと同じ（作業フォルダ設定済みのエージェント。
  未設定なら `work_dir_missing()` の共通文言）。`enabledTools` のフィルタにも
  既存ツールと同じく従う
- 引数（`op` は閉じた列挙）:

  | op | 引数 | 動作 |
  |---|---|---|
  | `read` | `path` | 中身を返す。サイズ上限とバイナリ拒否は `sd` と同じ規律 |
  | `write` | `path`, `content`, `overwrite?` | ファイルを書く。**既存ファイルは `overwrite: true` が無い限り拒否**（案内: 部分編集は `sd` / `yq`） |
  | `mkdir` | `path` | フォルダを作る（`create_dir_all`。中間も作る） |
  | `move` | `path`, `to` | 移動・改名（両端とも境界内） |
  | `copy` | `path`, `to` | 複製（両端とも境界内） |
  | `remove` | `path` | **OS のごみ箱へ移す**（`trash` crate）。フォルダも可 |

- 実装は `tools/fs.rs` の隣（`tools/file.rs`）。境界検査は既存の
  `resolve_in_work_dir` を再利用する

**境界の変種 — 実在しない宛先（本 Spec の実装で必ず踏む穴）**

`resolve_in_work_dir` は canonicalize + 前方一致で、**実在するパスでしか
成功しない**。`write` / `mkdir` / `move` / `copy` の宛先は実在しないのが
正常系なので、そのままでは全部「見つかりません」で落ちる。変種
`resolve_creatable` を切り出す:

1. 宛先の**実在する最も深い祖先**を canonicalize し、作業フォルダ内であることを
   前方一致で検査する
2. 祖先から宛先までの残り成分に `..` と絶対パス成分が無いことを検査する
   （canonicalize できない区間は文字列検査しかない — `..` を許すと
   実在する祖先の検査をすり抜けて外へ出られる）
3. symlink は辿らない（既存の囲いと同じ。リンクを踏むと囲いが破れる）

**エラーは全部モデルが読んで次を決められる文言にする**（`Ok(String)` で返す
既存規律）。特に:

- `write` で既存ファイル + `overwrite` 無し →「`{path}` は既にあります。
  書き換えるなら sd / yq、丸ごと置き換えるなら overwrite: true を付けてください」
- `remove` →「ごみ箱へ移しました（完全削除はしていません）」
- 境界外 → 既存の「作業フォルダの外を指しています」と同じ文言

### P2: `sd` の空転を閉じる（文言の相互参照）

> エージェントとして、`sd` が新規作成できないことをエラーから知りたい。
> なぜなら知らなければ書き方の問題だと解釈して再試行し続けるから。

- `sd`（と `yq`）のファイル不在エラーを
  「`{path}` は作業フォルダ内に見つかりません。**このツールは既存ファイルの
  書き換え専用で、新規作成はできません — 作るなら `file` ツールの `write` を
  使ってください**」へ差し替える
- 禁止ではなく案内で空転を消す（この行動を選ぶ理由を消す情報を与える —
  Concordia で確立した処方。failures.md #20 と同型）

**Acceptance**

- Given 作業フォルダ設定済み、When `write` で新規ファイル、Then 作成され
  中身が一致する
- Given 既存ファイルへ `write`（`overwrite` 無し）、Then 拒否され、`sd` / `yq` /
  `overwrite: true` への案内が返る
- Given `overwrite: true`、Then 置き換わる
- Given `mkdir` で深い階層、Then 中間フォルダごと作られる
- Given `move` / `copy`、Then 宛先に現れ、`move` は元が消える
- Given `remove`、Then ファイルが場所から消え、結果文言に「ごみ箱」が含まれる
- Given 境界外の宛先（`../escape` / 絶対パス / 実在しない深い `../` 混じり）、
  Then 何も起きず「作業フォルダの外」の文言が返る
- Given symlink 経由で外を指す宛先、Then 拒否される
- Given バイナリへの `read`、Then 拒否される（`sd` と同じ文言）
- Given 作業フォルダ未設定、Then `work_dir_missing()` の共通文言
- Given `sd` でファイル不在、Then エラーに「新規作成はできません」と
  「`file` ツール」への案内が含まれる

## Notes（査読論点）

1. **crate の選定**: 本体は `std::fs`（create_dir_all / rename / copy /
   read / write で全 op が書ける）。新依存は **`trash` 1 つ**（ごみ箱移動、
   Win / macOS / Linux 対応）。検討して不採用: `walkdir` / `ignore`
   （探索は `fd` / `grep` が既に自前で持つ）、`tempfile`（tmp + rename は
   `save_world` の自前パターンで足りる — そもそも本ツールの write に原子性の
   要求は無い）、`fs-err`（エラーへのパス埋め込みは既に自前 format でやっている）。
   `dunce` は canonicalize の `\\?\` 前置が**モデルの読むエラー文言に漏れる**
   ことが実装中に観測されたら入れる（今は表示前に相対化しているはずなので保留）
2. **1 ツール + op 列挙の根拠**: スキーマの固定費（毎ターン全ツール定義を運ぶ）と
   モデルの選択の散らばり。`yq` の前例で列挙 op の可読性は実証済み
3. **`append` を持たない**: `read` → `write(overwrite)` で表現できる。
   席を作るのは「追記で足りるのに全文を運ぶのが実測で重い」と分かってから
   （確かめる前に席を作らない — Spec 05 Notes 4 の流儀）
4. **preview を持たない**: `sd` の preview は既存内容を壊す操作だから要る。
   `write` の新規作成は壊すものが無く、上書きは `overwrite` ゲートが同じ役割を
   果たす。`remove` はごみ箱で可逆
5. **完全削除を作らない**: ごみ箱が無い環境（一部の Linux 構成）では `remove` が
   失敗する。そのときは「この環境ではごみ箱が使えないため削除できません。
   利用者に頼んでください」を返す — 勝手に完全削除へフォールバックしない
6. **`sd` 文言は Phase 3 で直す（本 Spec に同梱）**: `file` が入る前に文言だけ
   直すと「`file` ツールを使え」が嘘になるため、順序はツールが先
7. **割り込み停止は別 Spec（10 候補）**: 空転の非常口（人間が切る）は層が違う
   （ターン制御 vs ツール能力）。本 Spec は空転の理由を消す側
