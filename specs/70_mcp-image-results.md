## rev1 からの変更（査読 9 点の反映。詳細は Notes 2）

- **D2 の二重定義を解いた** — 再エンコードしないもの（JPEG / WebP で上限の内側 = バイト列をそのまま）と、再エンコード
  するもの（PNG・上限超え = JPEG 85・透明は白）を分けて書いた。白で塗るのは再エンコードするときだけ
- **「代替」を 1 つの意味にした** — 設計の語としての「代替」は OpenAI 互換が使う「直後の利用者の発話」だけ。P0 で
  Anthropic と Gemini に試した「同じ発話の別ブロック」は測定の変種で、どのワイヤも採らない（D1）
- **OpenAI 互換を一律に代替にした代償を書いた**（xAI の互換の口はネイティブで読めるのに発話が 1 つ増える）
- **1 要求に載せる画像の総数に上限を足した**（D2b 新設）— 査読の「利用者の添付と上限を共有したらどちらを落とすか」は
  前提が違った（共有しているのは 1 枚の上限の値で、予算ではない）。ただし同じ方向に実在する穴があった — ターンの中で
  ツールを何周も呼ぶと画像が積み上がり、Anthropic の 1 要求 100 枚の上限を超える
- **RepeatGuard の要約値は、接続先へ送るバイト列で取る**（D4）
- **Goal 1 の射程を「画像を読めるモデル」に絞った** — 200 で画像を黙って無視するモデルはコアから見分けられない（D5）
- **コアが足す文はすべて村の言語で、言語を知っている層が書く**（D5 / D6 / D1 の代替の本文）— 査読は D5 の一文の
  日本語固定を指したが、引くと rev1 の D5 は送り直しを `LlmBackend::chat`（言語を知らない層）に置いていた。
  `failures.md` #149 の形そのものなので、送り直しの置き場をターンの層へ移した
- **`ToolOutput` の形を決めた**（D7）— 落とした画像は `images` に入れず、`text` に村の言語で書き、落とした理由は計器用に別に持つ
- 反証 1 件: 「代替の発話を足すと入力キャッシュの前方一致が効かなくなる」（D3 に理由を書いた）
- 起点: 利用者（2026-10-24）—「NIK（Nikon のカメラと MCP で繋ぐアプリ）でカメラの写しているイメージを取得したい。
  Fuseforks のツール実行ではテキスト以外は受け取れないようになっているようだ。テキスト以外も受け取れるようにできるか」
- 調査だけのターンを 1 回取った（コード: `mcp.rs` の `render_tool_result` / `tool.rs` の `AgentTool::call` /
  `llm/canonical.rs` の `ChatMessage.attachments` / 各ワイヤの `Role::Tool` の組み立て / `attachment.rs` の上限 /
  `orchestrator/turn.rs` の `RepeatGuard`）。下の「現況」はその実測

## 覆す判断

- **`render_tool_result` の「テキスト以外は種別だけを明示して落とす」**（`mcp.rs` の doc —「そのまま渡せないので」）。
  落としていた理由は経路が無かったことで、黙って捨てないための注記は正しかった。本 Spec は**画像だけ**経路を作り、
  音声・埋め込みリソースは今の注記のまま残す（D6）

## Goal

1. MCP サーバーがツールの結果として返した画像（`type: "image"`）を、そのツールを呼んだ個体のモデルが見られる。
   **対象は画像を読めるモデル**（rev2）— 画像を読めないモデルのうち 200 で黙って無視するものは、コアから見分けられない（D5）
2. 画像を返さない MCP・同梱ツールの挙動は 1 バイトも変わらない（ツールの提示・結果の本文・履歴・ログ）
3. 画像が入っても、同じ失敗の繰り返しを止める歯止め（RepeatGuard）が誤って止めない・誤って見逃さない
4. 画像を読めないモデルの個体で、ターンが落ちない
5. 外へ送るものが 1 つ増えることを、PRIVACY に書く

## 現況（実測 2026-10-24）

- **落としている場所は 1 箇所** — `mcp.rs` の `render_tool_result` が `CallToolResult.content` の各ブロックを
  `as_text()` で見て、テキスト以外を「（テキスト以外の内容が返されました。この経路では扱えません）」の 1 行へ置き換える。
  この 1 行は**日本語固定**で、英語の村にも日本語のまま入る（`failures.md` #149 の家族）。単体
  `non_text_blocks_are_reported_rather_than_dropped` がこの挙動を留めている
- **ツールの戻り値の型がテキストしか運べない** — `AgentTool::call` は `CoreResult<String>`（`tool.rs`）
- **運ぶ器は半分ある** — `ChatMessage.attachments: Vec<PromptAttachment>`（Spec 23 / 36）。ただし各ワイヤが
  添付を組み立てるのは利用者の発話だけで、`Role::Tool` は本文だけを送る（例: `openai_compat.rs` の `Role::Tool` は
  `OaiContent::Text` で即 return）
- **ツール結果はもともと 1 ターン限り** — 履歴（`Record::Exchange`）にはツール結果を積まない。ターンの中の 2 周目
  以降には送り直される（入力キャッシュの前方一致に乗る）
- **コアが扱える画像の形式は WebP と JPEG だけ**（`PromptMediaType`）。利用者の添付は画面側が WebP にしてから送る
  （Spec 23）。上限は `ATTACHMENT_IMAGE_MAX_BYTES` = 2 MB・`ATTACHMENT_IMAGE_MAX_EDGE_PX` = 1568。依存の `image` は
  `features = ["webp", "jpeg"]` で、**PNG のデコーダが無い**。`image` の WebP エンコーダは可逆だけ
- **RepeatGuard は (ツール名, 引数, 結果の本文) で数える**（`turn.rs` の `RepeatGuard::observe`）。本文が同じで画像
  だけが違う結果（ライブビューを撮り直す）は「同じ結果の 3 回目」として止まる
- **ツール結果の圧縮（Jev・Spec 59 / 60）は本文の文字列を見る**。ツールの出力の表示（Spec 57）も文字列のリング
- **各社がツール結果の中の画像を受けるか** — Anthropic は `tool_result` の `content` に画像ブロックを置ける（文書）。
  OpenAI 互換の `role: "tool"` はテキストだけ（文書）。Gemini ネイティブ・OpenAI / xAI / Meta / Perplexity の
  Responses は**未測定**（P0）。利用者の発話に載せる画像は 7 ワイヤ全部が運べる（Spec 36 の carries 表）

## Design

### D1. 画像を置く場所 — ワイヤごと（P0 で決める）

- **ツール結果の中へ置けて、モデルが中身を読めるワイヤは、ツール結果の中へ置く**（ネイティブ）
- **置けないワイヤは、ツール結果の直後に利用者の発話を 1 つ足して、そこへ載せる**（代替）。本文は
  「（{ツール名} の結果の画像 N 枚）」— モデルが「利用者が貼った画像」と取り違えないよう、どのツールの結果かを名乗る。
  送り手封筒（Spec 26）は付けない（利用者の発話ではなく、コアが組んだ運び台）
- **「代替」はこの 1 つの意味だけ**（rev2）。P0 で Anthropic と Gemini に試した「同じ発話の別ブロック」は測定の変種で、
  どちらのワイヤもネイティブを採るので実装には現れない
- **代替の本文はターンの層が村の言語で組み、canonical で adapter へ渡す**（rev2。D6）— adapter は言語を知らないので
  文を書かない（`failures.md` #149）。ツール結果の `ChatMessage` に画像と一緒に載せる欄を 1 つ足す（名前は P1）
- どちらにするかは P0 の実測で表にして `data_contract` に凍結する（Spec 36 の carries 表と同じ形 — 述語 1 実装と
  adapter の一致をテストで留める）。**P0 の結果**:

  | ワイヤ | 置き場 | 根拠（P0） |
  |---|---|---|
  | Anthropic | ネイティブ（`tool_result` の `content` の配列に画像ブロック） | ネイティブ・代替とも読めた |
  | OpenAI 互換 | **代替**（`role: "tool"` は本文だけ、直後に利用者の発話で `image_url`） | ネイティブは接続先しだい（Gemini の互換の口 = 400、xAI の互換の口 = 通る）。代替は 2 つとも読めた |
  | Gemini ネイティブ | ネイティブ（`functionResponse.parts` に `inlineData`） | ネイティブ・代替とも読めた（3.5-flash-lite / 3.8-flash） |
  | OpenAI Responses | ネイティブ（`function_call_output.output` を `input_text` + `input_image` の配列に） | ネイティブ・代替とも読めた |
  | xAI Responses | ネイティブ（同上） | 同上 |
  | Meta Responses | ネイティブ（同上） | 同上 |
  | Perplexity Responses | ネイティブ（同上） | 画像を受けるモデル（`google/gemini-3.7-flash`）でネイティブ・代替とも読めた |

- **OpenAI 互換を一律に代替にした代償**（rev2）— `openai_compat.rs` は接続先を区別しない 1 実装で、ネイティブが通るかは
  接続先しだい（Gemini の互換の口 = 400、xAI の互換の口 = 通る）。400 になる接続先を避けるため一律に代替にする。
  代償は、ネイティブで読める接続先（xAI の互換の口など）でも利用者の発話が 1 つ増えること（本文は 10 トークン前後）。
  xAI を Responses のワイヤ（`xai_responses`）で使う個体はネイティブなので、この代償は互換の口を選んだ個体だけ
- canonical では、画像を**ツール結果の `ChatMessage.attachments`** に載せる。ネイティブか代替かは adapter が決める
  （プロンプトを組む側は場合分けを抱えない）

### D2. 形式と大きさ — コアで JPEG へ寄せる

- **2 つに分ける**（rev2。rev1 は「すべてデコードして JPEG へ」と「上限の内側ならそのまま」を同じ段落に書いていた）:
  - **再エンコードしない**: `image/jpeg` か `image/webp` で、長辺 1568px 以下・2 MB 以下のもの。**MCP が返したバイト列を
    そのまま送る**（寸法を読むためにデコードはするが、エンコードし直さない。WebP の透明はそのまま残る — 7 ワイヤとも
    WebP を受ける）
  - **再エンコードする**: `image/png`、または上限（長辺・大きさ）を超えた JPEG / WebP。デコードし、長辺 1568px へ縮め、
    **JPEG（品質 85）** へ。**透明は白で塗る**（JPEG は透明を持たない。白で塗るのはこの経路だけ）。再エンコードしても
    2 MB を超えるものは落とす
- WebP へ再エンコードしない理由: `image` の WebP エンコーダは可逆だけで、写真が 2 MB の上限を超えやすい。非可逆の WebP は
  C 依存（libwebp）になる。JPEG は 7 ワイヤ全部が運ぶ（Spec 23 の JPEG フォールバック・本 Spec の P0 で実測済み）
- **上限**: 1 つのツール結果につき画像 4 枚・1 枚 2 MB・長辺 1568px。**値は利用者の添付と同じ定数
  （`ATTACHMENT_IMAGE_MAX_BYTES` / `ATTACHMENT_IMAGE_MAX_EDGE_PX`）を使うが、予算は共有しない**（rev2。利用者の添付は
  1 発話 1 枚で、ツール結果の画像とは別の発話に乗る。どちらかを落として他方を通す関係は無い）
- デコードできない・形式が違う（GIF など）・上限を超えた画像は落とし、**落としたことを本文に書く**（`failures.md` #44。D7）
- `image` に `png` の機能を足す（純 Rust。依存の木に 7 crate 増えるが、7 つともロックファイルに既にある。P0）

### D2b. 1 要求に載せる画像の総数（rev2 で新設）

- ツール結果の画像は、ターンの中で周を重ねるたびに `messages` に積み上がり、毎周送り直される（D3）。カメラを何度も
  撮るターンでは、Anthropic の **1 要求 100 枚**の上限（20 枚を超えると 1 枚の上限も 2000px へ下がる）に届く
- **1 要求に載せるツール結果の画像は、新しいものから 20 枚まで。** 超えたら古いものから外し、外したツール結果の本文に
  「（前の周の画像は省きました）」を村の言語で足す（ターンの層）
- 古い画像を外すとその位置から後ろの前方一致が切れ、その周は入力キャッシュの書き直しになる（D3）。新しい画像を
  落とす形は採らない — カメラを見張る仕事では、要るのは最新の画像

### D3. 寿命 — 1 ターン限り

- ツール結果と同じ。履歴にも `sessions.redb` にも入らない（Spec 23 D1 と同じ判断）
- ターンの中では 2 周目以降に送り直される。入力キャッシュの前方一致に乗るので、払いは主に最初の 1 回
- **代替（D1）でも前方一致は保たれる**（rev2。査読の反証）— 代替の発話はツール結果の直後に**追記**され、次の周も
  同じバイト列で組み直されるので、`messages` の並びは周をまたいで前方が変わらない。前方一致が切れるのは D2b で
  古い画像を外したときだけ。代替の本文が足すのは 10 トークン前後で、画像のトークン（NIK の 640×424 で約 360）は変わらない

### D4. RepeatGuard — 本文と画像の要約値で数える

- 「同じ結果」の判定に、画像のバイト列の SHA-256 を加える。本文が同じで画像が違えば別の結果
- **要約値を取るのは、接続先へ送るバイト列**（rev2）— 再エンコードしないものは MCP が返したバイト列、するものは
  再エンコード後の JPEG。D2 の経路の分かれ目を判定に持ち込まない（同じ入力は同じ経路を通るので、同じ画像は同じ要約値）。
  落とした画像は要約値の列に入れない
- 画像を返さないツールの判定は今と同じ（要約値の列が空）

### D5. 画像を読めないモデル — 画像を外して 1 回だけ送り直す

- ツール結果の画像を含む要求が 400 で返ったら、ツール結果の画像を外し、そのツール結果の本文に「画像はこのモデルへ
  送れませんでした」を足して 1 回だけ送り直す
- **置き場はターンの層**（rev2 で rev1 から移した）— rev1 は Spec 23 D3 の JPEG フォールバックと同じ
  `LlmBackend::chat` の最外周に置いていたが、そこは村の言語を知らない層で、足す一文が日本語固定になる
  （`failures.md` #149 が直したばかりの形）。ターンの層は村の言語を知っており、`messages` を組み直せる。
  その周の `messages` から画像を外すので、以後の周も画像なしで続く（同じ 400 を毎周踏まない）
- 外して通ったことはログに 1 行（`tool image fallback:`）
- **この網に掛からないモデルがある**（P0）— 画像を読めないモデルの一部は 400 を返さず、200 で画像を黙って無視する。
  sakura の gpt-oss-120b は 3 回とも 200 で、1 回は**存在しない色（青と赤）を答えた**。コアからは見分けられないので
  機構は足さず、DETAIL に「画像を読めないモデルの個体では、画像が無いと答えるか、中身を捏造することがある」と書く。
  **このモデルは Goal 1 の対象外**（rev2）— Goal 4 の「ターンが落ちない」は満たすが、「見られる」は満たせない

### D6. 範囲 — 画像だけ

- 音声（`type: "audio"`）・埋め込みリソース（`type: "resource"`）は今の注記のまま。ただし**注記の文を村の言語で**
  書く（日本語固定の 1 行を直す）
- **コアがツール結果に足す文は、すべて村の言語で、言語を知っている層が書く**（rev2。査読 8 を広げた）:

  | 文 | 書く層 |
  |---|---|
  | テキスト以外を扱えない注記（音声・リソース） | `McpTool`（`ToolContext.language` を持つ） |
  | 画像を落とした注記（D2・D7） | `McpTool` |
  | 代替の発話の本文（D1） | ターンの層（canonical の欄で adapter へ渡す） |
  | 前の周の画像を省いた注記（D2b） | ターンの層 |
  | 画像をモデルへ送れなかった注記（D5） | ターンの層 |

  adapter（LLM の層）は文を 1 つも書かない
- 同梱ツールは画像を返さない。戻り値の型を広げるのは MCP のツールだけ（D7）

### D7. 型 — 既定実装つきのメソッドを足す

- `AgentTool` に `call_with_media`（仮）を足し、既定は `call` の文字列をそのまま包む（`ToolOutput { text, images }`）。
  上書きするのは `McpTool` だけ。同梱ツールは 1 行も変えない
- **一部の画像を落としたときの形**（rev2）— `ToolOutput` は 3 つを持つ:
  - `text`: MCP のテキストのブロックに、落とした画像の注記（村の言語）を足したもの。**モデルが読むのはこれ**
  - `images`: 送る画像だけ（D2 を通ったもの。最大 4 枚）。**落とした画像は入れない**
  - `dropped`: 落とした画像の理由の列（形式違い / デコード不能 / 大きさ超え / 枚数超え）。**計器だけが読む**
    （`tool image dropped:` 行）。モデルへは `text` の注記で伝わる
- 部分的な成功はエラーにしない — テキストと残った画像は届ける。すべて落ちたら `images` が空で、`text` に注記だけが残る
  （「空の結果」にしない）
- 呼ぶ側（`CallRunner`）は `call_with_media` だけを呼び、画像をツール結果の `ChatMessage.attachments` へ載せる

### D8. 他の機構との関係

- **ツール結果の圧縮（Jev）**: 本文だけを見る。画像は送らない・落とさない
- **ツールの出力の表示（Spec 57）**: 本文の後ろに「（画像 N 枚・{形式}・{大きさ}）」を足す。画像そのものはリングに
  持たない
- **計器**: `tool:` 行に `images=N`（画像を返したときだけ）。落とした画像は `tool image dropped: … reason=…` を 1 行。
  **画像の中身は書かない**
- **トークン予算**: 画像のトークンは接続先が返す `usage` にそのまま入る（新しい計上は要らない）

### D9. PRIVACY

- 日英の「LLM の接続先へ送るもの」に「MCP サーバーがツールの結果として返した画像（Spec 70）」を足す。
  NIK のように実世界を写す画像が、その個体のモデルの接続先へ出る

## 採らなかった形

- **画像を常に代替（利用者の発話）で運ぶ** — 1 経路で済むが、ネイティブで運べるワイヤでも「利用者が貼った」と読める
  位置に置くことになる。P0 で運べると分かったワイヤはネイティブを使う
- **画像を WebP へ寄せる** — D2 の理由（可逆だけ / C 依存）
- **画像を履歴に残す** — D3（Spec 23 D1 と同じ）

### P0 実測記録（2026-10-24）

**測り方**: 使い捨ての Python（scratchpad。リポジトリには入れていない）で、各社の API を直に 2 段で撃った —
1 段目で `camera_snapshot`（引数なしの関数）を呼ばせ、2 段目で 1 段目の出力を逐語で積み（Anthropic の思考ブロック・
Gemini の `thoughtSignature`・Responses の `reasoning` を含む）、画像入りのツール結果を返す。画像は 128×96 の
左半分が緑・右半分がマゼンタの合成で、答えに両方の色が出れば「読めた」。置き方は **ネイティブ**（ツール結果の中）と
**代替**（Anthropic と Gemini は同じ発話の別ブロック、それ以外は直後の利用者の発話）。鍵は資格情報ストアから読み、
表示もファイルへの書き出しもしていない。

| 対象（モデル） | ネイティブ JPEG | ネイティブ WebP | 代替 JPEG |
|---|---|---|---|
| Anthropic（claude-sonnet-5-5） | 読めた | 読めた | 読めた |
| Gemini（gemini-3.5-flash-lite / gemini-3.8-flash） | 読めた | 読めた | 読めた |
| OpenAI Responses（gpt-6.1-sol） | 読めた | 読めた | 読めた |
| xAI Responses（grok-4.7） | 読めた | 読めた | 読めた |
| Meta Responses（muse-spark-1.3-contributor） | 読めた | 読めた | 読めた |
| Perplexity Responses（google/gemini-3.7-flash） | 読めた | 読めた | 読めた |
| OpenAI 互換・Gemini の互換の口（gemini-3.5-flash-lite） | **400** `Invalid content part type: image_url` | **400** | 読めた |

**画像を読めないモデル**（D5 の網との関係）:

|---|---|

  OpenAI の文書はツールの結果をテキストだけと書いており、D1 で OpenAI 互換を代替に固定するので結論は変わらない
- sakura の Qwen3-VL — サーバー側でツールが使えない設定（`"auto" tool choice requires --enable-auto-tool-choice`）

**実物の MCP の画像**（NIK の `live_view_image`、Claude Code から 1 回）: `content` は **JPEG の画像 1 枚

**依存**: `image` に `png` を足すと、`fuseforks-core` の依存の木に 7 crate（`png` / `fdeflate` / `flate2` /

**トークン**: 合成の画像（128×96）は入力の数十トークン。NIK の 640×424 なら Anthropic の目安（幅 × 高さ ÷ 750）で
約 360 トークン。ターンの中の 2 周目以降に送り直されるが、入力キャッシュの前方一致に乗る。

**実装で決めたこと**（Design に書いていなかったもの）:

- **形式は `mimeType` ではなくバイト列で決める**（`image::guess_format`）— `mimeType` はサーバーの自己申告で、
  送る `media_type` がバイト列と食い違うと接続先が 400 を返す。判別できないバイト列は「読み取れない」、
  判別できて運べない形式（GIF・BMP）は「対応していない形式」と分けた
- **アニメーション WebP は再エンコードの経路**（先頭フレームの JPEG）— そのまま送ると、モデルに何が渡るかが
  接続先しだいになる
- **展開の上限 1 辺 16,384px**（`TOOL_IMAGE_DECODE_MAX_EDGE_PX`）— 伸張爆弾の歯止め。D2 の「上限を超えたら縮めて送る」は
  縮める前に展開するので、小さなファイルで巨大な画像を名乗られるとメモリを食い尽くす。超えたら展開せずに
  「大きすぎる」で落とす
- **画像だけが返った結果の本文は「（画像 N 枚）」**（`McpTool`）— Spec 70 の前の「（空の結果）」のままだと嘘になる。
  D6 の表に無かった 6 つ目の文
- **同じ関数にあった日本語固定の 2 文も村の言語へ**（「（空の結果）」「ツールはエラーを返しました:」）。日本語の村の
  本文は、画像を返さない結果では Spec 70 の前と 1 バイトも変わらない。**ターンの層に以前からある日本語固定の文**
  （ツールの実行に失敗しました / そのツールはありません / 同じ結果の繰り返しを止めた文）は範囲外のまま
- **1 要求 20 枚の確かめは周の終わりの 1 回**で、`messages` を直に書き換える。一部だけ外す結果は先頭から残し、代替の
  本文の枚数を組み直す。同じ結果を 2 度絞っても一文を重ねない。外した周にだけ `tool image capped:` の 1 行
  （D8 に無かった計器）
- **送り直しの拒否は 400 と `ImagesRejected`** — OpenAI 互換の口では、ツール結果の WebP も Spec 23 の JPEG フォールバックを
  通り、2 回とも 400 なら `ImagesRejected` で返る。送り直した後のターンでは、**新しいツール結果の画像も載せずに**
  本文へ一文（同じ 400 を毎周踏まない）。打ち切りが立っていたら送り直さない。**まとめ呼び出し**（ツール上限・
  繰り返しで打ち切った後の 1 回）も同じ送り直しを通す — 最後の周に返った画像を初めて運ぶ呼び出しになりうる
- **表示の 1 行の形は「（画像 1 枚: JPEG 21 KB）」**（複数なら「、」でつなぐ）。D8 の「（画像 N 枚・{形式}・{大きさ}）」を、
  枚数ごとに形式と大きさが違いうる形へ寄せた

**テスト**: 単体 = `tool_image` 14 本（2 経路・透明の白・縮める寸法・展開の上限・GIF / 判別不能 / 壊れた base64・
注記の言語・20 枚の絞り方・送り直しの外し方・表示の 1 行）+ `mcp` の結果の組み立て 9 本（うち 4 本を新設、
既存の `non_text_blocks_are_reported_rather_than_dropped` は画像ではなく**音声**で留め直した — 画像は扱える側へ移ったので、
「テキスト以外」の注記を留めるには音声が要る）。結合 = `tests/tool_image_results.rs` 6 本（ツール結果に載る / 本文だけの
ツールの欄が増えない / 400 で外して送り直し・次の周は最初から載せない / 画像が違えば繰り返しではない / その対照 /
20 枚）+ `tests/tool_image_log.rs` 1 本（計器 3 つと、本文だけのツールの行に `images=` が無い負の対照）。
