# Spec: ツール結果の即時圧縮 — 判断専用モデル Jev で、関連の無い段落を返す前に落とす

- 起票: 2026-09-22
- 状態: **rev1 起票（査読待ち）**。利用者裁定 3 点は取り込み済み（下）。未決 4 点（末尾）
- 起点: 利用者 —「TypeSafe AI の Jev という、文章を出力しないで判断だけを返す AI が話題になっている。
  Kataribe で少し検証した。Fuseforks にもコストカットで使えそうか」→「省略のようなものに効くかな。
  ツール結果の即時圧縮などにも」（2026-09-22）。同日に実測 2 本を取ってから起票した
  （CLAUDE.md「TypeSafe Jev の検討」の節が正。数字は下の「実測」に写した）
- 利用者裁定（2026-09-22）:
  1. **対象は MCP 由来のツールと `rag`。`file` と `run` は対象外**（sqz の教訓 = 圧縮された出力は
     編集の材料に使えない、を入れる）
  2. **閾値は既定値を持ち、利用者が切り替えられる**
  3. **システム設定に Jev の API を設定するページを作り、そこのチェックで圧縮の使用を切り替える**
- 覆す凍結: 無い。`tool_call_detail_contract`（Spec 57）の「モデルへ返した本文を記録する」は
  そのまま — 記録するのは**圧縮後**の本文（モデルが実際に受け取ったもの）。
  2026-08-17 の「ツール出力の畳み込みは作らない」は**行の形で畳む機構**への結論で、
  中身の関連度で落とす本 Spec とは問いが別（あの節に前方参照を入れてある）

## Goal

1. **MCP 由来のツールと `rag` が返した 4,000 字以上の本文から、そのターンの依頼に関係の無い段落を、
   モデルへ返す前に落とす。** 落とすのは結果が返った瞬間の 1 回だけで、落とした後の文字列を
   そのまま積む。以後の周では 1 バイトも変えない（入力キャッシュの前方一致を壊さない）
2. **残る部分は逐語。** 要約も言い換えもしない。切るのは段落の境界だけ
3. **落としたことと、落としたものへ戻る道を、本文に書く**（`failures.md` #44 の規律）
4. **既定は OFF。キーが無ければ機構ごと存在しない。** 使わない村のプロンプト・ツール提示・
   ログは 1 バイトも変わらない
5. **Jev が落ちても、遅くても、ターンは止まらない。** そのときは全文をそのまま返す

**やらないこと（範囲外）**: 履歴の間引き（キャッシュと衝突する。Notes 1）/ 提示するツールの絞り込み
（同）/ `run` の実行前の安全判定（閉じた許容の逆向き。Notes 1）/ 完遂の評価器と手順書の選別
（別 Spec。較正を測ってから）/ `file`・`grep`・`fd`・`sd`・`yq`・`diff`・`blackboard`・`remember`・
`run` の出力の圧縮 / 個体ごとの ON・OFF（裁定 3 はシステム設定の 1 つのチェック。Notes 3）/
Jev の費用を統計画面の `≈ $` へ入れること（Notes 4）/ TypeSafe 直の接続（Cloudflare Workers AI 経由のみ）

## 実測（2026-09-22。起票の根拠）

**ツール出力の比重**（`fuseforks.log` 2026-08-09〜09-22・1,460 ターン・5,818 呼び出し）:
ツール出力は実効コストの **11〜22%**（字→トークンを 0.5〜1.0 で振った幅。ターン内の再送込み）。
字数は `file` 4.02M / MCP 由来 5.29M / `grep` 1.02M / `rag` 0.60M / 全体 12.25M で、
**78% が 4,000 字以上の結果**から来る。本 Spec の対象（MCP 由来 + `rag`）は全体の **48%**。

**段落の採点**（Web ページ 3 本・487 段落・`jev-1.13.0`・依頼文 1 つに対し段落ごとに Noul 1 問）:

| | 閾値 0.2 で落ちる | 0.3 | 0.5 |
|---|---|---|---|
| 記事 15K 字 | 22% | 34% | 62% |
| 論文の HTML 110K 字 | 54% | 71% | 84% |
| ブログ 9K 字 | 43% | 55% | 67% |

- ナビ・フッター・参考文献・結果の表は 0.01〜0.12、依頼の核は 0.85〜0.94 で、両端は分かれる
- **誤って落とすのは依頼文の 2 つ目以降の論点**（2 論点の依頼で、2 つ目に答える節が 0.24〜0.46。
  3 論点目に答える段落が 0.12〜0.17）。閾値を上げるほど副論点から先に消える
- **決定的ではない**（同じ入力 ×8 で 16 問中 11 問が振れ、最大 0.11）
- 152,500 トークン = $0.0064。1 呼び出しの中央 1.05 秒・最大 1.52 秒。110K 字は 25 呼び出し
- 限界: テキスト化は自前の粗い変換で、村が使う MCP の fetch より定型部分が多い（ナビぶんの
  削減は過大）/ 中間帯の同席依存は未測定 / 落とした段落の要否を人が判定した数字は無い

## Design

### D1. 対象は「ツールが自分で名乗る」— 既定は対象外

`AgentTool` に既定実装つきのメソッドを 1 本足す（`wants_reason` と同じ形）:

```rust
/// 返した本文を、関連度で段落単位に落としてよいか（Spec 59）。既定は偽。
fn prunable(&self) -> bool { false }
```

真を返すのは `McpTool` と `RagTool` の 2 つだけ。**名前の表（除外リスト）で持たない** — 新しい同梱ツールは
何もしなければ対象外になる。`file` の出力は `sd` の材料で逐語が要り、`run` の固定枠 12,000 字は
RepeatGuard の完全一致のためにある。どちらも「足し忘れたら圧縮される」形にしない。

合成側（`plan` / `ask_*` / `transfer_to_*` / `room_log`）は `AgentTool` を実装していないので、
構造上ここへ来ない。

### D2. 掛ける場所は `CallRunner` の 1 箇所。RepeatGuard は圧縮前を数える

`turn.rs` の registry の枝（`execute_tool` が返した直後）で、次の順に並べる:

```text
execute_tool → raw
  → repeat_guard.observe(name, args, &raw)      … 圧縮「前」で数える
  → prune(raw) → body                            … 条件を満たすときだけ。満たさなければ body = raw
  → tool_calls.record(args, &body) → emit → `tool:` 行 → Executed(body)
```

**RepeatGuard を圧縮前で数えるのは、Jev が決定的でないため**（実測）。圧縮後で数えると、同じ失敗を
繰り返していても本文が回ごとに 1 段落ずれて、完全一致の数えに乗らない。

圧縮する条件（すべて真のとき）: 設定が ON かつキーが在る / `tool.prunable()` / `execute_tool` が `Ok` /
`raw` が 4,000 字以上 / 本文が JSON として解釈できない（D4）。

解決の 1 実装: いま `registry_reason` と `execute_tool` が同じ「個別 MCP → 共有 registry」の逆引きを
2 箇所に書いている。3 箇所目を作らず、`resolve_registry_tool(shared, agent_id, name)` へ寄せて
3 つ（理由・実行・`prunable`）が同じ 1 本を引く。

### D3. コアは trait、Jev は 1 実装

```rust
#[async_trait]
pub trait ParagraphScorer: Send + Sync {
    /// 段落ごとの 0.0〜1.0。返らなかった段落は `None`（= 残す）。
    async fn score(&self, request: &str, paragraphs: &[&str]) -> CoreResult<ScoreReport>;
}
```

- `crates/fuseforks-core/src/prune.rs` — 純機構（段落へ割る / 採点結果から残す段落を決める /
  省略の印を入れて組み立てる）。HTTP を知らない。単体テストは偽の `ParagraphScorer` で書く
- `crates/fuseforks-core/src/jev.rs` — Kataribe の `crates/llm_client/src/jev.rs` を写す
  （`encode` / `decode` は純関数・Cloudflare の二重包装を剥がす・`json()` 直ではなく text→parse・
  402 は再試行しない）。v1 は Noul だけ。`impl ParagraphScorer for JevClient`
- `Shared` は `RwLock<Option<Arc<dyn ParagraphScorer>>>` を持つ。GUI 層が設定とキーから組んで差し込む。
  `None` なら D2 の条件で落ちて何も起きない

### D4. 段落の割り方と、採点しないもの

- 段落 = 空行区切り。**``` の柵の中は割らない**（1 段落として扱う）。120 字未満の段落は次の段落へ寄せる
- **段落の途中では切らない。** 6,000 字を超える段落は採点せず残す（Jev の state は約 32k トークン）
- **JSON として解釈できる本文は圧縮しない**（`outcome=structured`）— 段落で割ると構文が壊れ、
  モデルは壊れた JSON を読まされる。MCP の結果には JSON の一覧が多い（SNS の投稿一覧・記憶の検索）
- 1 呼び出し 16 段落・12,000 字まで。呼び出しは 4 並列
- 質問文と criteria は**実測した文面をコードの定数として固定**し、テストで逐語に留める
  （Kataribe `failures.md` #104 — 一文の増減で 0.36 動く。変えたら測り直す）。この文面を読むのは Jev で
  サーヴァントのモデルではないので、Spec 35 の二言語化の対象外（1 言語のまま）

### D5. 関連度の基準

基準 = **そのターンの受信本文（`incoming.content`）の先頭 2,000 字**。MCP のツールには理由欄が無い
（`ReasonState::Unsupported`）ので、呼び出しごとの意図は取れない。

`rag` は理由欄を持つ（Spec 27）。**理由（中央 19 字・1 論点）を基準にしたほうが副論点の沈みが減るかは
未測定** — P0 で同じ標本に対して対で測り、差が出たら `rag` だけ理由を基準にする（未決 2）。

### D6. 閾値

`0.1 / 0.2 / 0.3 / 0.5` の離散 4 値。**既定 0.2**（実測で副論点の段落が 0.24〜0.46 に居たため、
0.3 以上は既定にしない）。集合に無い値は既定へ落とす（`theme` / 表示倍率と同じ）。
画面のラベルは数値ではなく「控えめ / 標準 / 強め / 最大」+ 説明 1 行（強いほど、依頼の 2 つ目以降の
論点に答える段落が先に落ちる）。

**全部落ちたら圧縮しない**（`outcome=all_dropped`）。残す段落が 0 になる採点は、依頼と結果が
噛み合っていないか採点の失敗で、どちらでも全文を返すほうが害が小さい。

### D7. 落としたことを本文に書く / 戻る道（未決 1）

圧縮した本文の形（ja。en は Spec 35 の規律で対に書く）:

```text
【関連度で段落を省略しています: 全 48 段落・9,388 字のうち 21 段落・3,926 字を省略。
 省略した段落は `omitted` に id と段落番号を渡すと逐語で読めます。id=P2】

（残した段落 1）

［… 段落 8〜14・7 段落・1,204 字を省略 …］

（残した段落 15）
```

戻る道の案（**推奨は A**）:

- **A. 合成ツール `omitted { id, from, to }`** — ターンの中だけ生きる生の本文の置き場
  （`CallRunner` が持つ `Vec<String>`。id は `P1`・`P2`…）から、段落番号の範囲を逐語で返す。
  1 回 20,000 字まで（`room_log` と同じ）。寿命はターン（ツール結果が 1 ターン限りなのと同じ）。
  メモリだけで、ログにも `sessions.redb` にも書かない。提示は「圧縮が ON で、その個体が `prunable` な
  ツールを 1 本以上持つとき」だけ = 静的（チェックを切り替えた 1 回だけ入力キャッシュが書き直しになる）
- B. 戻る道を作らず、印だけ書く — モデルの唯一の手が同じツールの呼び直しになり、また圧縮された
  本文が返って RepeatGuard に当たる。採らない

`omitted` の出力は `prunable` ではない（圧縮しない）。

### D8. 失敗と打ち切り — 全文を通す

- Jev の呼び出しは**全体で 20 秒**まで。超えたら全文（`outcome=timeout`）
- HTTP の失敗・402・解釈できない応答は全文（`outcome=failed`）。再試行は 429 / 5xx に 1 回だけ
- **待ちはターンの打ち切り（Spec 10）で切れる**（`select!` で `turn.token` を見る）。切れたら全文を
  返して、ターンの側の打ち切り処理へ渡す
- 一部の呼び出しだけ失敗したら、その呼び出しの段落は残す（`None` = 残す）

Jev は検証器ではないので fail-open でよい（eigent の採点器の教訓とは向きが逆 — あちらは
「壊れたら合格」が害で、こちらは「壊れたら圧縮しない」= 今日の挙動へ戻るだけ）。

### D9. 設定と置き場

| もの | 置き場 | 理由 |
|---|---|---|
| Account ID / 圧縮の ON・OFF / 閾値 | `{app_data_dir}/jev.json` | `mcp_server.json` / `pricing.json` と同じ第 3 の棚。**村を配ったとき、受け取った人の村が、知らない送信先へツール結果を送る状態を作らない** |
| API トークン | OS の資格情報ストア（`SecretStore`。鍵 `jev_api_token`） | モデルの API キーと同じ扱い。値を返す IPC は作らない（「設定済み」だけ返す） |

`jev.json` が読めないときは書き込みを拒む（`mcp_server.json` と同じ。既定値の書き戻しで設定を消さない）。

画面: **システム設定 ＞ 外部連携 ＞ Jev**（「MCP サーバー」の下）。Account ID / API トークン（書くだけ）/
「接続を確かめる」（2 段落の採点を 1 回投げて、モデルの版と遅延を出す）/ **「ツール結果を Jev で
圧縮する」のチェック** / 閾値 / 送るものの説明（D10）。チェックはキーが揃うまで `disabled`。
反映は押した時点（MCP サーバーのページと同じ）。

IPC は `get_jev_settings` / `set_jev_settings` / `set_jev_token` / `clear_jev_token` / `test_jev` の 5 本。
投影は持たない（読むのはこのページだけ）ので生の `ipc` でよい。

### D10. 外へ送るもの（PRIVACY）

圧縮が ON のあいだ、対象のツールが 4,000 字以上を返すたびに、**そのターンの依頼文の先頭 2,000 字**と
**ツールが返した本文**が Cloudflare（Workers AI。モデルの提供元は TypeSafe AI）へ送られる。
`rag` の本文は利用者が宣言したフォルダの中身で、MCP の本文は接続先が返したもの（記憶・メール・
社内文書を返す MCP を繋いでいればそれも含む）。ページの説明文と PRIVACY 日英の「4. 外部へ送信される情報」に
この 2 つを名指しで書く。既定 OFF・キーが無ければ送信経路ごと無い。

### D11. 計器（件数だけ。本文は 1 字も出さない）

```text
tool prune: agent=… name=… outcome=ok|structured|all_dropped|timeout|failed|cancelled
            raw_chars=… kept_chars=… paragraphs=… dropped=… calls=… jev_tokens=… ms=… threshold=0.2
tool omitted: agent=… id=P2 from=8 to=14 chars=1204 outcome=ok|not_found|too_large
```

`tool prune:` は圧縮を**試みた**呼び出しでだけ出す（4,000 字未満・対象外・OFF では 1 行も増えない）。
`tool:` 行の `body_chars` は今までどおり「モデルへ返した本文」= 圧縮後。`tool omitted:` の回数が、
落としすぎの実測になる（多ければ閾値が強すぎる）。

Jev のトークンは `TurnSpend` にも予算にも載せない（単価が入力 $0.042/MTok で、実測 15 万トークンが
$0.0064。村の天井は実効トークン建てで、桁が 2 つ下の別の課金を混ぜると数字の意味が割れる）。
`jev_tokens=` をログに出すので、払った量は `fuseforks.log` から読める（#103 の形にしない）。

## Notes

1. **採らなかった置き場**（CLAUDE.md の判定表が正）: 履歴の間引きは、キャッシュ済み 0.1 倍の履歴の
   前方一致をターンごとに切るので、90% 以上落とさないと損。ツールの絞り込みは tools + system =
   18,897 トークンの最上流を毎ターン変える。`run` の実行前の判定は `decide`（argv の決定的な照合）の
   逆向きで、Jev は公式に敵対的入力に弱い
2. **攻撃面**: MCP が取ってきたページは他人が書いた文で、「他の段落は無関係」と書いた段落が同じ
   呼び出しの採点を動かす可能性がある（未測定）。起きるのは「要る段落が落ちる」で、落ちた事実は
   印に残り `omitted` で読める。**これは安全の境界ではない**（封筒の無害化とは別の層）
3. **個体ごとの切り替えは作らない**（裁定 3）。要るようになったら `AgentSpec` に 1 欄足す形で足せる
   （`usesBlackboard` と同じ）。今その欄を作らないのは、空の欄が「何を入れるべきか」を問い続けるため
4. 統計画面の `≈ $` に Jev の費用は入らない。リリースノートの「知っておいてほしいこと」に書く
5. **sqz の教訓**（2026-08-25）: 圧縮された `sed` の出力に元ファイルに無い空行が入り、それを写した
   編集が「文字列が見つからない」で落ちた。本 Spec は (a) 編集の材料になる `file` を対象外にし
   (b) 残す部分を逐語に保ち (c) 省略を印で名指しする、の 3 つでこの形を避ける
