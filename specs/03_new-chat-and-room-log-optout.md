## Goal

会話の文脈コスト（履歴 + 広場ログ）を利用者が制御できるようにする。

1. **新規チャット** — 会話ログと全エージェントの履歴を、エージェントを
   止めずにリセットする。話題を切り替えるたびに古い文脈へ課金し続けない
2. **広場ログのオプトアウト** — エージェント別に「自分の発言と自分宛ての
   発話だけを受け取る」設定。場の共有が要らない役（単機能の作業役など）から
   毎ターン最大 12 件 × 200 字の固定費を外す

いずれも Spec 02 と同じ設計思想（トークンコストの徹底管理が差別化軸）の
続きで、対象が「ツールのスキーマ」から「会話の文脈」へ移っただけである。

---

## 現状の構造（接地）

- **履歴**: `AgentRecord.history`（直近 `history_turns` = 8 往復）。
  プロセス寿命に閉じ、消す手段は**エージェントの再起動だけ**
  （`start_agent` が履歴をクリアする）
- **会話ログ**: `Shared.log`（上限 5,000 件）。UI の会話ペインと
  広場ログの原料。消す手段が無い
- **広場ログ**: `compose_room_log` が「自分が送り手でも受け手でもない
  エージェント発の発話」を全エージェントのプロンプトへ毎ターン注入する
  （`room_log_window` = 12 件 × `room_log_excerpt_chars` = 200 字）。
  エージェント別の制御は無い

## Stories

### P1: 新規チャット（会話のリセット）

> 利用者として、話題を切り替えるときに会話を白紙へ戻す。なぜなら古い
> 文脈（履歴・広場ログ）は次の話題に不要で、載せ続けるだけ課金されるから。

**仕様**

- 会話ペインのヘッダに「新規チャット」ボタン。**確認ダイアログ必須** —
  会話ログは現状メモリ内のみで永続化が無く、リセットは復元不能
- コア: `Orchestrator::reset_conversation()` を新設。処理順を固定する:
  **1. `Shared.log` クリア → 2. 全 `history` クリア →
  3. `ConversationCleared` 発行 → 4. フロントが `messages` を空へ**
  （`messages` は `Shared.log` の投影。イベント順を固定することで
  テストの観測点が安定する）。トーストで完了を明示
- **消すのは `Shared.log` と `AgentRecord.history` の 2 つだけ。**
  稼働状態・累積統計（トークン・稼働時間）・Memory.md・
  **エージェント別 MCP の接続（Spec 02 の per-agent map）**はすべて維持 —
  リセットするのは「会話」であって「エージェント」ではない。
  `AgentRecord` ごとクリアしてはいけない（MCP 接続や統計を巻き添えにする）
- **処理中のターンとの競合（案 A で確定）**: リセットは即時だが、
  飛行中のターンの**完了書き込みは許容する**。ペインは一瞬空になり、
  その後、飛行中だった発話 1 件が載るのは仕様 — 発話は起きた事実であり、
  ログに残す（hop 打ち切りが「記録してから打ち切る」のと同じ規律）。
  世代管理（旧 generation の書き込み破棄）は採らない — 白紙化は意図表明で
  あり、ミリ秒の競合に機構を足す価値が無い

**Acceptance**

- Given 会話が積まれた状態、When 新規チャット、Then 会話ペインが空になり、
  次の発話のプロンプトに旧履歴・旧広場ログが含まれない
- Given 稼働中のエージェント、When 新規チャット、Then 稼働状態は変わらず
  （再起動しない）、累積トークン・稼働時間も変わらない
- Given リセット後、When エージェントに発話、Then 正常に応答する
  （コールドスタートとして）
- Given 処理中のターンがある状態でリセット、When 飛行中ターンが完了、
  Then その完了 1 件は**ログに載る**（案 A。破棄しない）

### P2: 広場ログのオプトアウト

> 利用者として、場の共有が要らないエージェントには自分宛ての発話だけを
> 渡す。なぜなら広場ログは毎ターン最大 12 件 × 200 字の固定費で、
> 単機能の作業役には価値が無いから。

**仕様**

- `AgentSpec.hearsRoomLog: bool` を追加（serde default = **true**、
  旧データ・新規作成とも現状互換）
- `false` のエージェントは `compose_room_log` をスキップする。
  履歴（自エージェントが送受信したもの）の注入は従来どおり行う —
  変わるのは広場ログの有無だけ
- **受信側だけの設定**である: `false` にしても、そのエージェントの発話は
  従来どおり他のエージェントの広場ログに載る（これはプライバシー機能では
  なくコスト機能。発話は公共のまま、聞く量だけを絞る）
- UI: 設定ダイアログに**「会話の文脈」セクション**を新設し、そこへ
  チェックボックス「広場の会話が聞こえる」を置く（Spec 02 で増えた
  「道具」系の欄と混ぜない）。外すときの注記「他のエージェント同士の
  会話を文脈として使えなくなります（トークンは減ります）」

**Acceptance**

- Given `hearsRoomLog: false`、When 他エージェント同士の会話がある状態で
  発話処理、Then プロンプトに「この場で交わされていた会話」節が入らない
- Given 同状態、When 別の `true` のエージェントが発話処理、Then そちらの
  広場ログには `false` のエージェントの発話も**載る**（受信側だけの設定）
- Given 旧 world.json（フィールド不在）、Then true として読める（現状互換）

## Notes（査読論点）

1. **hearsRoomLog の既定は true（現状互換）**: トークン思想に忠実なら
   false 既定だが、「場を共有する村」という製品の性格の既定を変えるのは
   別の議論。enabledTools と同じく互換側に倒した
2. **エージェント個別の履歴リセットは作らない**: トグル（再起動）で既に
   できる。全体リセット（新規チャット）だけを足す
3. **リセットの復元不能性**: 会話ログの永続化自体が未実装なので、
   リセット以前に「アプリ終了でも消える」。将来ログ永続化（セッション
   保存）を作るなら、新規チャット = セッション切り替えへ再設計する余地
4. **処理中ターンとの競合を守らない**判断（仕様に明記）: 白紙化は意図表明
   であり、組み立て済みプロンプトのミリ秒競合に同期機構を足す価値が無い
5. **命名**: `hearsRoomLog`（聞こえる）。`roomLogEnabled` 等の機械的な名も
   あるが、広場ログの説明文（「聞こえていた発言」）と語彙を揃えた
