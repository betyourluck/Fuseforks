## Goal

毎リクエストのプロンプトに載る「基礎料金」を、エージェントごとに必要な分だけへ絞る。

1. **同梱ツールの提示制御** — エージェント設定で同梱ツールを個別に ON/OFF。
   あわせて、作業フォルダ未設定ならファイル系 5 本を**自動で提示から外す**
2. **エージェント別 MCP** — `agents/{id}/mcp.json` にそのエージェント専用の
   MCP サーバーを書ける。**共通の `{workspace}/mcp.json` は現状のまま残し、
   全員に提示され続ける**（上書き可能な加算モデル。後述）

### 設計思想（この製品の差別化軸）

トークンコストの徹底管理を、大手オーケストレーションとの差にする。
個人用ツールは 1 人の財布で全エージェントが動く — 「全員に全能力」は
機能ではなく浪費であり、**必要な道具だけを持たせる**のが既定であるべき。
（実測: ツール定義 + 転送ツール + 広場ログ + 履歴で、挨拶 1 回の下限が
3,000〜6,000 tok まで育っていた）

## ツール収集の最終形（アーキテクチャの確定）

`handle_message` がモデルへ提示するツール集合は、次の順で組む:

```text
1. 転送・委譲ツール（transfer_to_* / ask_*。トポロジー由来、本 Spec の対象外）
2. 共有 registry のツール
   a. 同梱 6 本 …… enabledTools と work_dir 連動でフィルタ（P1）
   b. 共通 MCP 由来 …… フィルタなし（全員に提示）
3. 個別 MCP 由来（orchestrator が持つ per-agent map。P2）
   …… `{server}__{tool}` が 2b と同名なら**個別が勝つ**（上書き可能な加算）
```

- 実行解決も同順の逆引き: `execute_tool` は**個別 map を先に**引き、
  無ければ共有 registry を引く
- 「registry は共有のまま」の射程は 2（同梱 + 共通 MCP の置き場）だけ。
  個別 MCP は registry に**入れない** — 入れると全員から見え、共通 MCP の
  再接続（全入れ替え）とも衝突する
- 同名衝突が起きるのは server 名まで同じ場合のみ。これは「共通と同じ
  サーバーを、自分専用の接続先（別 DB 等）で置き換えたい」という正当な
  使い方であり、意図的な上書き手段として明記する

## Stories

### P1: 同梱ツールの提示制御

> 利用者として、雑談役のエージェントにファイル系ツールを持たせない。
> なぜなら使わないツールのスキーマに毎ターン課金されるから。

**仕様**

- `AgentSpec.enabledTools: string[] | null` を追加
  - `null`（既定・旧データ）= 全同梱ツールを提示（従来互換）
  - 配列 = 列挙した同梱ツールだけを提示（`[]` なら同梱ツール無し）
  - 対象は同梱 6 本のみ。MCP 由来・転送・委譲はこのリストの対象外
- **null と明示配列の意味の差**（新しい同梱ツールが増えたとき）:
  - `null` = 「既定に従う」— 7 本目が増えれば自動で提示される
  - 明示配列 = 「必要な道具だけ」— 7 本目は**増えない**。それが明示の意味
- **新規作成時の保存値は `null`**。UI のチェックボックスが全 ON に見えるのは
  「null の効果の表示」であって、明示配列 6 本を保存するのではない。
  利用者がチェックを 1 つでも触った時点で明示配列へ切り替わる。
  「既定に戻す」ボタンで null へ戻せる
- **作業フォルダ未設定なら、ファイル系 5 本（grep / fd / diff / sd / yq）は
  enabledTools に関わらず提示しない**（使えないツールを見せない）
  - UI: 作業フォルダ未設定の間、ファイル系のチェックボックスは
    **disabled + 「作業フォルダが未設定のため提示されません」の注記**。
    チェック状態自体は保持し、作業フォルダを設定すれば効き始める
    （「設定したのに効かない」を UI で見せる）
- 提示されないツールをモデルが名指しで呼んだ場合は、既存の
  「そういうツールはありません」経路に落ちる（新設不要）
- **remember を OFF にしても Memory.md の注入は続く**（書きのみ不可）。
  注入 OFF のオプションは作らない — Memory.md を空にすれば注入は消える
  ので制御手段は既にあり、機構を重ねると「どちらで消えているのか」が
  分からなくなる。この割り切りは README にも明文化する

**Acceptance**

- Given `enabledTools: ["remember"]`、When 発話処理、Then バックエンドが
  受け取る同梱ツールは remember だけ
- Given `enabledTools: null` + 作業フォルダ設定済み、Then 6 本すべて提示
  （従来互換）
- Given `enabledTools: null` + 作業フォルダ未設定、Then remember だけ提示
- Given `enabledTools: []`、Then 作業フォルダの有無に関わらず同梱 0 本
- Given `enabledTools: ["grep"]` + 作業フォルダ未設定、Then 同梱 0 本
  （自動除外が明示より優先）
- Given 旧 world.json（フィールド不在）、Then null として読める
- MCP 由来ツールの提示は enabledTools の影響を受けない

### P2: エージェント別 MCP（`agents/{id}/mcp.json`）

> 利用者として、エージェントごとに専用の MCP サーバー（例: 個体別の
> 記憶 DB）を繋ぐ。なぜなら同じサーバーでも接続先が違えば、全員に同じ
> ものを渡すのは誤りだから。

**仕様**

- 置き場: `{workspace}/agents/{agent_id}/mcp.json`。形式は共通 mcp.json と
  同じ（Claude Desktop の `mcpServers` 形式）。無ければ空集合
- 提示・実行は「ツール収集の最終形」のとおり（共通 + 個別、同名は個別優先）
- **接続の寿命はエージェントの稼働に一致させる**: 個別サーバーは
  `start_agent` で接続し、`stop_agent` で切断する（共通サーバーは
  従来どおりアプリ寿命）
- **プロセス管理は agent_id 紐付け**: 個別接続は
  `HashMap<AgentId, McpManager>` で保持し、`stop_agent` は**自分の
  エントリだけ**を畳む。複数エージェントが同じコマンドのサーバーを持つ
  場合も**プロセスは共有しない**（それぞれ spawn）— 接続先が違いうる
  ことが個別 MCP の動機そのものであり、共有すると動機が壊れる
- 個別接続の失敗はエージェントの起動を**止めない**（共通と同じ規律）

**失敗の二分類**（エラー定義。Phase 0 で凍結する）

| 分類 | いつ起きる | どう扱う |
|---|---|---|
| (1) JSON パース失敗 | 保存時 | **保存を拒否**しエラー表示（ディスク上のファイルは常に正しい JSON か不在）。共通 McpDialog と同じ流儀 |
| (1') 外部編集でパース失敗 | 起動時の読み込み | 起動は止めず、「個別 MCP の読み込み失敗」として接続状態に残す。個別ツール 0 本で稼働 |
| (2) MCP 接続失敗 | 起動時・再接続時 | 起動は止めず、サーバー単位の接続エラーとして接続状態に残す（共通と同じ） |

- 編集 UI: 設定ダイアログの設定ファイルタブに `mcp.json` を追加
  （`ConfigFileKind::Mcp`）。保存経路（write_config）が Mcp kind のとき
  JSON パースを検証し、失敗なら保存拒否（分類 1）
- 保存時、そのエージェントが**稼働中なら**個別接続を張り直す。
  停止中なら何もしない（次回起動で反映。停止中の保存は検証のみ）
- **接続状態の可視性**: 個別 MCP の状態（サーバー名 / connected /
  error / ツール名）は orchestrator の per-agent map に**プロセス寿命で**
  保持し、IPC で読める。設定ダイアログに状態表示を置く。停止中は
  「停止中（未接続）」と表示する。**状態は永続化しない** — 状態ファイルは
  プロセスが消えても「接続済み」を残して嘘をつく。World の同期純データ
  原則も守る（map は AgentRecord に入れず orchestrator 側）

**Acceptance**

- Given エージェント A の mcp.json にサーバー宣言、When A を起動して発話、
  Then A には共通 + 個別のツールが提示され、個別ツールが実行できる
- Given 同条件、When B（個別設定なし）が発話、Then B には共通のツール
  だけが提示され、A の個別ツール名を呼んでも「ありません」になる
- Given A を停止、Then A の個別サーバーの子プロセスが終了する
  （共通サーバーと、同じコマンドを使う B の個別サーバーは生きている）
- Given 壊れた JSON を mcp.json タブで保存、Then 保存が拒否され
  ディスクは変わらない（分類 1）
- Given 外部編集で壊れた個別 mcp.json、When A を起動、Then 起動は成功し、
  読み込み失敗が接続状態から読める（分類 1'）。共通ツールは使える
- Given 起動しないコマンドのサーバー宣言、When A を起動、Then 起動は
  成功し、サーバー単位の接続エラーが接続状態から読める（分類 2）
- Given 共通と個別に同名 `{server}__{tool}`、Then A では個別が実行される

## Notes

### rev2 で確定した設計判断

1. **新規作成時の保存値は null**（UI の全 ON は null の効果の表示）。
   「新規は remember のみ」の思想純化案は、初見で道具が無くて動かない
   体験になるため不採用。明示配列に触った後も「既定に戻す」で null へ
   戻れるので、思想側へ倒したい利用者の道は残る
2. **自動除外（work_dir 未設定 → ファイル系非提示）は明示より優先**。
   UI は disabled + 注記で「効かない設定」を見せる
3. **remember OFF = 書きのみ不可、Memory.md 注入は継続**で割り切る
   （注入の制御手段は「ファイルを空にする」として既に存在する）
4. **個別 MCP の接続状態は永続化しない**（プロセス寿命の map + IPC）。
   停止中の試験接続（保存時に一度繋いで結果だけ見せる）は将来の余地
5. 転送・委譲ツールの絞り込みは対象外（接続トポロジーの編集で足りる）
