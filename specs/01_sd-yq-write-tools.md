**Branch**: なし（main へ Phase 単位で直接コミット。ただし Phase 0 は本 Spec の

---

## Goal

同梱ツールに初の**書き換え系** 2 本を足す。

- `sd` — 正規表現によるファイル内置換（構造を知らないテキスト置換）
- `yq` — TOML / YAML / JSON の**構造を保った**値の取得・設定・削除

どちらも読み取り系（grep / fd / diff）と同じ作業フォルダ境界に閉じ、
**書き込みは必ず差分（unified diff）として会話に残る**ことを契約とする。

---

## 背景と動機

- コーディング用エージェントの編集依頼で「ファイル全文を読ませて全文を
  書き戻させる」のはトークン的に最悪の経路。置換・構造編集を 1 呼び出しで
  済ませられれば、grep / fd と同じ理由（トークン節約 = 最重要課題）で効く。
- 設定ファイル（TOML / YAML）を LLM に全文書き換えさせると**コメントが消え、
  キー順が壊れる**事故が定番。構造編集ツールを経由させればコメントと
  フォーマットを保持したまま値だけ変えられる。
- 読み取り 3 本と違い、書き込みは被害クラスを「漏洩」から「**改竄**」へ広げる。
  本 Spec の過半は機能ではなく**安全境界の設計**である。

### 依存の接地（2026-07-29 調査）

| 用途 | crate | 判定 |
|---|---|---|
| sd の置換 | `regex`（**既存依存**） | 新規依存ゼロ。sd 本体も内部は regex crate |
| yq: TOML | `toml_edit` 0.25 | 累計 6.9 億 DL、cargo 本体が使用。コメント・フォーマット完全保持のデファクト |
| yq: YAML | `yaml-edit` 0.2.3 | rowan ベースの lossless 構文木。`set()` / `remove()` / `set_path()` あり。2026-07 更新で現役だが **0.2 系と若い**（リスク、Phase 4 参照） |
| yq: JSON | `serde_json` + `preserve_order`（既存依存 + feature） | キー順保持。JSON にコメントは無いので lossless 論点なし。**整形は正規化される**（P2 Acceptance に明記） |
| 差分表示 | `similar`（既存依存） | diff ツールと共用 |

serde_yaml は 2024 年に開発終了・アーカイブ済み。fork 群（serde_yml /
serde_norway 等）はコメントを保持しないため、導入動機を満たさない。

## 安全境界（本 Spec の核）

1. **二段階実行**（書き込み op のみ。`yq get` 等の読み取り op は対象外）:
   既定は preview — 適用結果の unified diff を返すだけで**書かない**。
   `apply: true` を明示したときだけ書き込み、そのときも**適用した diff を
   「適用済み」の明示とともに応答に含める**。黙って書く経路は存在しない。
   - 根拠: ツール結果はモデルと会話ログの両方に残る。「何が変わったか」が
     ログから追えない書き込みは、api_key_env の教訓（failures.md #1）と
     同型の「見えない変化」になる。
2. **境界の上限共有**: 書き込み先も `resolve_in_work_dir`（canonicalize +
   前方一致、symlink 不追従）を通す。**読める範囲を超えて書き込み範囲を
   広げることはない**。ツールごとに範囲を**さらに絞る**ことは許す
   （yq の拡張子制限がこれ。data_contract には
   `additional_restriction: extension` として明記する）。
3. **diff 上限は「切り詰め」ではなく「拒否」**: 適用結果の diff が
   12,000 字を超える書き込みは、**preview / apply を問わず実行しない**。
   代わりに変更統計（置換件数・変更行数）と「対象を絞ってください」を返す。
   - 根拠: 切り詰めた diff を許すと「何が変わったかが会話に残る」契約が
     崩れる。上限を超える書き込みは**そもそも起こせない**形にすることで、
     契約と上限を両立させる。読み取り系の「切り詰めて明示」とは
     ここが意図的に異なる（data_contract に例外として定義する）。
4. **入力上限の共有**: 1 ファイル 2 MiB・バイナリ拒否は読み取り系と同じ。
5. **対象は 1 呼び出し 1 ファイル**: 複数ファイル一括置換は v1 では
   提供しない。インジェクション 1 発での改竄範囲を 1 ファイルに閉じる。
   横断置換したければモデルが grep → 1 ファイルずつ sd を回せばよく、
   その形なら各ステップが diff としてログに残る。
6. **新規ファイル作成はしない**: 既存ファイルの編集のみ。
   `resolve_in_work_dir` は canonicalize（実在パスのみ成功）を通るため
   構造的にも新規作成は不可能だが、加えて `is_file()` を検査し
   ディレクトリ指定も拒否する（Acceptance に落とす）。

### 検査の順序（エラーメッセージを安定させる）

sd / yq とも、必ずこの順で検査し、最初に失敗した段の文言だけを返す:

1. 境界解決（`resolve_in_work_dir`: 実在 + 囲い内）
2. `is_file()`（ディレクトリ・特殊ファイル拒否）
3. 拡張子（**yq のみ**: `.toml` / `.yaml` / `.yml` / `.json` 以外は拒否。
   推測でパースしない）
4. サイズ上限（2 MiB）
5. バイナリ判定（先頭 4 KiB の NUL）
6. 内容の解釈（sd: 正規表現コンパイル / yq: パース）

## Stories

### P1: sd — 正規表現置換

> エージェントとして、ファイル内の一致箇所を正規表現で置換できる。
> なぜなら全文読み → 全文書き戻しはトークンの浪費で、書き間違いの
> 混入面も広いから。

**ツール定義**

- name: `sd`
- 引数:
  - `path`（必須）: 対象ファイルの相対パス
  - `pattern`（必須）: Rust regex 構文
  - `replacement`（必須）: 置換文字列。`$1` `$name` のキャプチャ参照可。
    **リテラルの `$` は `$$` と書く**（regex crate の仕様どおり。説明文に明記）
  - `apply`（省略時 false）: false = preview（diff のみ返す）、true = 書き込み
  - `case_insensitive`（省略時 false）: grep と同じ既定。
    パターン内のインラインフラグ（`(?i)` `(?-i)`）は**パターン側が優先**
    （regex crate の仕様どおり。grep も同じ挙動であり、実挙動を文書化する）
- 戻り: 置換件数 + unified diff（preview / apply とも同形式。apply 時は
  「適用済み」の明示を添える）。一致 0 件なら「一致なし」を返し書かない。

**Acceptance**

- Given 作業フォルダ内のテキストファイル、When `apply` 省略で呼ぶ、
  Then ファイルは**変更されず** diff と件数が返る
- Given 同条件、When `apply: true`、Then ファイルが置換され、返り値の
  diff が実際の変更と一致する
- Given `../` や symlink 経由の外部パス、When 呼ぶ、Then 内容に触れず拒否
  （読み取り系と同文言）
- Given ディレクトリを `path` に指定、Then 拒否（書き込み系はファイルのみ）
- Given 不正な正規表現、Then 読める文字列でエラーが返る（Err にしない）
- Given 置換で内容が変わらない（一致はあるが同文）、Then 「変更なし」を
  返し書かない（無意味な mtime 更新をしない）
- Given diff が 12,000 字を超える置換、When preview / apply いずれでも、
  Then 書き込まず、変更統計と「対象を絞る」案内を返す
- Given `replacement` に `$$`、Then リテラル `$` として置換される

### P2: yq — 構造を保った設定編集

> エージェントとして、TOML / YAML / JSON の特定の値だけを
> 取得・設定・削除できる。なぜなら全文書き換えはコメントとキー順を
> 破壊し、利用者のファイルを劣化させるから。

**ツール定義**

- name: `yq`
- 引数:
  - `path`（必須）: 対象ファイルの相対パス。形式は**拡張子で判定**
    （検査順序 3 のとおり。それ以外は拒否）
  - `op`（必須）: `get` | `set` | `remove`
  - `key`（必須）: `a.b[0].c` 形式のパス。**フル yq 式は受けない**
    （説明文に明記。名前は認知のために yq を借りるが、機能は path 演算のみ）。
    v1 のキーは `[A-Za-z0-9_-]+` とインデックス `[数字]` のみ。
    クォートされたキー（`a."b.c"` 等、ドットや記号を含むキー名）は
    v1 非対応として読める文言で拒否する
  - `value`（set 時必須）: **JSON リテラルとして解釈**する文字列
    （`"text"` / `42` / `true` / `null`）
  - `apply`（set / remove のみ。省略時 false）: sd と同じ二段階
- **set の対称規則（型破壊の禁止）**: v1 の set は
  「**既存のスカラー値を、スカラー値で置き換える**」操作に限る。
  - 置換先がコンテナ（テーブル / マップ / 配列）→ 拒否
    （`a.b[0]` が配列要素のスカラーなら可、要素がテーブルなら不可）
  - 置換先が JSON に写像できない型（TOML / YAML の日時等）→ 拒否
    （黙って文字列化すると型が壊れ、Goal の「構造を保つ」が嘘になる）
  - `value` にも配列・オブジェクトは不可（対称）
  - 既存の中間キーが無いパスへの set → 拒否（静かに新構造を生やさない）
  - スカラー同士の型変化（数値 → 文字列等）は**許す** — 値の修正として正当な
    ケースが多く、diff に型の変化が見える形で残る
- 戻り:
  - `get`: 値（存在しなければ「無い」と返す。パスの綴り違いを推測しない。
    JSON に写像できない型は文字列表現で返し、その旨を添える）
  - `set` / `remove`: unified diff（sd と同形式。apply 時は「適用済み」明示、
    diff 12,000 字超は安全境界 3 のとおり拒否）
- コメント・キー順・インデントの保持:
  - TOML: 完全保持（toml_edit）
  - YAML: 保持（yaml-edit）。anchor / alias を含むファイルは
    round-trip を保証できないため**編集を拒否**する（get は可）
  - JSON: キー順は保持、**整形（インデント・改行）は正規化される**

**Acceptance**

- Given コメント付き TOML、When `set` を apply、Then 対象の値だけが変わり
  **コメントと他行のフォーマットが 1 字も変わらない**（diff が対象行のみ）
- Given コメント付き YAML、同上
- Given JSON、When `set`、Then キー順は保持される。**整形の正規化により
  diff が対象行以外に及ぶことは許容**（契約どおりであり、バグではない）
- Given 既に同じ値である `set`、When preview / apply いずれでも、
  Then 「変更なし」を返し**書かない**（sd と同じ規則。フォーマッタ由来の
  空白差分を発生させない）
- Given 存在しないキーへの `get`、Then 「無い」という読める応答（Err にしない）
- Given 存在しない中間キーを含むパスへの `set`、Then 拒否
- Given テーブル / 配列そのものへの `set`、Then 型破壊として拒否
- Given TOML の日時型の値への `set`、Then v1 非対応として拒否
  （`get` は文字列表現 + 型の注記を返す）
- Given `set` の `value` に JSON として不正な文字列、Then 読める拒否
- Given anchor 入り YAML への `set` / `remove`、Then 「保証できないため拒否」
- Given 対応外拡張子、Then 拒否（検査順序 3。パースより先）
- Given ディレクトリを `path` に指定、Then 拒否

## Notes

### rev2 で確定した設計判断（rev1 査読論点の裁定）

1. **preview 既定は維持**: 2 呼び出しのコストより「黙って書かない」を優先。
   査読でも異議なし。運用で毎回 apply 二度打ちが常態化したら再考する。
2. **名前は `yq` を維持**: 認知を借りる利得を取り、フル yq 式の誤用は
   説明文の明記（path 演算のみ）とパース拒否の読める文言で受ける。
3. **value はスカラー限定で確定**: set の対称規則として本文へ昇格
   （置換先も value もスカラー。型破壊は拒否、スカラー間の型変化は許す）。
4. **yaml-edit は Phase 4 に隔離のまま維持**: PoC 関門 + 縮退経路つき。
5. **中間キーの自動生成はしない、で確定**: 誤ったパスへの set が静かに
   新構造を生やすのは事故の形。

### rev1 → rev2 の査読反映記録（2026-07-29 査読）

- Must-1: 「読める範囲 = 書ける範囲」を「読める範囲を超えて広げない +
  ツール側の追加制限は許す」へ修正（安全境界 2）
- Must-2: diff 12,000 字超は preview / apply とも**拒否**に確定（安全境界 3。

  yq set/remove の戻りに「適用済み」明示を追加
