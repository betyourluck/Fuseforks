## 実機の指摘で分類を改稿（2026-08-03、P4 の後）

利用者が実機で触っての指摘: 「**あまりにも砕けすぎていて逆にわかりづらい**。
システム設定なので Concordia のテイストとは別にシステム用語でいい」。

**真因は分類の切り口**だった。初版は 村の設定 / この画面の設定 =
**保存先（`world.json` か `localStorage` か）で切っており**、実装の都合が
そのまま目録に出ていた。設定画面の目録は主題で切るのが標準で、保存先は
利用者から見れば「配ると付いて回るかどうか」の 1 点しか意味を持たない。

| 旧 | 新 |
|---|---|
| 村の設定（グループ） | **全般**（言語） |
|  | **コスト管理**（トークン制限） |
| この画面の設定（グループ） | **ユーザーインターフェース**（メッセージ表示/非表示） |
| トークン天井 | **トークン制限（実効トークン）** |
| 天井あり / 天井なし | **制限あり / 制限なし** |
| 線削除の確認（項目） | **メッセージ表示/非表示** の中の「接続（線）の削除」の節 |

- **「標準設定」は採らず「全般」にした**（利用者が受け入れ）。日本語のソフトで
  標準設定は「既定値／初期設定に戻す」と読まれやすく、General の訳は
  macOS が「一般」、Windows が「全般」
- **用語境界を 1 つ足した**: UI ラベル = トークン制限、内部の台帳・コード・
  ログ = 天井 / ceiling。CLAUDE.md の「外向け=グラウンディング / 内部=接地」と
  同型の二例目で、`CoreError::InvalidTokenBudget` の `#[error]` は利用者に
  見えるので制限側で書く。ページ本文の「村」「サーヴァント」は**残す** —
  それは世界の説明であって分類名ではない
- **保存先は分類から降ろし、各ページ末尾の注記へ**（村に保存＝配ると付いて回る /
  端末に保存＝村の設定には含まれない）。分類から消しただけだと、
  言語を村ごと配ってしまう驚きが説明されないまま残る
- **「メッセージ表示/非表示」は節を足せば増える器**にした（利用者に他の候補が
  ある）。ただし**機構は今も線の削除 1 つだけ** — 器が広いことと機構が広いことは
  別で、1 つ足すたびに機構 5 の検討（便利さと安全のどちらかを機械が決められない）
  が要る
- 既定の表示ページは目録の先頭（全般 → 言語）へ

## 査読への反論 2 点

### 反論 1: ホットリロード用の IPC は要らない（指摘 1 の前提）

> 「`world.json` は従来起動時に読むファイルです。`次の依頼から`効かせるには、
> ホットリロード用の IPC が P1 で必須になります」

**`world.json` は所有者ではなく投影である。** 所有者はメモリ上の `World` で、
天井は**依頼のたびに**そこから読まれる:

- `new_root_budget`（[orchestrator.rs:2230](../crates/agent-core/src/orchestrator.rs)）が
  `shared.world.read().await.token_budget()` を読む
- 呼ばれるのは**ユーザー発話の宛先ごと**（同 1896）と**予定の発火ごと**（同 2180）

これは `schedules.json` と同じ形（`data_contract` の「予定の所有者は in-memory で
ファイルは投影」）で、既存の `upsert_template` / `create_agent` の IPC が
すでにこの経路を使っている（メモリを変えてからファイルへ書き戻す）。
`set_token_budget` は `World` に**既にある**（[world.rs:236](../crates/agent-core/src/world.rs)）。

したがって P1 は「メモリを変えて保存する IPC 1 本」で足り、**次の依頼から効く**。
再起動は要らないし、ホットリロードという別機構も要らない。

**ただし WARN の指摘は正しい。** 天井なしの警告は `bootstrap` でしか出ない
（同 681）ので、「画面で無しにする → WARN は次回起動まで出ない」は即時反映の
原則に反する。処方は WARN を増やすことではなく、**天井なしの状態を設定画面が
その場で表示すること**（R1）。

### 反論 2: 天井の型は `Option<u64>` で正しい（指摘 3 の前提）

> 「`×0.1` が入ると実効値は整数になりません。`u64` にそのまま入らない」

**重みは内部の milli 表現に閉じており、天井は実効トークンの整数である。**

- `WEIGHT_CACHED_MILLI: u64 = 100`（= ×0.1）、`WEIGHT_OUTPUT_MILLI = 4000`
  （[budget.rs:16-21](../crates/agent-core/src/budget.rs)）
- 内部の蓄積は `ceiling_milli: u64`、外へ出すときは
  `effective_milli().div_ceil(1000)` で**切り上げて整数**へ戻す（同 43-48）
- CLAUDE.md にも凍結済み: 「内部は milli 建て AtomicU64・切り上げ
  （Atomic に浮動小数は無い）」

`f64` へ倒す必要は無い。浮動小数を持ち込むと、`AtomicU64` で回している
`try_reserve` / `debit` の機構ごと作り直しになる。

> 「0 を禁止するなら『無し』をどう表現するかも `Option` で解決と言っているが、
> UI で 0 入力を弾くバリデーションが必要」

**0 の正規化はコアに既にある。** `World::from_persisted` が `Some(0)` を
`None` へ倒し、`token budget: tokenBudget=0 は不正値のため天井なしとして扱います`
と 1 行出す（[world.rs:195](../crates/agent-core/src/world.rs)）。
UI 側の入力検査は**二重化**であって新規要件ではない（それでも P1 で入れる —
「保存したのに黙って別の値になる」を画面に作らないため）。

**ただし D1 は未決のまま残す。** 「画面に出すのは実効値か素の値か」は型の話とは
別で、そこは指摘が正しい。

## Goal

**いま何が設定できるのかを、画面から分かるようにする。**

起点は利用者の言葉（2026-08-03）: 「トークンの天井の設定や、UI の設定、あと
多言語化したいので言語などあると、**僕もなにが設定できるのか分かりやすい**」。

### この Spec の立場（正直に書く — rev2 で修正）

この企画には「**設定が少なくて分かりやすい**」という軸があり、設定ダイアログは
その軸と正面から衝突しうる。立場をここで固定する:

> **主目的は、既にある設定を可視化すること。新しいつまみは原則作らない。
> ただし本 Spec は新規の設定を 2 つ足す — 言語（S3）と、線削除の確認（S4）。**

rev1 は「S4 は設定の追加ではない」と書いていたが、**これは虚偽だった**。
確認の有無は新しい boolean であり、設定項目数は純増する。言語も同様に新規である。
数えると: 可視化 1（天井）+ 新規 2（言語・確認）。

新規 2 つを許容する理由は、どちらも**設定を持たない実装が成立しない**ため:

- 言語: 訳を持つなら、どれを出すかの選択は必ずどこかに要る
- 確認: 「常に出す」と「常に出さない」のどちらも利用者の言葉に反する
  （「1 回クリックで消すのは便利ですが」「たまに間違えてクリックしてしまい消して
  しまいます」— 便利さと安全のどちらかを機械が決められない）

**`OrchestratorConfig` は引き続き出さない**（機構 2）。ここが「増やさない」の本体。

## Stories

### S1: トークンの天井を画面から設定する

村の天井（Spec 11）を画面で見て、変えられる。いまは `world.json` を手で開いて
`tokenBudget` を書き換えるしかない。**天井の無い村は起動のたびに WARN が出るのに、
直す場所が画面に無い。**

### S2: 何が設定できるかが一目で分かる（rev2 で書き直し）

rev1 の「表示の設定を 1 箇所で見る」は、D3（集めないほうがよい）と衝突していた。
**S2 の本体は「集めること」ではなく「見えること」**である。
2 ペインの左メニューが**設定できるものの目録そのもの**になる — これが Goal に
直結する（利用者の「なにが設定できるのか分かりやすい」）。

### S3: 言語を選ぶ

日本語以外で使えるようにする。**訳す対象は 3 層あり、層ごとに判断が違う**。

### S4: 消す操作を間違えない

村の地図で線をクリックすると接続が消える。**1 回のクリックで消える**ため、
誤って触ると接続が失われる（利用者の実体験、2026-08-03）。

## 機構の要点（Phase 0 で凍結する）

1. **設定の置き場は 2 つ。**
   - **村の設定**（天井・**言語**）→ `world.json`。村を配れば設定も付いて回る
   - **この画面の設定**（線削除の確認）→ `localStorage`
   **言語を `world.json` へ置くのは rev2 の変更**（指摘 2）。System 行
   （入退室・打ち切り・予算切れ・要約）は**会話ログに保存される**ので、
   言語は村の共有物に触る。ペイン幅と同じ棚には置けない
2. **`OrchestratorConfig` は画面へ出さない。** 間違えると村が壊れる種類の値で、
   正しい値は実測でしか決まらない（#41 の較正）。出すなら別 Spec で 1 つずつ
3. **天井は「無し」を選べる。** `Option<u64>`（実効トークンの整数）をそのまま
   映す。0 は入力段で弾く（コアの正規化との二重化）。
   **天井なしの村では、その状態を設定画面がその場で赤く示す** — 起動 WARN を
   待たせない（rev2。指摘 1 の後半）。
   **表示単位は実効トークンで固定**（rev3 の D1 決定）。文言も凍結する:
   - ラベル: `トークン天井（実効トークン）`
   - ヘルプ: `未キャッシュ×1 + キャッシュ済み×0.1 + 出力×4 を合算した値。`
     `内部では milli 単位で管理し、表示は切り上げた整数です`
   **素のトークンは参考値としても出さない** — 打ち切り判定に使われるのは実効値で、
   素の値を並べると「まだ余裕があるのに切られた」という誤った読みを作る。
   しかも入力の内訳（未キャッシュ／キャッシュ済み）が画面に無いので、
   素の値から実効値は逆算できない
4. **言語の選択肢は `日本語` / `English` の 2 つだけ。** `自動` は選択肢に**出さない** —
   初回起動時に OS の言語を見て、どちらかに**確定して `world.json` へ保存**する
   （rev2。指摘 5）
5. **確認の有無は地図の線の削除だけ**（上の棚卸しが根拠）。**既定は ON**
   （rev3 で確定。この決定はここ 1 箇所にだけ置く — rev2 は Notes 側に同じ論点を
   「未決」として重複させていた）。根拠 3 つ:
   (a) 破壊的操作の既定は安全側。棚卸しで**他 6 種はすべて確認あり**、線だけ無いのは
       整合性の破れ (b) 誤クリックによる消失の実害報告がある (c) OFF にしたい人は
       1 回切れば済むが、**ON を知らずに失うと復旧できない**（接続は元に戻せない）
6. **保存したら次の依頼から効く。再起動を要求しない。**（rev2 で定義し直し）
   - 天井・言語は**メモリ上の `World` を変えてから `world.json` へ書き戻す**。
     天井は依頼ごとに読まれるので次の依頼から効く（反論 1）
   - **再起動しないと効かない設定は載せない。** 載せるなら、その旨をその項目に書く
   - OS 再起動を要する設定は**そもそも作らない**
7. **入口はタイトルバーの「スケジュール」の右**、COG アイコン + 「システム設定」
   （利用者指示）
8. **アイコン規約**（rev3 で置き換え）: **UI の恒久要素のアイコンは SVG で描く。
   絵文字を使わない。**
   理由 3 つ: (a) 絵文字は**フォント依存**で、環境ごとに字形も大きさも変わる
   (b) `currentColor` を継承しないので、**テーマの配色に追従しない**
   （`text-fail` を当てても色が変わらない） (c) 大きさが行の高さに引きずられ、
   38px のヘッダで他のアイコンと揃わない。
   **システム設定は COG（歯車）を使ってよい** — カードの設定ボタンは鉛筆の SVG へ
   変更済みで（2026-08-03、利用者）、歯車は空いている。
   rev2 の「`⚙` は個別設定に予約」は**前提ごと消滅した**。
9. **画面は 2 ペイン**（利用者指示）: 左にメニュー、右にページ。Kataribe と同型。
   **左メニューが「設定できるものの目録」になる**ことが S2 の実体

## 検証の設計（実装の前に決める）

- **天井**: 変えて保存 → `world.json` が変わり、**再起動せずに次の依頼から**
  新しい天井が効く（結合テスト: 保存 → 依頼 → `BudgetPool` の天井が新しい値）
- **天井なし**: 選んだ時点で設定画面がその状態を示す（起動を待たない）。
  併せて再起動で従来どおり起動 WARN が出ること（**起動ログを見る**。rev2、指摘 7）
- **言語**: 切り替えで UI の文言が変わり、**システムプロンプトは変わらない**
  （`system_digest` が切り替えの前後で同一 — 機械的に押さえる）
- **言語の保存先**: `world.json` に入り、`localStorage` には**入らない**
- **線の削除**: 設定 ON で確認が出る／OFF で出ない
- **触らず閉じたら書き換わらない**: `world.json` の**内容とタイムスタンプ**、
  および `localStorage` の両方（rev2、指摘 7）
- 0 を入力したら保存前に弾かれること（コアの正規化に到達しない）

## Phases

- **P0 契約凍結**: `data_contract.yaml` へ `settings_contract`
  （置き場の 2 分割・出す設定と出さない設定の線・言語の 3 層・アイコン規約・
  即時反映の定義）
- **P1 村の設定**: 天井の読み書き（IPC 2 本 + `SettingsDialog.vue` の骨格 =
  2 ペインと左メニュー）。**ここだけで独立して価値がある**
- **P2 表示の設定**: 線削除の確認（S4）。`askConfirm` は Spec 12 P3 の機構を使う
- **P3 多言語化 (1) UI 文言**: 辞書の形を決めて差し替え
- **P4 多言語化 (2) コアの文言**: **案 A 固定** — コアは日本語のまま返し、
  UI が `ErrorPayload.code` で引いて訳す。**コアは言語を知らない**
- **P5 台帳と実機確認**

## Notes（残る未決）

- **D1 決定: 実効トークンの整数**（rev3。文言ごと機構 3 へ凍結）。
  素のトークンは参考値としても出さない
- **D2 決定: エージェント別の天井は作らない**。Spec 11 は因果に掛ける設計で、
  個体別ではない
- **D4 決定: 日本語・英語の 2 つで始める**。README が日英 2 本あるので訳の水準は
  既にある
- **D5 決定: 案 A（コアは言語を知らない）**。理由は 2 つ —
  (a) コアが `localStorage` も言語も知らない設計を保てる
  (b) `ErrorPayload.code` という**既に安定した機械可読キー**がある
  **残る問題**: System 行は**訳す前の文字列が会話ログへ保存される**ので、
  言語を切り替えると過去の行と混ざる。案 A でも案 B でも起きる。
  **rev2 の判断: 混ざるのを許容する**（過去の記録は起きた当時の言語で残るのが
  正しい。遡って訳し直すと、書き出した JSONL と画面が食い違う）
- **D6 削除**（rev3）。同じ決定を機構 5 と Notes の 2 箇所に置いており、
  片方が「未決」のまま残っていた。**決定は機構 5 の 1 箇所だけに置く**
- **D8 決定: COG（歯車）を SVG で描く**（rev3）。カードの設定ボタンが鉛筆へ
  変わったので歯車は空いた。詳細な形は P1 の実装

**残る未決: なし。** P0 の契約凍結から着手できる。

## 起票中に見つかった追従漏れ（本 Spec の外・P1 で直す）

アイコンを絵文字から SVG へ替えた際に、**それを指す文言が追従していない**。

- `AgentList.vue:190`（**利用者に見える文言**）:
  `モデルテンプレートが未登録です。⚙ から先に 1 件登録してください。`
  → 同ファイル 139 行のボタンは既に SVG で、`title` は「モデルテンプレートを管理」。
  **画面のどこにも `⚙` は無い**ので、この案内は行き先を示せていない
- `App.vue:7` / `AgentSettingsDialog.vue:3`（コメント）: 「カードの ⚙ から開く」
  → 実体は鉛筆の SVG

**一般化**: 絵文字を SVG へ替える作業は、**その絵文字を本文で参照している箇所を
道連れにする**。絵は差し替えたがテキストは別ファイルにあるので目に入らない
（`mandate_removal_requires_ledger_grep` と同じ機序の、UI 版）。
機構 8 を入れる以上、`⚙` で grep して回収するのが本 Spec の仕事に含まれる。
