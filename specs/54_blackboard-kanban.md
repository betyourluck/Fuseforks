## Goal

1. **付箋 1 枚が仕事 1 つになり、仕事の状態をフォルダで宣言する** —
   `blackboard/<状態>/<表示名> - <仕事名>.md`。状態を変えるのは `file move` 1 回
2. **黒板タブは状態ごとの列になる**（KANBAN）。前日の「持ち主の手番」（動いている / あなたの手番 /
   手が離れている）は列から降りて**バッジ**になる — 宣言（仕事の状態）と観測（持ち主の状態）を
   1 つの列に混ぜない
3. **既存の付箋は壊れない** — `blackboard/` 直下の平置きは「状態なし」列に出る。`まとめ.md` は
   直下のまま、列の外で最上部に固定

**やらないこと（範囲外）**: GUI からのドラッグで状態を動かす（D2。頻度を見てから別 Spec）/
付箋の本文に状態を書く（1 行目方式は採らない）/ 2 段より深いフォルダ / 仕事名の禁止文字を
機械で検査する（D1）/ 列の横並び（D5）/ `fd` に深さの引数を足す（D1 の残余）/
条例の書き換え（利用者の資産。Notes 1 に改訂案）。

## 起票時の実測（2026-09-17。コードと条例を読んだ）

- **読み手は 1 段も潜らない。** `blackboard.rs:125` の `read_blackboard_dir` は `is_file()` で
  ないエントリを `continue` で飛ばす。**フォルダ方式は読み手の改修が必須**（ファイル名方式でも
  区切りの parse が要るので、コード量は同程度）
- **`file move` は宛先の親フォルダを作る。** `tools/file.rs` の `run_transfer` が
  `resolve_creatable` → `create_dir_all(parent)` → `rename`。サーヴァントは `mkdir` を打たずに
  `blackboard/done/ザリ - X.md` へ移せる。`write` も同じく親を作る（Spec 09 の実機で
  `docs/` 未作成のまま書けた）
- **`file move` は宛先が既にあれば `overwrite: true` 無しで拒否する**（`run_transfer` の
  `dest.exists() && !overwrite` の門。`rename` の OS 差はこの門の後ろなので Windows / Unix で
  挙動は割れない）。**同名を上書きして重複を消してしまう経路は元から無い**（rev2 で査読の
  指摘を反証した点 — Notes 6 の A6）
- **`fd` は再帰し、深さの引数を持たない**（`fs.rs` の `FdTool` の schema は `pattern` /
  `path` / `case_insensitive` の 3 つ。飛ばすのは隠しフォルダと `SKIP_DIRS` 6 つ）。
  条例の「着手時に fd で `blackboard/` を一覧」は状態フォルダがあってもそのまま成立するが、
  **GUI が読まない深さのファイルも `fd` には出る**（D1 の残余）
- **持ち主の同定はファイル名の完全一致**（`blackboardLanes.ts:72` の `ownerNameOf` = `.md` を
  落とした文字列と `AgentSnapshot.name`）。仕事名を足すなら区切りが要る
- **GUI の削除は `is_safe_note_name` が `/` `\` `..` `.` 先頭を弾く**（`blackboard.rs:59`。
  単体 `only_flat_note_names_are_accepted` が `..` / `../world.json` / `sub/note.md` を
  拒否側で固定している）。フォルダを 1 段足すと、`name` に区切りを入れる形では**削除の関門を
  緩めることになる**。状態は `name` と別の欄で運ぶ（D4）
- **畳みの鍵は `dir:name`**（`useBlackboardCollapse.ts:29`）。同じ `name` が 2 つの状態に
  並ぶと鍵が衝突する（D4）
- **前日の一括削除は IPC を足さずにフロントが 1 枚ずつ回している**（`BlackboardPane.vue` の
  `clearReleased` — `delete_blackboard_note` のループ・途中で失敗したら止めて読み直す）。
  `done` 列の一括もこの形をそのまま使う（D5）
- **条例は「1 人 1 ファイル」「着手時に write で見出しだけにして古い内容を消す」**
  （`{workspace}/Ordinance.md` 19〜26 行）。コードは 1 人 1 ファイルを縛っていない
  （CLAUDE.md の材料で確認済み）
- **`BLACKBOARD_DIR` は言語に依存しない名前**（2026-08-05 利用者判断で `黒板/` → `blackboard/`）。
  状態フォルダの名前も同じ規律で決める（D1）
- **`.gitignore` は `blackboard/`** なので、サブフォルダも追跡されない

## Design

### D1. 書き場所 = `blackboard/<状態>/<表示名> - <仕事名>.md`（裁定 1・2）

**状態フォルダは閉じた 5 つ。名前は言語に依存しない英字**（`blackboard` と同じ規律。
条例が名指しし、GUI は辞書で訳す）。**表の並びが画面の列の並び**（D5）:

| 順 | フォルダ | 列の表示（ja / en） | WHITEBOARD の対応 |
|---|---|---|---|
| 1 | `doing` | 進行中 / In progress | 進行中 |
| 2 | `needs-you` | あなたの判断待ち / Needs you | あなたの判断待ち |
| 3 | `waiting` | エージェント待ち / Waiting on an agent | エージェント待ち |
| 4 | `on-hold` | 保留 / On hold | 保留 |
| 5 | `done` | 完了 / Done | 完了 |

- **直下の平置きは「状態なし」列**（`unfiled`。既存の `<表示名>.md` がそのまま出る。列は付箋が
  あるときだけ出す。**`まとめ.md` はこの列に入らない** — 列の外で最上部固定・D4）。
  **5 つ以外のフォルダは「その他」列**へ落とす — **フォルダごとに 1 列**、見出しは
  「その他: `<フォルダ名>`」（`foo/` と `bar/` があれば列が 2 本。閉じた列挙から外れた名前を
  黙って混ぜず、フォルダ名で名指しする）。**2 段目より深いファイルは読まない**（今と同じ
  「無視」。`blackboard/done/2026/x.md` は出ない）
- **残余: `fd` には深いファイルも出る。** `fd` に深さの引数は無く（起票時の実測）、本 Spec で
  足すと同梱ツールの schema が動いて全員の毎ターンに乗る。**条例で「状態フォルダの中に
  フォルダを作らない」と 1 行書いて受ける**（Notes 1）。破られたときの形は「`fd` に出るが
  黒板タブには出ない付箋」で、実機で出たら読み手を 2 段へ広げるかを別に決める
- **ファイル名は `<表示名> - <仕事名>.md`。区切りは最初の ` - `（半角空白 + ハイフン + 半角空白）。
  仕事名の中に ` - ` があってもよい**（2 つ目以降は仕事名の一部）。区切りが無ければ全体が
  表示名（今の形 = 仕事名なし）。**表示名に ` - ` を含む個体は持ち主が引けなくなる** —
  表示名は個体の設定であって条例の射程外なので、条例には書かない（今も同じ約束）
- **仕事名の禁止文字は機械で検査しない。** Windows で使えない文字（`\ / : * ? " < > |`）は
  OS が `write` を拒み、`file` ツールがその文言を返すので**失敗は沈黙しない**。条例に
  1 行書く（Notes 1）。macOS / Linux で書いた `:` 入りの名前を Windows で開く形は範囲外
- **`まとめ.md` は直下のまま**（状態を持たない。進行役が束ねる唯一のファイル）
- **状態の変更は `file move`**（`blackboard/doing/X.md` → `blackboard/done/X.md`）。中身に
  触れないので append の履歴が保たれる。**宛先に同名が既にあれば move は拒否される**
  （既存の門。`overwrite: true` を付ければ上書きできるが、条例で付けないと書く — Notes 1）。
  **move ではなく write で別の状態に同名を作ると同じ仕事が 2 つの状態に並ぶ** — D4 のバッジで
  名指しする。拒否された move も同じ形を残すので、同じバッジが両方を拾う

### D2. 誰が動かすか = サーヴァントの `file move` だけ（裁定 3）

- **本 Spec で足す IPC は無い。変えるのは既存の `delete_blackboard_note` の引数 1 つだけ**
  （D4 — `state` を省略可で足す。`tests/ipc_contract.rs` を追従する）。**「GUI から状態を書く
  経路を作らない」が本 Spec の線** — 契約の凍結「GUI から内容を書く経路は作らない」は不変で、
  削除は前日までと同じく「内容を書く操作ではない」側
- **GUI のドラッグは別 Spec。** フォルダ方式なら「ドラッグ = move」で内容に触れないので、
  凍結と衝突せずに足せる。足すときの形は `move_blackboard_note(dir, from_state, name, to_state)`
  1 本で、`to_state` は D1 の 5 値に閉じる。**「状態なし」と「その他」へは落とせない**
  （閉じた列挙の外へ GUI から動かす経路を作らない。そこへ動かすのは `file move` だけ）。
  **実機で「手で動かしたい」が出てから**

### D3. 持ち主の手番はバッジへ降ろす

- `classifyNote`（`blackboardLanes.ts`）の判定は**そのまま残す**。返る `lane`（active / yourTurn /
  released）と `reason` を列ではなく**付箋の見出し行のバッジ 1 つ**にする。**バッジの文言は
  `lane` ではなく内訳で出す** — `yourTurn` →「あなたの手番」/ `active` →「動いている」/
  `released` → `reason` の 5 つ（孤児 2 種 / 失敗で停止 / 停止中 / 起動中・待機。**前日の辞書
  `blackboard.reason.*` をそのまま使う**）。「手が離れている」という文言は列ごと消える
- 読めるようになる形: 「状態は `doing` なのに持ち主は停止中」= サーヴァントが move し忘れた付箋。
  「状態は `waiting` なのに持ち主は動いている」= 待ちが解けたのに動かしていない付箋。
  **宣言と観測の食い違いを人が拾える**のが、列を宣言に譲った理由
- **`yourTurn` > `active` > `released` の優先は「どのバッジを出すか」の優先であって、
  列の中の並びには使わない**（1 枚の付箋に付くバッジは 1 つ。持ち主が typing 中かつ波が
  pending なら「あなたの手番」）。列の中の並びは D4
- **直下の `まとめ.md` は `classifyNote` に掛けない**（今と同じ `SUMMARY_NOTE` の特別扱い。
  バッジ無し・列の外）。**`state` の中の `まとめ.md` は普通の付箋**として掛ける（凍結 8）

### D4. ワイヤと関門

- `BlackboardNote` に **`state: Option<String>`** を足す（`None` = 直下。フォルダ名そのもの。
  serde は `skip_serializing_if = None` で既存の形を保つ）。`name` は**ファイル名のまま**
  （フォルダを含めない）
- **`delete_blackboard_note(dir, name, state?)`** — `state` は省略可（`None` = 直下）。
  **空文字は `None` と同じに扱う**（フロントが `undefined` を空文字で送る形を拒否にしない）。
  `is_safe_note_name` を **`state` と `name` の両方に別々に掛ける**（どちらも平置きの 1 成分
  でなければ**拒否 = `BlackboardDeleteFailed` を返す**。落ちるのではない）。`..` / `/` / `\` /
  先頭 `.` は既存の述語がそのまま弾く。関門を 2 段にすることで `name` に区切りを入れる経路を
  開けない。`clear_blackboard` は直下と 1 段目の全フォルダを消す（`まとめ.md` も含む =
  今と同じ「全部」）
- **読みと削除は同じ列挙**（`blackboard_dirs` の 1 実装）— 不変
- **並び**: コアは `まとめ.md`（直下）→ 直下の平置き（`name` 順）→ `state` の**文字列順** →
  その中で `name` 順で返す（**安定な並びのためで、意味は持たせない**）。**列の並びはフロントが
  D1 の表の順に固定**（`doing → needs-you → waiting → on-hold → done`、その後に「状態なし」
  「その他: …」）。**コアの返却順と画面の列順は別のもの** — コアに列順を持たせると 5 値の
  順序がコアと辞書の 2 箇所に住む
- **列の中の並び**: 孤児（`orphanUnknown` / `orphanMoved`）を先頭へ寄せ、残りはコアの
  `name` 順のまま。**バッジの種類では並べ替えない**（D3）
- **畳みの鍵は `dir:state/name`**（`state` 無しは `dir:name` のまま = 既存の保存値を壊さない）。
  **`file move` で状態が変わると鍵も変わり、畳んでいた付箋は開く。これは意図した挙動** —
  状態が動いた付箋は人が見るべきもので、鍵を `dir:name` にすると重複（同名が 2 状態）で
  片方を畳むと両方が畳まれる
- **重複の検出はフロントの派生**: 同じ `dir` で**同じ `name`（表示名 + 仕事名の全体）**が
  2 つ以上の `state` に並んだら両方に「重複」バッジ（D3 のバッジとは別枠で 2 つ目）。
  `ザリ - A.md` と `ザリ - B.md` は別の仕事なので重複ではない。コアは数えない
  （数える場所を 2 つにしない）

### D5. 列は縦に積む（横並びにしない）

- 中央下段は仕切りで 80px まで縮む帯で、5 列 + 状態なし + その他を横に並べる幅が無い。
  **前日の 3 列と同じ「見出し + 付箋の束」を縦に積む**形で、見出しが列。並びは D1 の表の順
- **5 つの列は付箋が 0 枚でも出す**（前日の裁定「最初に何もないときにチラッとカテゴリが
  見える」を引き継ぐ）。「状態なし」と「その他: …」は付箋があるときだけ出す。
  `まとめ.md` は列の上、最上部に固定（今と同じ）
- **一括の消し口は `done` 列にだけ付く**（「完了を全部消す」。確認あり・枚数入り）。
  **新しい IPC は足さない** — 前日の `clearReleased` と同じく、フロントが `done` 列の一覧を
  `delete_blackboard_note(dir, name, "done")` で 1 枚ずつ回し、途中で失敗したら残りは消さずに
  止めて読み直す。`clear_blackboard`（全部）はこの列の消し口には使わない。前日の
  「手が離れている」列の消し口はその列ごと無くなる。孤児は個別のごみ箱で消す
  （バッジで名指しされているので迷わない）

### D6. 条例は利用者の資産 — 改訂案を渡す

コードは条例を読まない。**条例の名前とコードの名前は必ず一致させる**（`BLACKBOARD_DIR` の
doc と同じ規律）ので、D1 のフォルダ名 5 つは契約に凍結し、条例案（Notes 1）に同じ綴りで書く。

## 契約への凍結（P0 で `data_contract.yaml` の `blackboard_contract` へ）

1. 付箋の置き場は `blackboard/<state>/<表示名> - <仕事名>.md`。`state` は
   `doing | needs-you | waiting | on-hold | done` の閉じた 5 値。直下の平置きは「状態なし」、
   5 値の外のフォルダは**フォルダごとに**「その他: `<名>`」の列。2 段目より深くは読まない
2. **状態の変更は `file move` であって write ではない**。GUI が状態を書く経路は本 Spec では
   作らない（本 Spec で新設する IPC は無い）
3. `BlackboardNote.state: Option<String>`（フォルダ名そのもの・`None` = 直下）。`name` は
   ファイル名だけでフォルダを含めない。ファイル名の区切りは**最初の** ` - ` で、仕事名の中の
   ` - ` は仕事名の一部
4. `delete_blackboard_note` の `state` と `name` は**別々に** `is_safe_note_name` を通す。
   どちらか 1 つでも区切りを含めば拒否。`state` の空文字は `None`
5. 列は `state` から決まり、持ち主の手番（typing / status / 波 / workDir）は**バッジ**
   （1 枚に 1 つ。優先は yourTurn > active > released の内訳）。付箋にもワイヤにも持ち主の
   状態の欄は足さない（前日の凍結を引き継ぐ）。列の中の並びはバッジで変えない（孤児を
   先頭へ寄せるだけ）
6. **コアの返却順は `まとめ.md` → 直下 → `state` の文字列順 → `name` 順。画面の列順は
   凍結 1 の表の順で、フロントが持つ**
7. 同じ `dir` で同じ `name` が複数の `state` に並んだら**両方にバッジ**（フロントの派生。コアは
   数えない）
8. 一括の消し口は `done` 列にだけ（`delete_blackboard_note` を 1 枚ずつ）。`clear_blackboard` は
   全部（直下 + 1 段目）
9. **直下の `まとめ.md` は列の外・最上部固定・バッジ無し**（`classifyNote` に掛けない）。
   `state` の中の `まとめ.md` は普通の付箋として扱う（持ち主「まとめ」= 孤児バッジ。
   特別扱いを 2 箇所にしない）
10. 畳みの鍵は `dir:state/name`（`state` 無しは `dir:name`）。move で状態が変わった付箋は開く

## Notes

### 1. 条例の改訂案（利用者へ渡す。適用は利用者）

「### 付箋 `blackboard/<自分の表示名>.md` — append で育てる」の節を次に置き換える:

```text
### 付箋 `blackboard/<状態>/<自分の表示名> - <仕事名>.md` — 1 仕事 1 ファイル、append で育てる
- 黒板は作業フォルダの `blackboard/` フォルダ。村のみんなで共有する作業メモで、各自の長期記憶（Memory）とは別物。
- 付箋は仕事 1 つに 1 枚。書いてよいのは自分の名前の付箋だけ。他人の付箋には書かない。
- 状態はフォルダで表す。5 つだけ: `doing`（進行中）/ `needs-you`（管理人の判断待ち）/ `waiting`（他のサーヴァント待ち）/ `on-hold`（保留）/ `done`（完了）。状態フォルダの中にフォルダを作らない。
- 新しい仕事に着手したら `blackboard/doing/<自分の表示名> - <仕事名>.md` を `file` の write で作る（見出しは仕事の名前）。以後は append で足す。
- ファイル名の ` - `（空白・ハイフン・空白）は最初の 1 つが表示名と仕事名の区切り。仕事名の中に ` - ` があってもよい。
- 状態が変わったら `file` の move でフォルダを移す（例: `blackboard/doing/ザリ - 調査.md` → `blackboard/done/ザリ - 調査.md`）。move に `overwrite` を付けない。移せなかったら（同じ名前が既にある）人に報告する。write で別のフォルダに同じ名前を作らない。
- 仕事名にはファイル名に使えない文字を入れない（`\ / : * ? " < > |`）。
- 書くのは途中経過・気づき・次に渡す人への引き継ぎのメモだけ。頼まれた仕事の答えは付箋ではなく返信で返す。
- 読むのは着手時に 1 回。新しいタスクを受け取った直後に fd で `blackboard/` を一覧し、自分の付箋と関係する付箋だけ read する。同じタスクの進行中は読み直さない。関係ないメモは束ねに入れない。
- 依頼を配った進行役だけが `blackboard/まとめ.md` を write で束ねる。
- 終わった仕事の付箋は `done/` に残す。消すのは管理人。
- 管理人からの指示や即時対応が要るメッセージでは、黒板の確認を飛ばして直接対応する。
```

変えた点は 5 つ — 1 人 1 ファイルを 1 仕事 1 ファイルへ / 「着手時に write で見出しだけにして
古い内容を消す」を「`doing/` に新しい付箋を作る」へ / 状態変更 = move の 1 行（`overwrite` を
付けない・拒否されたら報告） / 区切りと禁止文字の 2 行 / 入れ子の禁止。
**文言は保証ではない**（#84）ので、効いたかは P4 の 1 と 2 で読む。

### 2. 前日の 3 列は捨てずに役割を変える

`classifyNote` の判定は 1 行も変えない。変わるのは返り値の使い方（列 → バッジ）だけ。
前日の凍結「付箋にもワイヤにも持ち主の状態の欄は足さない」はそのまま生きる。
**`released` 列の一括消し口だけが消える**（`done` 列へ移る）。バッジの文言は
`blackboard.reason.*` の 5 鍵をそのまま使い、「手が離れている」という語は画面から消える。

### 3. ファイル名方式を採らなかった理由（2026-09-17 の裁定の根拠）

- 状態の集合が構造で閉じる（フォルダ名 = 列挙。parse 不要）
- 仕事名に ` - ` が入っても状態は壊れない（区切りは表示名と仕事名の間の最初の 1 つ）
- Windows の禁止文字の問題が仕事名だけに縮む
- 同じ仕事が 2 つの状態に並ぶ事故の検出が `name` の一致だけで済む
- 既存の平置きが「状態なし」としてそのまま読める
- 人が Explorer で見ても列になる

### 4. 状態フォルダを英字にした理由

`BLACKBOARD_DIR` を `黒板/` から `blackboard/` へ改名したのと同じ（2026-08-05 利用者判断 —
言語に依存しない名前）。英語の村でも同じ条例の綴りで動く。表示は辞書が訳す。
**`まとめ.md` だけが日本語のまま残る**のは既存の約束で、本 Spec では触らない。

### 5. 開いたままの観察

- `needs-you` と Spec 43 の窓（`PlanWaveState === "pending"`）は同じ「人の手番」を 2 つの
  機構で表す。窓は機構、フォルダはサーヴァントの申告。**食い違いはバッジで読める**が、
  どちらかに寄せる判断は実機の頻度を見てから
- サーヴァントが move し忘れた付箋（`doing` のまま持ち主が停止）がどれくらい出るかは未測定。
  多ければ「停止時に `doing` を `on-hold` へ自動で移す」機構の材料になるが、それは
  **GUI でもコアでも内容に触らない move** なので凍結とは衝突しない
- `fd` に出るが黒板タブに出ない付箋（2 段目より深い）は、条例の入れ子禁止が破られたときだけ
  出る。頻度を見て読み手を 2 段へ広げるか決める
