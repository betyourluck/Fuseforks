## 覆す判断

1. **Spec 73 の「再添付は利用者の発話の添付だけ」**（`attachment_contract` 凍結 S73-5 の「利用者の発話以外の ID →
   `InvalidAttachment`」と、会話ペインの「入力欄へ」の表示条件）。生成した画像の写しはサーヴァントの返事の発話に付く（D5）ので、
   この制限のままでは次のターンの参照に渡せない。~~**送り手を問わず、消えていない添付なら渡し直せる**ようにする~~ → **利用者とサーヴァントの発話の、消えていない添付なら渡し直せる**ようにする（D3。P1 で閉じた許容 `User | Agent` にした — システムと外部クライアントの発話は添付を持たず、将来持つ送り手が増えても既定で渡せない側に倒すため。P2 で画面も同じ集合へ）。
   制限の理由は「添付を持つのは利用者の発話だけ」という当時の事実で（Spec 73 の 50 行目）、方針ではなかった
2. **`attachment_contract` の「画像の添付は WebP」**（rev3。P0 の実測を見た利用者裁定 2026-11-16 —「JPEG を加える」）。
   サーヴァントの返事の発話に付く生成画像の写しに限り、画像の添付に JPEG を加える。**利用者が貼る画像は今も WebP だけ**。
   rev2 は「可逆 WebP で段を踏んで縮め、1024px でも収まらないときだけ JPEG」としていたが、P0 で (a) 2K の写実の画像は
   1024px まで縮めて 1.96MB（上限まで 4.5%）で、理屈の上でも 1024px では必ずは収まらない（段の最後に JPEG の実装が要る）
   (b) 元が JPEG の画像は可逆 WebP にすると元より大きくなる（Gemini 951KB → 1.68MB）、が分かった。写しは
   `tool_image::normalize`（Spec 70）と同じ 1 実装にする（D5 の 2）

## Goal

1. 利用者がシステム設定で画像生成 API（プロバイダ・モデル・鍵）を 1 つ選ぶと、`image` にチェックを付けた
   サーヴァントが画像を生成できる
2. 利用者がそのターンに添付した画像と、そのターンに生成した画像を、参照画像として渡せる。過去の画像は
   「入力欄へ」で渡し直せる
3. 生成した画像は会話ペインに出て、作業フォルダにファイルとして残り、生成したサーヴァント自身も見られる
4. 設定していない村・チェックを付けていない個体の挙動は 1 バイトも変わらない（ツールの提示・プロンプト・ログ）
5. 画像生成は費用がかかり外へ送るので、**アプリの更新だけでは誰にも生えない**。1 ターンの枚数に上限がある
6. 外へ送るものが増えることを PRIVACY に書く

## 現況（実測 2026-11-16）

### Lorekeel（Kataribe）のワイヤ

- HTTP はすべて Rust 側（reqwest）から出す（`image_gen.rs`・2,095 行）。プロバイダは 5 つ:
  - **OpenAI**（既定 `gpt-image-1-mini`）— 参照なしは `POST /v1/images/generations`（JSON）、参照ありは
    `POST /v1/images/edits`（multipart の `image[]`）。Bearer。画像は `data[0].b64_json`。使用量は `usage.input_tokens / output_tokens`
  - **Gemini**（既定 `gemini-3.1-flash-lite-image`）— `POST /v1beta/models/{model}:generateContent`。`x-goog-api-key`。
    `parts = [inlineData × N, text]`（画像が先）+ `responseModalities: [IMAGE, TEXT]` + `imageConfig {aspectRatio, imageSize}`。
    画像は `candidates[0].content.parts[].inlineData`。**断っても 200 で中身が空**（`promptFeedback.blockReason` /
    `finishReason != STOP` で見分ける）
  - **Meta**（既定 `muse-image-1.0`）— `POST https://api.meta.ai/v1/responses` の `tools: [{type: image_generation, output_format: webp, size}]`、
    参照は `input_image { image_url: data URL }`、`store: false`。画像は `output[]` の `image_generation_call.result`。
    **`size` は縦横比しか決めず、`quality` と `aspect_ratio` は黙って無視される**（解像度を選べない）。
    **P0: `1024x1024` を頼んでも 1600² が返る**
  - **xAI**（既定 `grok-imagine-image-2.0`）— generations / edits の 2 口、どちらも JSON。参照は
    `images: [{type: image_url, url: data URL}]`。画像は `data[0].b64_json`（**P0: 1k は JPEG、2k は PNG** — 形式は解像度で
    変わる）。費用は `usage.cost_in_usd_ticks` だけ（単位 1e-10 USD。参照ありの edits は 1k low で $0.05 と、生成の $0.04 より高い）。
    **拒否は応答の `data[0].respect_moderation: false` で読む**（`decode_xai`。コメントは「SDK が『モデレーションで隠された』と
    扱う欄（docs）。通常の応答には欄自体が無い・断られた形は未観測」）
  - **ComfyUI** — ローカルのワークフロー JSON の置換とポーリング（本 Spec の範囲外。D11）
- **接続確認は社ごとの GET**（`probe`。タイムアウト 20 秒。画像は作らない）— OpenAI `GET {base}/v1/models` /
  Gemini `GET {base}/v1beta/models/{model}` / Meta `GET {base}/v1/models/{model}` / xAI `GET {base}/v1/image-generation-models/{model}`。
  どれも鍵で認証する。2xx で成功、Gemini・Meta・xAI の 404 は「モデルが見つかりません」
- 画像の形は「縦横比 3 値（正方形 / 横長 / 縦長）× 解像度 3 段」の 1 軸を持ち、各社の欄へ写す。1 回 1 枚
- 参照画像は全社 3 枚まで。Lorekeel 自身の上限は 1 枚 8MB・1 回の合計 12MB（参照の出所が利用者の手元のファイルなので要る。
  本 Spec の参照は添付の置き場から来るので、この上限は使わない — D3）
- **失敗の列挙は 9 つ**（`ImageGenError`）: `Unauthorized` / `RateLimited` / `Blocked` / `Timeout` / `ComfyNodeError` /
  `Api` / `Network` / `Shape` / `Config`。**自動の再試行はしない**
- **既定のタイムアウト**（`ImageGenConfig::timeout`）: OpenAI 120 / Gemini 90 / Meta 120 / xAI 120 秒（下限 5 秒）。
  Meta の実測 10〜19 秒、xAI の実測 9.8〜16.9 秒
- プロバイダはアプリ全体で 1 つを選び、プロバイダごとに設定の枠（baseUrl / model / timeout ほか）を持つ。鍵は資格情報ストア
- 費用は枚数とトークンを数えるだけで金額は出さない
- 罠（Kataribe の `failures.md`）: `input_fidelity=high` は gpt-image-1-mini で 400 / プロンプトに「reference sheet」の
  ような参照を指す語を書くと分割された画像が返る / ComfyUI はワークフローに `%ref_1%` が無いと参照を黙って使わない
- **バグを 1 つ見つけた（Kataribe 側）** — `ref_stock.rs:45` の PNG の判定バイトが壊れている。**写さない**（Notes 1）

### Fuseforks の受け皿

- **アプリ全体の設定の前例は Jev**（`fuseforks-host/src/jev_settings.rs`）— `{app_data_dir}/jev.json` + 資格情報ストアの鍵
  `jev_api_token`。値を返す IPC は無い。「いま効いているか」は `is_active` の 1 本に閉じ、起動時・保存後・画面のチェック・
  画面の表示の 4 箇所が同じ述語を読む。置き場の理由は「村を配っても、受け取った人の村が知らない送信先へ送らない」
- **`bake` は `jev.json` と `pricing.json` を写す**（`bake.rs` の `SHELF_COPIED`）。鍵は `--env-out` のとき Jev が有効なら書き出す。
  GUI なしで動かすときの環境変数の名前の衝突検査は `boot.rs:191` が Jev の鍵と扉の合鍵を足して見ている
- **同梱ツールの表** — `BUNDLED_TOOL_NAMES`（8 本）/ `DEFAULT_ENABLED_TOOLS`（7 本 = 8 − `run`）/ `WORK_DIR_TOOL_NAMES`（6 本）。
  画面側の写しは `defaultEnabledTools.test.ts` が Rust の表と突き合わせる
- **ツールの登録とツールの文脈は別の場所で組む** — 登録（どのツールが村に在るか）は `build_host` の 1 実装。
  文脈 `ToolContext`（9 欄: `agent_id` / `work_dir` / `cancel` / `rag_roots` / `agent_names` / `uses_blackboard` / `language` /
  `run_approval` / `judges_dir`）を組むのは**本番では `turn.rs` の 2 箇所**（1435 行の提示用・3757 行の呼び出しごと）で、
  ほかの 25 箇所はテスト（rev1 の「27」はテストを含めた数）。**そのターンの添付を運ぶ欄は無い**
- **そのターンの添付** — `turn.rs` は `incoming.attachments` から画像を読み（`load_turn_attachments`）、最後の利用者の
  発話の `ChatMessage.attachments` に載せる（1 ターン限り = `attachment_contract` 凍結 3）
- **ツール結果で画像をモデルへ返す口は Spec 70 で在る** — `AgentTool::call_with_media` → `ToolOutput.images`（`ToolImage` =
  JPEG / WebP・1 結果 4 枚・1 要求 20 枚）。**PNG を JPEG へ寄せる正規化も在る**（`tool_image::normalize` — 上限の内側の
  JPEG / WebP はそのまま、PNG と上限を超えたものは長辺 1568px・JPEG 品質 85 へ）
- **RepeatGuard は (ツール名, 引数) ごとに、結果の本文と画像の SHA-256 の組が変わらずに返った回数を数え**、同じ組が 2 回
  返った呼び出しが同じ引数でまた来たら実行せずに止める（`turn.rs` の `SeenCall` / `RepeatGuard`）。結果が変われば数え直す
- **ツール行は返事の組み立てと独立に出る** — `ToolInvoked` は `CallRunner::on_call` の中（`turn.rs:2748`）で、呼び出しの
  たびに発行する。返事の組み立て（`dispatch_outcome`・3345 行）が走らないターン（打ち切りなど）でもツール行は残る
- **添付の置き場** — `{workspace}/attachments/`。画像は **WebP・2MB・長辺 1568px** に限る（`validate_attachment`。
  `AttachmentFormat` に JPEG は無い）。30 日で GC し、消えた添付は会話ペインに「保持期間を過ぎて削除されました」の枠で出る。
  依存の `image` 0.25（features = webp / jpeg / png）は **WebP を可逆でしか書けない**（画面の貼り付けは WebView の canvas が
  非可逆の WebP を作っている）
- **会話ペインは発話の添付を送り手に関係なく描く**（`ChatPanel.vue` の `entry.row.message.attachments` の `<img>`）。
  サーヴァントの返事の `AgentMessage` に添付を付ければ、そのまま吹き出しに出る
- **再添付（Spec 73）は利用者の発話の添付だけ** — コアの `find_reattachable`（`runtime.rs:540`）が `Endpoint::User` の発話だけを
  探し、会話ペインの「入力欄へ」も `isMine` の発話にだけ出る。契約（`data_contract.yaml` 1789〜1791 行）は
  「添付を持つのは利用者の発話だけなので広場ログに添付は構造上現れない。利用者以外に増えたらここを数え直す」と書いている
- **返事の組み立ては 1 箇所**（`dispatch_outcome` 系。`AgentMessage::new` → `shared.record`）。
  委譲の依頼元へ返る `Reply` は本文だけを運ぶ
- **システム設定の「外部連携」** — 今は MCP サーバー / 判断特化モデル（Jev）/ 単価表の 3 ページ

## Design

### D1. 置き場 — アプリ全体で 1 つ。`{app_data_dir}/image_gen.json` と資格情報ストア

- 設定は `{app_data_dir}/image_gen.json`（`jev.json` / `pricing.json` と同じ第 3 の棚）。**`world.json` に入れない** —
  村を配ったとき、受け取った人の村がその人の知らない送信先へプロンプトと画像を送る状態を作らない
- 中身: 選んでいるプロバイダ（`openai` / `gemini` / `meta` / `xai`）と、**プロバイダごとの枠**（`model` / `baseUrl` /
  `timeoutSecs`）、既定の縦横比と解像度。プロバイダを切り替えても他の枠の値は残る（Lorekeel の `perProvider` と同じ）
- 鍵はプロバイダごとに資格情報ストア（鍵の名前は `image_gen_key_openai` / `image_gen_key_gemini` / `image_gen_key_meta` /
  `image_gen_key_xai`。**モデルテンプレートの id と衝突しない名前**）。**値を返す IPC は作らない**（登録済みかだけを返す）。
  **モデルテンプレートの鍵は使い回さない** — 使い回すと、テンプレートを消したり鍵を差し替えたりしただけで画像生成が黙って止まる
- **「いま効いているか」は `is_active` の 1 本**。偽になる理由は閉じた 3 つ — **設定ファイルが読めない / プロバイダが
  選ばれていない / そのプロバイダの鍵が登録されていない**。ツールの提示・設定画面の表示・起動時のログが同じ述語と同じ理由を読む
  （Jev と同じ規律）。**接続確認（D8）の結果は `is_active` に入れない**（確認は押したときだけ外へ出る情報で、門ではない）

### D2. 同梱ツール `image` — 既定オフ・2 段の門

- 名前は `image`。`BUNDLED_TOOL_NAMES` は 8 → 9 本、**`DEFAULT_ENABLED_TOOLS` には入れない**（7 本のまま）。
  `run` と同じ理由 — 費用がかかり外へ送るので、**アプリを更新しただけで全個体が画像生成の能力を得る作りにしない**
- **`WORK_DIR_TOOL_NAMES` にも入れない**（6 本のまま）。作業フォルダが無い個体にも提示する — 生成した画像は会話ペインと
  モデルへ届き（D5 の 2・3）、作業フォルダへの保存（D5 の 1）だけが無くなる。保存しなかったことは結果の本文に書く
- **提示の門は 2 段**: `enabledTools` に `image` がある **かつ** `is_active`。どちらかが欠ければ提示しない
  （設定画面のチェックの横に、設定が無効なら「システム設定で画像生成を設定してください」と出す — `noWorkDirWarn` と同じ形）。
  門は呼び出しの時にも見る — ターンの途中で設定が無効になったら生成を始めずに断る（`outcome=inactive`）
- 引数: `prompt`（必須）/ `aspect`（`square` / `landscape` / `portrait`。省略は設定の既定）/ `references`（参照番号の配列 = D3。
  省略可・3 つまで）。**解像度はモデルに選ばせない**（費用を決めるのは利用者 — 設定の既定だけ）
- 理由の欄（Spec 27）を付ける（`wants_reason` は真）。Jev の圧縮の対象外（`prunable` は偽）
- **ツールの説明文と結果の本文は Rust 側で村の言語（ja / en）**。简体中文の村は英語（Spec 74 の `voice()`）。
  **画面の辞書（ja / en / zh-Hans）は設定ページとツールの行の文言だけ**で、ツールの説明文は持たない（P2）

### D3. 参照画像 — そのターンの画像を番号で指す

- `ToolContext` に **そのターンの画像の台帳**を 1 欄足す（D6 の枚数の台帳と同じもの。ターンの間だけ生き、呼び出しの
  たびに共有する）。台帳の画像には**参照番号が届いた順に 1 から**付く:
  1. 利用者がそのターンに添付した画像（画像以外の音声・動画・PDF は数えない）
  2. **そのターンに `image` で生成した画像**（生成した順に続きの番号）。結果の本文に「参照番号 N で次の生成に渡せます」と書く
- 利用者の添付の番号は、添付を畳む文脈の 1 行（「添付: 画像 N 件」）に番号の規則を 1 句足して知らせる（**`image` を提示して
  いるターンだけ**。提示していなければプロンプトは 1 バイトも変えない = Goal 4）
- **添付は 1 ターン限り（`attachment_contract` 凍結 3）を変えない。** 生成した画像の番号も次のターンには残らない。
  委譲で受けたターンには利用者の添付が無いので、参照できるのはそのターンに生成した画像だけ
- **過去の画像は「入力欄へ」（Spec 73）で渡し直す。** 生成した画像の写しはサーヴァントの返事の発話に付く（D5 の 2）ので、
  再添付の対象を~~**送り手を問わない**~~ **利用者とサーヴァントの発話**へ広げる（「覆す判断」1）。コアの `find_reattachable` の送り手の条件を
  閉じた許容 `User | Agent` にし、会話ペインの「入力欄へ」を同じ集合の発話の、消えていない添付に出す。**凍結 S73-7（モデルが過去の添付を自分で取り出す経路は作らない）は
  変えない** — 渡し直すのは人の操作のまま
- 範囲外の番号・4 つ以上・番号が付いた画像が 1 つも無いのに `references` がある、は**生成を始めずに断る**（結果の本文で
  理由と次の手を書く）
- **参照として送るバイト列は、台帳の画像の写し**（利用者の添付は添付の置き場の実体、生成した画像は D5 の 2 の写し）。
  どちらも 1 枚 2MB・長辺 1568px 以下なので、**参照の大きさは添付の上限で決まる**（3 枚で合計 6MB 以下。Lorekeel の 8MB / 12MB は
  使わない）。形式は `detect_format` で読む（利用者の添付は WebP、生成した画像の写しは JPEG か WebP）
- **送る前に変換しない**（rev3。rev2 は「受けない社だけ JPEG へ変換」としていた）。P0 で **4 社とも WebP の参照を受け**、
  **Gemini と xAI は JPEG の参照も受けた**（どれも出力の中央の色で、参照どおりに描き直したことを照合）。OpenAI と Meta の
  JPEG の参照は撃っていない（OpenAI は文書が jpg を挙げ、Meta は Spec 70 で JPEG の `input_image` を運んでいる）。
  受けない社が出たら `api` の失敗として本文に理由が出る。P4 の「生成した画像を参照番号で直す」が JPEG の参照を踏む

### D4. ワイヤ — 4 社の口を Lorekeel から写す

- 置き場はコアの `image_gen/`（プロバイダごとの組み立てと解釈の純関数 + HTTP）。LLM のワイヤ（`llm/`）とは分ける —
  会話の canonical を通らず、1 回の要求で 1 枚を返すだけの別の口
- 写すのは「縦横比 3 値 × 解像度 3 段 → 各社の欄」の写像、要求と応答の形、拒否の分類。**写さないもの**は D11
- **Meta は解像度を写さない**（`size` が縦横比しか決めない）。設定画面で Meta を選んでいる間は解像度の欄を押せなくする（D8）
- 1 回 1 枚（`n = 1`）。**タイムアウトの既定は Lorekeel の値をそのまま**: OpenAI 120 / Gemini 90 / Meta 120 / xAI 120 秒
  （下限 5 秒）。プロバイダの枠の `timeoutSecs` で上書きできる
- **打ち切り（Spec 10）は要求ごと切る**（`cancel` と HTTP の往復を `select!` で競わせ、打ち切りが勝ったら要求の future を落とす）。
  **Spec 52 D4（待ちだけ切り、HTTP は切らない）とは逆。** 理由 — あちらが HTTP を切らないのは払いの記録（`turn:` 行・予算）を
  失わないためで、画像生成の費用はもともと予算の外（D7）。待つと打ち切りが最長 120 秒遅れ、Spec 10 の「要求から 0.0 秒」が
  画像生成だけ破れる（`run` が打ち切りで子プロセスを止めるのと同じ側）。代償 — **接続先は生成を続けて費用がかかることがある**
  （「利用者が負う条件」）。打ち切った後はファイルも写しも 1 つも書かない（`outcome=interrupted`）
- **失敗は閉じた 8 区分で、Lorekeel の列挙と 1 対 1**（ComfyUI の `ComfyNodeError` だけ除く）:

  | 区分（ログの `outcome`） | Lorekeel | 例 |
  |---|---|---|
  | `auth` | `Unauthorized` | 401 / 403 |
  | `rate_limited` | `RateLimited` | 429（本文の要点を残す） |
  | `blocked` | `Blocked` | Gemini の空の 200 / xAI の `respect_moderation: false` / 各社の拒否の本文 |
  | `timeout` | `Timeout` | 既定のタイムアウト超え |
  | `network` | `Network` | DNS / 接続拒否 |
  | `shape` | `Shape` | 応答に画像が無い・JSON でない |
  | `api` | `Api` | 上のどれでもない 4xx / 5xx（状態コードを残す） |
  | `config` | `Config` | 生成の時の 404（モデルが無い）ほか設定の誤り |

  **自動の再試行はしない** — 結果の本文に村の言語で理由と次の手（言い換える / 鍵を確かめる / 待つ）を書いて、モデルに判断させる。
  ツールの側で生成を始めずに断ったもの（`bad_reference` / `limit` / `inactive`）と `interrupted` はこの 8 区分の外（D6 / D7）
- 拒否の見分け方は Lorekeel の記録に従う。**xAI の `respect_moderation` は文書の記述で、Lorekeel でも未観測**。
  **P0 で拒否をわざと起こす要求は送らない**ので、この読み方は P0 の後も未観測のまま残る

### D5. 生成した画像の行き先 — 元のまま 1 つ・写し 1 つ

1. **作業フォルダ**: `<work_dir>/generated_images/<日時>-<agent_id>-<番号>.<拡張子>` に元のバイト列のまま保存する。
   日時はローカル時刻の `YYYYMMDD-HHMMSS`（コロンを使わない）、番号はそのターンの生成の順（1〜4）、拡張子は中身から決める
   （`png` / `jpg` / `webp`）。**`agent_id` を入れるのは、多くの個体が同じ作業フォルダを向くから**。書くのは `create_new` で、
   既に在れば `-2`・`-3` を足して上書きしない。作業フォルダが無い個体・書き込みに失敗した個体では保存しない（結果の本文に
   そう書き、生成は成功のまま。ログは `saved=no_work_dir` / `saved=failed`）。`file` ツールで移動・コピーできる
2. **写し — 会話ペイン・モデル・参照の 3 つが同じバイト列を使う。** 元から 1 つだけ、**`tool_image::normalize`（Spec 70）と
   同じ 1 実装**で作る（rev3。利用者裁定 2026-11-16 —「JPEG を加える」）:
   - 上限の内側（長辺 1568px・2MB）の JPEG / 静止 WebP は**バイト列をそのまま**（Gemini・xAI 1k の JPEG がこの形）
   - それ以外（PNG・上限超え・アニメーション）は長辺 1568px の **JPEG 品質 85** へ（OpenAI の PNG・xAI 2k の PNG・Meta の 1600² の
     WebP がこの形）。P0 の実測では 263KB〜955KB（2K でも 1568px のまま 931KB）
   - 画像の添付に JPEG を加える（「覆す判断」2。`attachment_contract` の「Spec 76 改訂」S76-1）。JPEG になりうるのは
     サーヴァントの返事の発話の添付だけで、利用者が貼る画像は WebP のまま
   - **rev2 の「可逆 WebP で 1568 → 1280 → 1024px と段を踏む」は退けた** — P0 で 2K の写実の画像が 1024px で 1.96MB（上限まで
     4.5%）で、1024px でも収まる保証が無く、元が JPEG の画像は可逆 WebP で元より大きくなった（951KB → 1.68MB）
   - 写しは**返事の発話が組まれるときに**添付の置き場へ書き、**そのターンの返事の発話に添付として付ける**（`ChatPanel.vue` は
     送り手を問わず添付を描く）。それまでは D3 の台帳がメモリに持つ。**返事の発話が組まれないターン（打ち切り・予算切れ・
     失敗・承認待ちで止まった）では写しを書かない** — 画像は作業フォルダにだけ残り、ツール行の本文にパスが出る
     （ツール行は返事の組み立てと独立に出る = 現況）。作業フォルダも無い個体では、そのターンの画像は残らない（「利用者が負う条件」）
   - 写しに付ける表示用の名前（`file_name`）は作業フォルダに保存したファイル名、保存しなかったときは `generated-<番号>.<写しの拡張子>` の形
   - **写しは 30 日で GC される**（添付の置き場の規則のまま。対象外にする 2 つ目の保持規則は作らない）。過ぎると吹き出しは
     利用者の添付と同じ「保持期間を過ぎて削除されました」の枠になる。元は作業フォルダに残る
   - **写しがモデルへ後から届く経路は無い** — 履歴は本文だけ、広場ログは本文だけ（添付を書くコードが無い）、受信箱へ配送する
     経路に返事の発話の添付は載らない。届くのは利用者が「入力欄へ」で渡し直したときだけ。これで契約の 1789〜1791 行の
     「利用者以外に増えたら数え直す」を数え直したことになる（数え直した結果、広場ログに添付は今も現れない）
3. **モデル**: 結果の本文に保存したパスと参照番号を書き、**写し（2 と同じバイト列）を `ToolOutput.images` で返す**（Spec 70 の経路。
   写しは `ToolImage` を作る関数そのものの出力なので、そのまま渡せる）。モデルの視覚の入力は各社とも長辺 1568px 前後へ
   縮めるので、元を渡しても見えるものは増えない。生成した個体は自分の絵を見て、参照番号で直しを頼める（D3）
- 委譲の依頼元へ返る `Reply` は本文だけ（パスは届く、画像は届かない）。依頼元に画像を見せるのは範囲外（未決 3）

### D6. 歯止め — 1 ターン 4 枚

- 1 ターンで**接続先へ送れる生成の要求は 4 回まで**（定数）。数えるのは D3 の台帳（ターンの間だけ生きる）。
  **数えるのは送った要求** — 成功も、送った後の失敗（D4 の 8 区分）も、打ち切りも 1 回（拒否された言い換えの連打も費用に
  なりうるため）。**生成を始めずに断ったもの（`bad_reference` / `limit` / `inactive`）は数えない**（外へ何も出ておらず費用が
  無い）。5 回目は生成を始めずに断る（`outcome=limit`）
- 生成を始めずに断る呼び出しの連打は、RepeatGuard（同じ引数で同じ結果が 2 回返ったら 3 回目を止める）と周回の上限が止める
- **RepeatGuard はそのまま効く**（比べるのは (ツール名, 引数) ごとの結果の本文と画像の組 = 現況）。成功の結果は本文に毎回違う
  参照番号とパスが入り、画像も違うので、同じプロンプトで成功を繰り返しても数えが進まない。同じ拒否が同じ本文で 2 回返ったら、
  3 回目の同じ要求は送らずに止まる
- **4 という値は P4 の使い方を見て変えてよい**（未決 1）。P0 で凍結するのは「上限がある・何を数えるか」で、値は契約に
  「P4 で見直す」と書く

### D7. 費用 — 生成の費用はトークン予算の外。画像のトークンは予算の中。ログに 1 行

- **画像生成の API の費用は、トークン予算（Spec 11）にも統計（Spec 39）にも入れない**。単価表も 1 枚の値段を持っていない。
  「利用者が負う条件」に書く（Jev・Perplexity の検索料と同じ扱い）
- **D5 の 3 でモデルへ返した写しは、普通のツール結果の画像と同じく、そのターンの以後の周の LLM の入力トークンになり、
  トークン予算と統計に入る**（Spec 70 の経路のまま。ツール結果は履歴に積まないので、次のターンには残らない）
- 計器 `image gen:`（`agent` / `provider` / `model` / `aspect` / `refs` / `outcome` / `elapsed_ms` / `bytes` / `saved` /
  返ってきた費用の欄があればその値 — OpenAI のトークン・xAI の `cost_in_usd_ticks`）。`outcome` は `ok` + D4 の 8 区分 +
  `interrupted` / `limit` / `bad_reference` / `inactive` の閉じた集合。**プロンプトの本文は書かない**

### D8. システム設定のページ

- **システム設定 ＞ 外部連携 ＞ 画像生成**（判断特化モデル（Jev）の下）。プロバイダの選択 / モデル / 接続先（既定のまま
  なら空）/ 既定の縦横比と解像度 / タイムアウト / 鍵の登録（書くだけ）/ 「接続を確かめる」
- **Meta を選んでいる間は解像度の欄を押せなくし、「Meta は縦横比だけが効きます」と出す**。値は保存したまま（他の社へ切り替えれば効く）
- 「接続を確かめる」は**画像を作らない GET を社ごとに 1 本**（現況の 4 つの口。タイムアウト 20 秒）。2xx で「接続できました」、
  401 / 403 は鍵、Gemini・Meta・xAI の 404 はモデル名、それ以外は状態コードを出す。**接続先を既定から変えていて、その口が
  無いサーバーでは確認が失敗するだけ**で、生成の門（`is_active`）には影響しない。OpenAI の確認は鍵だけを見てモデル名は見ない
  （`/v1/models` の一覧）。押したときだけ外へ出る。開いただけでは 1 バイトも出ない
- ページの上に、いま有効か（`is_active`）と、偽ならその理由（D1 の 3 つのどれか）を出す

### D9. PRIVACY

- 送信先が 1 つ増える（選んだ画像生成 API）。送るのはプロンプトと参照画像。**参照画像は、利用者がサーヴァントの
  モデルの事業者へ送ったつもりの添付が、別の事業者へ渡ることがある**（Spec 73 の再添付と同じ形）。生成した画像を
  「入力欄へ」で渡し直すと、画像生成の事業者が作った画像がサーヴァントのモデルの事業者へ渡る
- 生成した画像は作業フォルダと添付の置き場に残る。ログには本文を書かない

### D10. GUI なしで動かすとき（Spec 64 / 65 / 66）

- ツールの登録は `build_host` の 1 実装なので、CLI でも同じ門で提示される。鍵は `SecretStore` 経由（env の秘密なら
  `FUSEFORKS_SECRET_IMAGE_GEN_KEY_OPENAI` の形）
- **`bake` は `image_gen.json` を写す**（`SHELF_COPIED` に足す。`jev.json` と同じ行）。D1 の「`world.json` に入れない」と
  理由が分かれる — D1 が避けているのは**村を他の人へ配ったとき**に送信先が付いていくことで、`bake` は**同じ利用者が自分の
  コンテナへ自分の村を写す**操作（Spec 65 の置き場の表の「棚」）。写さないとコンテナでは `image` が提示されない
- `--env-out` は `is_active` が真のとき、選んでいるプロバイダの鍵だけを書き出す（Jev と同じ条件の形）
- **環境変数の名前の衝突検査（`boot.rs:191`）に 4 つの鍵の名前を足す**（Jev の鍵・扉の合鍵と同じ並び）
- 起動前検査（`headless_preflight`）には足さない — 設定が無効なら `image` は提示されないだけで、止める理由が無い

### D11. Lorekeel から写さないもの

- **ComfyUI**（ワークフロー JSON の置換・ポーリング。ローカルのサーバーで、本 Spec の 4 社とは口の形が違う）
- スタイル・ネガティブプロンプトの欄（モデルがプロンプトに書けばよい）
- 参照画像のストック（`ref_stock.rs`）— 添付と Spec 73 の再添付が代わる
- 履歴の画面（`image_history.rs`）— 作業フォルダと会話ペインが代わる
- プロンプトを LLM に書かせる段（サーヴァント自身がプロンプトを書く）
- 参照の 8MB / 12MB の上限（D3。参照の出所が添付の置き場なので添付の上限で足りる）

## 採らなかった形

- **個体ごとにプロバイダを選ぶ** — 利用者裁定（アプリで統一）。個体ごとに持つと鍵と送信先が個体の数だけ増える
- **モデルテンプレートの鍵を使い回す** — D1
- **既定オン** — D2。更新しただけで費用と送信先が増える
- **`WORK_DIR_TOOL_NAMES` に入れる** — D2。作業フォルダが無くても会話ペインとモデルへは届く
- **解像度をモデルに選ばせる** — D2。費用を決めるのは利用者
- **トークン予算に換算して入れる** — 1 枚の値段が社とモデルと解像度で違い、単価表も持っていない。換算の嘘を作るより、
  予算の外だと書く
- **自動の再試行** — Lorekeel と同じ。拒否の言い換えはモデルが判断する
- **打ち切りでも HTTP の往復を待つ（Spec 52 D4 の形）** — D4。最長 120 秒遅れる
- **生成画像を添付の置き場だけに置く** — 30 日で GC される。作業フォルダに元のまま残す
- **写しを GC の対象から外す** — 保持の規則が 2 つになる。元は作業フォルダにある
- **会話ペイン用とモデル用で別の写しを作る** — D5。1 つの写しを 3 つの用途が共有する
- **元のバイト列をモデルへ返す** — D5 の 3。`ToolImage` の上限を超えうるうえ、視覚の入力は縮められる
- **写しを可逆 WebP で段を踏んで縮める**（rev2 の形）— D5 の 2。P0 で 1024px でも収まる保証が無く、元が JPEG だと大きくなった
- **参照を送る前に変換する**（rev2 は受けない社だけ JPEG、rev1 は PNG）— D3。P0 で 4 社とも WebP を受けた

## P0 実測記録（2026-11-16）

だったので、利用者が自分の端末で鍵を入れて同じスクリプトを撃った（鍵の値はこちらに届いていない）。撃つ前の予測は
