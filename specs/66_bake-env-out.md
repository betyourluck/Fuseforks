## Goal

`fuseforks-cli bake` に、**資格情報ストアにある鍵を、コンテナの `.env` の形で書き出す**口を足す。
運用者が鍵をどこかに控えていなくても、GUI に登録した鍵からコンテナを起動できるようにする。

**覆す約束が 1 つある。** PRIVACY 日英と DETAIL は「保存した値を読み出す経路を持たない」と書いている
（PRIVACY.md 3・DETAIL「認証情報」の節）。この Spec は、**利用者が引数で明示したときだけ**、資格情報ストアの値を
平文のファイルへ出す経路を初めて作る。画面（GUI）に値を戻す経路は今までどおり作らない。

## 前提の実測（2026-10-07）

- **値を引く口は既にある** — `SecretStore::get`（`KeyringSecretStore` は Windows の資格情報マネージャー / macOS の
  キーチェーン / Linux の Secret Service）。LLM と MCP に繋ぐときに使っている。新しい依存は要らない
- **変数名の写し方も既にある** — `env_secret_name`（`FUSEFORKS_SECRET_` + 鍵を大文字・英数字以外を `_`）。
  衝突は `check_secret_names`（`boot.rs`）が数える: テンプレート ID の全部 + `jev_api_token` + `door_token` +
  村の有効な http の MCP サーバーの `mcp:NAME`
- **開発機の村: テンプレート 15 個はすべて `credential: keyring`、そのうち個体が使っているのは 6 個**。テンプレートを全部
  書き出すと、使わない鍵 9 本まで平文のファイルに出る
- **`CredentialSource` は 3 値**（`Unset` / `NotRequired` / `Keyring`）。値を引くのは `Keyring` だけ
- 扉の合鍵: GUI の扉の合鍵は `{data_dir}/mcp_server.json` に住み、**資格情報ストアには無い**。作り方は
  `uuid::Uuid::new_v4().simple()`（32 桁の小文字 hex。`mcp_server.rs` の `ensure_token` / `regenerate_token`）
- Jev の鍵が要るのは、圧縮が有効か判断役が 1 つでも有効なとき（起動前検査の `JEV_TOKEN_MISSING` と同じ条件）
- **compose の `.env` の読み方**（rev2 で実測。`docker compose config` と busybox の中の `printf` で値を見た）:

  | `.env` の行 | compose が読んだ値 |
  |---|---|
  | `A=abc#123` | `abc#123`（空白の無い `#` は値の一部） |
  | `B=abc #123` | `abc`（**空白の後の `#` からコメント**） |
  | `E=a$x` | `a`（**引用符なしの `$x` は展開される** — 未定義なら空） |
  | `D="a\$x b"` | `a$x b`（二重引用符も展開とエスケープを読む） |
  | `C='a#b$x "q"'` | `a#b$x "q"`（**単一引用符の中はそのまま**） |
  | `H='a\'b'` | `a'b`（単一引用符の中でも `\'` だけはエスケープとして読む） |
  | `J='a\b'` | `a\b`（それ以外の `\` はそのまま） |
  | `G=  spaced  ` | `spaced`（引用符なしは前後の空白を落とす） |

  帰結: **値は単一引用符で囲めば `$`・`#`・`"`・空白がそのまま運ばれる**。運べないのは `'` と `\`（`\'` が `'` に化け、
  末尾の `\` が閉じ引用符をエスケープしうる）と改行・制御文字

## Design

### D1. 明示の引数のときだけ書く・写しの外だけ

```text
fuseforks-cli bake --data-dir <GUI の data_dir> --out <写し> [--map …] [--update]
                   --env-out <path>
```

- **`--env-out` を渡したときだけ**書く。既定では書かない（気づかないうちに鍵のファイルができる形にしない）
- **写しの中には書かせない** — `<path>` が `--out` と同じか、`--out` の下なら**引数の誤り（2）**。写しはボリュームや
  バックアップへ流れる（Spec 65 D2 の 4 と同じ理由）。参照構成は `deploy/.env`（`deploy/village` の隣）
- **判定の仕方**: `<path>` と `--out` のそれぞれで、**存在する最も近い祖先を `canonicalize` し、残りの成分をそのまま足した
  パス**どうしを、成分単位の前方一致で比べる（`deploy/../deploy/.env` もシンボリックリンクも解ける。まだ無い `--out` でも
  比べられる）。Windows では大文字小文字を無視する
- `<path>` の親フォルダが無ければ作る（`--out` と同じ扱い）

### D2. 2 段で動く — 判定は計画、書き込みは写しの後

Spec 65 の `bake` の「計画と適用」に乗せる。

- **計画の段**で全部を読んで判定する — 資格情報ストアの値・既にある `.env`・D1 のパスの判定・D4 の既存の行の扱い。
  止まる理由（2 / 3 / 4 / 5 / 10 / 11）は全部ここで出し、**止まるときは写しも `.env` も 1 バイトも書かない**
- **適用の段**では、写しを書き終えてから `.env` を書く（一時ファイル + rename）。写しの書き込みに失敗したら `.env` は書かない
- **終了コード 11 の意味を広げる**: Spec 65 の「写し先の状態が食い違う」を「**出力先（`--out` か `--env-out`）の状態が
  食い違う**」へ。エラー文はどちらの出力先かを名指しする。`bake` だけの番号なので、ほかのコマンドの意味は動かない

### D3. 書き出す鍵（村が要るものだけ）

| 鍵 | 対象 | 値の出どころ |
|---|---|---|
| テンプレートの鍵 | **村の個体が使うテンプレート**（`credential: keyring`）だけ。使っていないテンプレートは書かない | 資格情報ストア |
| MCP の参照 | 村の**有効な** http の MCP サーバーの `${secret:NAME}`（Spec 65 P4 の欄と同じ範囲 = `village_mcp_secret_refs`） | 資格情報ストア（`mcp:NAME`） |
| Jev の鍵 | 圧縮が有効か、判断役が 1 つでも有効なときだけ | 資格情報ストア（`jev_api_token`） |
| 扉の合鍵 | **常に対象に含める**（`--door-port` を使うかは compose で決まる。使わなければ何も起きない） | **コンテナ用に新しく作る**（D5） |
| `TZ` | 常に対象に含める | `bake.json` の `sourceTimeZone`（`bake` は時刻帯が読めなければ 2 で止まるので、**常にある**） |

- **ストアに値が無い鍵は、名前だけを印つきのコメントで残す**（`# FUSEFORKS_SECRET_GPT_6_SOL=   # bake: 資格情報ストアに無い`）。
  そのまま起動すれば `check` が `SECRET_MISSING` で変数名を名指しして止まる（黙って空の値を書かない）
- 並びは種類ごと・名前の順（差分が読める形）。先頭に「`bake` が書いた・git に入れない・値は平文」の注記

### D4. 値の書き方（compose が読む形）

- **値は常に単一引用符で囲む**（`FUSEFORKS_SECRET_X='…'`）。前提の実測のとおり、`$`・`#`・`"`・空白がそのまま運ばれる
- **`'`・`\`・改行・制御文字を含む値は書かない** — その鍵は D3 の印つきコメントにし（印の理由は「`.env` に書けない文字を含む」）、
  **名前だけ**を `ENV_VALUE_UNWRITABLE` で名指しする。終了コードは 0 のまま。直し方は deploy/README に書く（その鍵だけ手で書く）。
  エスケープの規則を作らないのは、compose の単一引用符の中のエスケープが `\'` だけで、`\` で終わる値と区別できないため

### D5. 扉の合鍵は GUI と別に作る

- **GUI の `mcp_server.json` の合鍵は引き継がない。** コンテナの扉は外（Caddy 越し）へ出る口で、GUI の扉は開発機の
  loopback だけの口。**別の合鍵にしておけば、片方が漏れてももう片方は閉じたまま**で、作り直すときも互いに影響しない
- 作り方は GUI と同じ `uuid::Uuid::new_v4().simple()`（32 桁 hex）。`mcp_server.rs` の生成を関数 1 本に切り出して共有する
  （書式を 2 通りにしない）
- 既にある `.env` に扉の合鍵の行があれば、**作り直さない**（作り直すと外の呼び出し側の設定が黙って壊れる）

### D6. 既にある `.env` の扱い

**行の分類**（既にある `.env` を読むとき）:

| 行 | 扱い |
|---|---|
| 有効な代入 `NAME=…` | 「ある名前」 |
| `bake` の印つきコメント `# NAME=   # bake: …` | 「`bake` が置いた空き」 — 値が揃えば置き換える |
| 印の無いコメントの `# NAME=…` | 「運用者が止めた名前」 — **ある名前として扱い、触らない**。`ENV_COMMENTED_OUT` で名前だけ知らせる |
| その他の行・空行・コメント | そのまま |

- `--update` なし: `<path>` が存在すれば **11** で止め、写しも作らない（D2 の計画の段）
- `--update` あり:
  - **足りない名前（どの形でも出てこない名前）だけを末尾に足す**
  - **`bake` の印つきコメントは、ストアに値があれば代入の行へ置き換え**、無ければそのまま
  - ある名前の行は値を書き換えない。ストアの値と違えば、**値を出さずに名前だけ**を `ENV_VALUE_DIFFERS` で知らせる。
    比べる前に既存の値を compose と同じ規則で読む（単一・二重引用符を外す・引用符なしは前後の空白を落とす）。
    **対象は資格情報ストアから読む鍵だけ**（扉の合鍵と `TZ` は対象外）
  - `TZ` が既にあり `sourceTimeZone` と違えば、`ENV_TZ_DIFFERS` で**両方の値を出して**知らせる（秘密ではない）。書き換えない
  - **要らなくなった鍵は消さない** — 村が要る集合（D3）に無い `FUSEFORKS_SECRET_*` の有効な代入を、`ENV_UNUSED` で名前だけ
    知らせる（扉の合鍵は除く）。テンプレートを外した・MCP サーバーを無効にした後に、不要な秘密が残っていることに気づける。
    消すのは運用者（deploy/README に書く）
- 警告がいくつあっても終了コードは 0

### D7. 値はどこにも表示しない

- 標準出力・標準エラー・`--json` に出るのは**名前と件数だけ**（書き出した名前・ストアに無い名前・書けない名前・値が違う名前・
  要らない名前・止められている名前の各リスト。`--json` では名前の配列）。例外は `ENV_TZ_DIFFERS` の時刻帯の名前（秘密ではない）
- **0600 の理由**: Unix では `.env` を 0600 で作る — **同じ機械の他のユーザーからの偶発的な読み取り**への備え。配布と
  バックアップへの備えは D1 の「写しの外だけ」が持つ。Windows では ACL を組まない（扉の合鍵の `mcp_server.json` と同じ判断。
  利用者のフォルダの既定の ACL に任せる）
- `fuseforks.log` には何も書かない（`bake` はもともと村のログに書かない）

### D8. OS ごとの読み

- Windows / Linux（Secret Service）は、同じユーザーならダイアログ無しで読める
- **macOS のキーチェーンは、項目ごとに許可のダイアログが出ることがある**（`fuseforks-cli` は GUI と別の実行ファイルなので）。
  deploy/README に書く
- **資格情報ストアを読めない**（Secret Service が居ない Linux 等）なら、計画の段で **5** — 写しも `.env` も書かない（D2）

### D9. 外へ送るもの（PRIVACY）

- **外へ送るものは増えない。** 書き出すのは手元のファイルだけ
- PRIVACY 日英の 3 を直す:「どれも保存した値を読み出す経路を持たない」→「**画面へ値を戻す経路は持たない。`fuseforks-cli bake
  --env-out` を明示したときだけ、コンテナ用に平文のファイルへ書き出す**（書き出したファイルの扱いは利用者の責任）」

## 採らなかった形

1. **既定で書き出す** — 気づかないうちに鍵の平文ファイルができる
2. **写しの中（`deploy/village`）に書く** — 写しはボリュームとバックアップへ流れる。`.env` は写しの外
3. **テンプレートを全部書き出す** — 開発機の村で使わない鍵 9 本まで出る
4. **既にある `.env` を上書きする / 要らない行を消す** — 運用者が手で書いた行（ドメイン・コンテナ用の別の鍵）を消す
5. **GUI に「書き出す」ボタン** — 画面から鍵のファイルを作れる経路は、CLI の明示の引数より広い。需要が出たら別に
6. **値の違いを自動で直す（ストアの値で上書き）** — どちらが正しいかはアプリには分からない
7. **GUI の扉の合鍵を引き継ぐ** — 外へ出す口と loopback だけの口で合鍵を共有すると、片方の漏れがもう片方へ及ぶ（D5）
8. **値をエスケープして何でも書く** — compose の単一引用符の中のエスケープは `\'` だけで、`\` で終わる値と区別できない（D4）
9. **起動する集合で鍵を絞る（`bake --start`）** — `bake` は起動する集合を知らない設計で、ここだけ知ると `check` と数える範囲が
   割れる。窓口 1 体で回すなら、書き出した後に要らない行を消せばよい（旧未決 1）

  報告 `EnvReport` は名前と件数だけ（`TZ` の違いだけ時刻帯の名前）
- **`bake.rs`**: `BakeRequest.env_out` と `bake(req, secrets)`（CLI は `KeyringSecretStore`、テストは `InMemorySecretStore`）。
  判定の順は 引数（写しの中なら 2）→ 元の村のロック（4）→ 出力先の状態（`--out` と `--env-out` の 11）→ … → 鍵の集合と
  ストアの読み（読めなければ 5）→ 既存の `.env` の分類 — **ここまでが計画の段**。適用は写しの後に `.env` を一時ファイル + rename
  （Unix は 0600）。鍵の集合は `village_mcp_secret_refs`・`JevSettingsStore` と判断役の `enabled`・個体が使うテンプレートから組む
- **扉の合鍵の生成は `mcp_server::new_door_token` の 1 本**（GUI の `ensure_token` / `regenerate_token` も呼ぶ）
- **Spec に無かった判断を 1 つ足した**: 書き出す鍵どうしが同じ環境変数名に写る（`a-b` と `a_b`）なら **5** で止め、写しも
  `.env` も書かない（そのまま書くとコンテナが Spec 64 の衝突検査で起動しない — 書いても使えない `.env` を作らない）
- 警告の識別子は `ENV_SECRET_MISSING` を足して 6 つ（ストアに無い鍵も名前で名指しする — D3 は「印つきコメント」とだけ書いていた）
- CLI: `--env-out`（`bake` だけ）・使い方の文・結果の 1 行（値を書いた鍵・ストアに無い・書けない・扉の合鍵を作ったか）。
  **CLI の結合テストでは `--env-out` を回さない** — CLI は本物の OS の資格情報ストアを読むので、テストが開発機の鍵に触れる
- テスト: `env_file` 単体 6 本 / `bake` 結合 6 本（要る鍵だけ・値が報告に出ない / Jev の条件 / 既存の `.env` で 11 と何も書かない /
  写しと同じ・下・`..` で 2 / `--update` で印つきコメントを置き換え運用者の行と扉の合鍵を残す・違いは名前だけ / ストアが読めなければ 5）/
  CLI の引数 1 本。**変異 5 本（予測を先に書いた）** — 全テンプレートを書く / 写しの中の判定を外す / 既存の `.env` を見ない /
  印つきコメントを置き換えない（結合 + 単体の 2 本）/ ストアの読みの失敗を握り潰す — すべて予測どおり
