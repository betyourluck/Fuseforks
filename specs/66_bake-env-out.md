# Spec 66: `bake` で `.env` を書き出す（資格情報ストアからコンテナの秘密へ）

- 状態: **Draft rev1**（2026-10-07 起票）
- 起点: 利用者（2026-10-07）—「できれば `.env` も自動的に作ってくれたほうがいい」「あまり LLM のキーって保管はしない。
  OS の資格情報ストアに書きっぱなし。なのでそこから `.env` に書き出せたほうがよい」。Spec 65 の P6 で `deploy/.env` を
  手で書いた（鍵 5 + MCP 5 + 扉 1 + `TZ`）のが直接のきっかけ
- 前提の Spec: [Spec 65](65_container-deploy.md)（`bake`・`--secrets env`・`${secret:NAME}`）/
  [Spec 64](64_headless-host.md) D4（`EnvSecretStore` と変数名の写し方）

## Goal

`fuseforks-cli bake` に、**資格情報ストアにある鍵を、コンテナの `.env` の形で書き出す**口を足す。
運用者が鍵をどこかに控えていなくても、GUI に登録した鍵からコンテナを起動できるようにする。

**覆す約束が 1 つある。** PRIVACY 日英と DETAIL は「保存した値を読み出す経路を持たない」と書いている
（PRIVACY.md 3・DETAIL「認証情報」の節）。この Spec は、**利用者が引数で明示したときだけ**、資格情報ストアの値を
平文のファイルへ出す経路を初めて作る。画面（GUI）に値を戻す経路は今までどおり作らない。

## 前提の実測（2026-10-07）

- **値を引く口は既にある** — `SecretStore::get`（`KeyringSecretStore` は Windows の資格情報マネージャー / macOS の
  キーチェーン / Linux の Secret Service）。LLM と MCP に繋ぐときに使っている。新しい依存は要らない
- **変数名の写し方も既にある** — `env_secret_name`（`FUSEFORKS_SECRET_` + 鍵を大文字・英数字以外を `_`）。
  衝突は `check_secret_names`（`boot.rs`）が数える: テンプレート ID の全部 + `jev_api_token` + `door_token` +
  村の有効な http の MCP サーバーの `mcp:NAME`
- **開発機の村: テンプレート 15 個はすべて `credential: keyring`、そのうち個体が使っているのは 6 個**。テンプレートを全部
  書き出すと、使わない鍵 9 本まで平文のファイルに出る
- **`CredentialSource` は 3 値**（`Unset` / `NotRequired` / `Keyring`）。値を引くのは `Keyring` だけ
- 扉の合鍵（`door_token`）は資格情報ストアに無い（GUI の扉の合鍵は `{data_dir}/mcp_server.json` に住む）
- Jev の鍵が要るのは、圧縮が有効か判断役が 1 つでも有効なとき（起動前検査の `JEV_TOKEN_MISSING` と同じ条件）

## Design

### D1. 明示の引数のときだけ書く

```text
fuseforks-cli bake --data-dir <GUI の data_dir> --out <写し> [--map …] [--update]
                   --env-out <path>
```

- **`--env-out` を渡したときだけ**書く。既定では書かない（気づかないうちに鍵のファイルができる形にしない）
- **写しの中には書かせない** — `<path>` が `--out` の下なら引数の誤り（2）。写しはボリュームやバックアップへ流れる
  （Spec 65 D2 の 4 と同じ理由）。参照構成は `deploy/.env`（`deploy/village` の隣）
- 書くのは**写しを作り終えた後**。写しで止まる（3 / 4 / 5 / 10 / 11）ときは `.env` も書かない

### D2. 書き出す鍵（村が要るものだけ）

| 鍵 | 対象 | 値の出どころ |
|---|---|---|
| テンプレートの鍵 | **村の個体が使うテンプレート**（`credential: keyring`）だけ。使っていないテンプレートは書かない | 資格情報ストア |
| MCP の参照 | 村の**有効な** http の MCP サーバーの `${secret:NAME}`（Spec 65 P4 の欄と同じ範囲 = `village_mcp_secret_refs`） | 資格情報ストア（`mcp:NAME`） |
| Jev の鍵 | 圧縮が有効か、判断役が 1 つでも有効なときだけ | 資格情報ストア（`jev_api_token`） |
| 扉の合鍵 | 常に書く（`--door-port` を使うかは compose で決まるので） | **乱数で新しく作る**（32 バイト・URL 安全な base64） |
| `TZ` | 常に書く | `bake.json` の `sourceTimeZone` |

- **ストアに値が無い鍵は、名前だけをコメントで残す**（`# FUSEFORKS_SECRET_GPT_6_SOL=  （資格情報ストアに無い）`）。
  そのまま起動すれば `check` が `SECRET_MISSING` で変数名を名指しして止まる（黙って空の値を書かない）
- 並びは種類ごと・名前の順（差分が読める形）。先頭に「`bake` が書いた・git に入れない・値は平文」の注記

### D3. 既にある `.env` は上書きしない

- `--update` なし: `<path>` が存在すれば **11**（写し先の状態が食い違う）で止め、**写しも作らない**（判定は計画の段で）
- `--update` あり: **既にある行はそのまま**にし、**足りない名前だけを足す**。運用者が手で書いた行（`FUSEFORKS_DOMAIN` 等）と
  コメントは消さない。値がストアと違う鍵は、**値を出さずに名前だけ**を標準エラーに名指しする（`ENV_VALUE_DIFFERS`）。
  書き換えるかは運用者が決める（ストアの鍵を入れ替えた直後かもしれないし、コンテナ用に別の鍵を入れているのかもしれない）
- 扉の合鍵は、既にあれば作り直さない（作り直すと外の呼び出し側の設定が黙って壊れる）

### D4. 値はどこにも表示しない

- 標準出力・標準エラー・`--json` には**名前と件数だけ**（`書き出した鍵: 11 / ストアに無い: 1`）
- 書き込みは一時ファイル + rename。Unix では 0600 で作る。Windows では ACL を組まない（扉の合鍵の
  `mcp_server.json` と同じ判断。守る相手は同じ利用者の他のプログラムではなく、配布とバックアップ）
- `fuseforks.log` には何も書かない（`bake` はもともと村のログに書かない）

### D5. OS ごとの読み

- Windows / Linux（Secret Service）は、同じユーザーならダイアログ無しで読める
- **macOS のキーチェーンは、項目ごとに許可のダイアログが出ることがある**（`fuseforks-cli` は GUI と別の実行ファイルなので）。
  `deploy/README` に書く
- 資格情報ストアを読めない（Secret Service が居ない Linux 等）なら、`.env` を書かずに **5**（元の村が読めないと同じ扱い）

### D6. 外へ送るもの（PRIVACY）

- **外へ送るものは増えない。** 書き出すのは手元のファイルだけ
- PRIVACY 日英の 3 を直す:「どれも保存した値を読み出す経路を持たない」→「**画面へ値を戻す経路は持たない。`fuseforks-cli bake
  --env-out` を明示したときだけ、コンテナ用に平文のファイルへ書き出す**（書き出したファイルの扱いは利用者の責任）」

## 採らなかった形

1. **既定で書き出す** — 気づかないうちに鍵の平文ファイルができる
2. **写しの中（`deploy/village`）に書く** — 写しはボリュームとバックアップへ流れる。`.env` は写しの外
3. **テンプレートを全部書き出す** — 開発機の村で使わない鍵 9 本まで出る
4. **既にある `.env` を上書きする** — 運用者が手で書いた行（ドメイン・コンテナ用の別の鍵）を消す
5. **GUI に「書き出す」ボタン** — 画面から鍵のファイルを作れる経路は、CLI の明示の引数より広い。需要が出たら別に
6. **値の違いを自動で直す（ストアの値で上書き）** — どちらが正しいかはアプリには分からない

## 未決

1. **起動する集合で絞るか** — 既定は「村の個体が使うテンプレート」（開発機で 6）。窓口 1 体で回すならさらに 1 まで減らせる。
   `bake` に `--start` を足して絞る形にするか。推奨は**この Spec では足さない**（`bake` は起動する集合を知らない設計で、
   ここだけ知ると `check` と数える範囲が割れる。絞りたければ書き出した後に手で消せる）
2. **扉の合鍵を常に書くか** — 推奨は**常に書く**（`compose.door.yaml` を重ねるかは後で決まる。使わなければ何も起きない）

## Notes

- 利用者の運用（鍵は OS の資格情報ストアに書きっぱなしで、別に控えていない）では、手で `.env` を書くには鍵を
  どこかから持ってくる必要があり、**GUI には読み出す手段が無い**（OS の資格情報ストアの画面か、各社の管理画面で鍵を
  作り直す）。Spec 65 の P6 では MCP の鍵を `mcp.json` の旧い値から控えてもらった
